# Аудит прав доступа к настройкам

12 ноября 2026 года, Europe/Moscow.

Доступ к странице настроек отделён от права изменять её содержимое. Для ролей добавлены отдельные разрешения на изменение блоков, а для пользователей — индивидуальные разрешения и запреты поверх роли. Отсутствующее право на изменение означает режим просмотра.

Аудит охватывает исходный код панели и изолированные HTTP и браузерные проверки. Фактические назначения ролей и прав на рабочем сервере не проверены: Docker локального стенда недоступен, подключение к рабочему PostgreSQL не выполнялось. Изменения данных рабочего сервера и развёртывание не выполнялись.

## Найденные нарушения и исправления

| Нарушение до изменения | Исправление |
| --- | --- |
| `PAGE_SETTINGS` одновременно разрешал просмотр и большинство изменений настроек | Отдельные права блоков проверяются до записи; право страницы сохраняет только просмотр |
| Создание, изменение и удаление характеристик и профилей оборудования не имели проверки прав страницы | Добавлены проверка страницы и отдельная проверка изменения оборудования |
| Общий API справочников позволял изменять юридические лица, подключения и прочие типы с одинаковыми правами | Право определяется по типу создаваемой записи или сохранённому типу записи при изменении и удалении |
| Разрешение изменять одну группу прав роли позволяло заменить весь JSON разрешений | Изменения страниц, прав редактирования и прав просмотра проверяются независимо; неизменённые группы дополнительных прав не требуют |
| Не было интерфейса индивидуального разрешения или запрета поверх роли | Добавлена таблица «По роли / Индивидуально / Итог» с режимами наследования, разрешения и запрета |
| Доступ к отчётам проверялся по `PAGE_DIALOGS`, а пункт роли «Отчёты» преобразовывался в право аналитики | Отчёты используют собственное право `PAGE_DASHBOARD`; навигация и API согласованы |
| Делегированное управление ролями могло назначить более привилегированную роль или переименовать роль в системную | Запрещены назначения выше собственных полномочий и изменение защищённых системных аккаунтов и ролей |
| Загрузка фото без идентификатора пользователя обходила проверки прав на создание и изменение пользователей | Для такой загрузки требуется право создания пользователя; права страницы недостаточно |
| Просмотр каналов выдавал токены, а чтение списка могло автоматически обновлять информацию о ботах | Секреты скрываются у читателей; автоматическое обновление метаданных доступно редактору каналов |

## Актуальный каталог страниц — уточнение 01-283

Каталог ролей, персональных разрешений и преобразование прав при входе используют единый источник `PanelAccessPolicy.PAGE_CATALOG`.

| Пункт доступа | Маршруты | Право |
| --- | --- | --- |
| Диалоги | `/dialogs`, `/dialogs/{ticketId}` | `PAGE_DIALOGS` |
| AI Ops | `/ai-ops` | `PAGE_AI_OPS` |
| Задачи и проекты | `/tasks`, `/projects` | `PAGE_TASKS` |
| Клиенты | `/clients` | `PAGE_CLIENTS` |
| Паспорт объектов | `/object-passports` | `PAGE_OBJECT_PASSPORTS` |
| База знаний и AI-источники | `/knowledge-base`, `/business-ai-sources` | `PAGE_KNOWLEDGE_BASE` |
| Отчёты | `/dashboard` | `PAGE_DASHBOARD` |
| Аналитика | `/analytics` | `PAGE_ANALYTICS` |
| Настройки | `/settings` | `PAGE_SETTINGS` |

Названия общих прав явно перечисляют связанные страницы. AI-источники дополнительно зависят от флагов модуля. Главная доступна после входа, Инциденты — действующим аккаунтам панели по существующей проверке `SharedSystemAccessService`; фиктивные переключатели для этих страниц не добавлены. Права участников проектов, задач и бизнесов продолжают проверяться отдельно. Существующий административный доступ к задачам и проектам сохранён.

«Каналы» и «Пользователи и роли» убраны из текущего списка: эти блоки доступны в Настройках. Старые `channels` / `user_management` и прямые `PAGE_CHANNELS` / `PAGE_USERS` сохранены для совместимости существующих отдельных маршрутов. Изменение актуальных страниц роли не удаляет её сохранённые старые разрешения. Индивидуальные старые полномочия также автоматически не удаляются.

AI Ops больше не наследует доступ от Диалогов. Общие API мониторинга, памяти решений, очереди проверки и offline evaluation требуют `PAGE_AI_OPS`. Операции AI с конкретным обращением сохраняют проверку точного ID; экспорт событий отдельного диалога доступен оператору Диалогов. Одно право AI Ops не позволяет отвечать в Диалогах. Переход из AI Ops в диалог отключён без `PAGE_DIALOGS`.

После пересборки панели нужно назначить AI Ops нужным обычным ролям или пользователям. Роли с `pages: ["*"]` получают новое право автоматически; bootstrap системного администратора дополнен `PAGE_AI_OPS`. Миграция схемы не требуется. Рабочие назначения прав и развёртывание в этом уточнении не выполнялись.

Проверка уточнения: 368 серверных тестов в 13 целевых наборах по итоговым Surefire-отчётам; отдельно финально перепроверен новый набор границ доступа (21 тест, exit 0). Дополнительно прошли 33 Node-сценария AI Ops и Playwright-проверка ролей и индивидуальных прав на 320/1440 px. Каталог для браузерной проверки получен из настоящего MVC-ответа; рабочие API не использовались.

## Матрица изменения настроек

Открытие страницы требует `PAGE_SETTINGS`. В JSON роли права изменения перечисляются в `permissions.fields.edit`. Например, `settings.dialogs` разрешает изменение категорий, включая критичность P1–P5. Каждое право преобразуется в отдельное полномочие сессии; `settings.dialogs` соответствует `EDIT_SETTINGS_DIALOGS`.

| Блок | Ключ права роли |
| --- | --- |
| Каналы и запуск ботов | `settings.channels` |
| Шаблоны и параметры ботов | `settings.bot_templates` |
| Автозакрытие обращений | `settings.auto_close` |
| Автоотчёты | `settings.reporting` |
| Форматы вводимых данных | `settings.input_formatting` |
| Категории, шаблоны и настройки диалогов | `settings.dialogs` |
| Дизайн панели и статусы клиентов | `settings.appearance` |
| Общие справочники | `settings.parameters` |
| Подключения IT-блока | `settings.it_connections` |
| Оборудование, характеристики и профили | `settings.equipment` |
| Юридические лица и контакты партнёров | `settings.legal_entities` |
| Структура и синхронизация локаций | `settings.locations` |
| Привязка управляющих | `settings.manager_bindings` |
| Организационная структура | `settings.organization` |
| Должности, графики и настройки сотрудников | `settings.workforce` |
| Сетевые профили и интеграции | `settings.network_profiles` |
| Синхронизация NetBox | `settings.netbox` |
| Маршрутизация уведомлений | `settings.notification_routing` |
| Резервное копирование и восстановление | `settings.backup` |
| Индивидуальные разрешения пользователей | `settings.access` |

Для служебной инвентаризации остаётся дополнительная проверка системного администратора. Редактор форматов вводимых данных работает с состоянием браузера; отдельного API общесерверного сохранения этих форматов в исходной реализации нет.

Создание и изменение пользователей и ролей сохраняет отдельные права `user.*` и `role.*`, показанные в каталоге роли. Они также доступны для индивидуальных переопределений. Для этих операций достаточно соответствующего доступа к странице пользователей или настроек вместе с правом на действие.

Собственный профиль, кроме логина, и пароль сохраняют отдельное правило доступа владельца аккаунта. Исторический пункт `user.password` в правах просмотра не открывает просмотр паролей: этот API отключён для всех ролей.

В ответах настроек для читателей скрываются структурированные поля токенов, паролей и ключей API. Для секретов сохраняются признаки наличия сохранённого значения. Право редактирования одного блока не открывает секреты другого блока. Контракт запуска процесса бота доступен редактору каналов.

## Права отдельных пользователей

Для вкладки «Документы и история» паспорта объекта (01-284) добавлено отдельное право `passport.documents` / `EDIT_PASSPORT_DOCUMENTS`. `PAGE_OBJECT_PASSPORTS` разрешает просмотр списка, версий и скачивание файлов. Создание записи, редактирование с заменой файла, архивирование и возврат из архива требуют обоих прав. Право изменения доступно в роли и индивидуальных переопределениях; персональный запрет имеет приоритет. `fields.edit: ["*"]` и системные административные роли включают новое действие, `settings.*` его не включает.

Кнопка «Права» находится в списке пользователей в настройках и на странице пользователей. Таблица показывает права роли, индивидуальное значение и результат. Индивидуальный запрет имеет приоритет над разрешением роли; индивидуальное разрешение добавляет право, отсутствующее у роли. Разрешение изменять блок само по себе не открывает закрытую страницу.

Изменения хранятся в существующей таблице `user_authorities`. Разрешения используют имя полномочия, запреты — префикс `DENY_`. При возврате к наследованию удаляются только переопределения выбранного права; другие полномочия пользователя сохраняются. Новая миграция схемы не требуется.

Пользователь не может изменить собственные индивидуальные разрешения. Защищённые системные администраторы сохраняют права управления; доступ к страницам проверяется по назначенным разрешениям и для административных ролей. Делегированный редактор не может выдавать или изменять права, которых у него самого нет. Сессия перечитывает права перед защищёнными запросами, поэтому изменения действуют со следующего запроса.

Бизнес-членство и доступ к отдельным обращениям и объектам продолжают проверяться своими сервисами. Индивидуальные полномочия панели не заменяют эти проверки.

## Проверки

Пройдено 584 серверных теста в 16 наборах: ошибок, неуспешных и пропущенных тестов нет.

Серверные проверки охватывают разделение просмотра и изменения, независимые блоки, смешанные запросы без частичной записи, общий API справочников, оборудование, персональные права, группы разрешений роли, системные роли, CSRF, доступ к отчётам и обновление полномочий сессии.

Браузерная проверка `tools/settings-permissions-qa.cjs` проверяет режим просмотра, доступный блок при закрытом соседнем блоке, вложенные разделы, динамически добавленные поля и сохранение индивидуальных разрешений и запретов на ширинах 320 и 1440 px. Запросы используют локальные тестовые ответы и не обращаются к рабочему серверу.

## Применение изменения

После пересборки и перезапуска панели нужно назначить обычным ролям необходимые права изменения блоков. Одного доступа к странице настроек для сохранения больше недостаточно. Существующее явное разрешение редактирования `*` охватывает новые блоки; системные административные роли получают права изменения блоков с сохранением назначенного доступа к страницам.

Каталог и правила объединения полномочий находятся в `PanelAccessPolicy`; HTTP-проверки операций — в `SettingsWritePermissionFilter`. Общий запрос сохранения настроек дополнительно проверяет каждый ключ перед вызовом сервиса записи.
