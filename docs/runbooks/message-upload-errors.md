# Загрузка файлов и причины отказов — 01-332

Транспортный лимит размера задаёт принимающая сторона. Указанные ранее пределы
25 МиБ Nginx, 50 МиБ на файл и 60 МиБ на запрос Spring отключены.

- В `docker/nginx/panel-direct.conf` и обоих edge templates:
  `client_max_body_size 0`.
- В `spring-panel/src/main/resources/application.yml`: multipart max-file-size/max-request-size = -1,
  Tomcat max-http-form-post-size/max-swallow-size = -1. Удаление этих параметров
  вернуло бы значения по умолчанию; используются явные значения отключения.
- При отправке файла/подписи Telegram нет локальной проверки его предполагаемого
  предела. Пустой файл, scope, credential и send guards проверяются как прежде.
- API Telegram/VK/MAX и внешний прокси могут отклонить запрос. Общий parser
  сохраняет фактические код/описание и не подставляет выдуманный размер.
  HTML 413 даёт понятное сообщение без числового предела, JSON 413 сохраняет
  предоставленную причину. Невалидный ответ/тайм-аут не подтверждают доставку.
- Ошибки MAX upload init и binary upload теперь возвращаются из ответа API;
  они не заменяются общим «не удалось загрузить». После отказа загрузки сообщение
  клиенту не отправляется; неизвестная попытка не повторяется на другом host.
- Нельзя называть загрузку безграничной: ресурсы хранилища и ограничения API
  сохраняют физические пределы. У приложения нет дополнительных транспортных
  caps из этого списка. Временные файлы перед отправкой записываются на диск.

## Граница изменения

Анкета 10 МиБ, GENERAL document payload и внутренняя переписка 50 МиБ имеют
отдельные storage/DB contracts. Их изменение задано отдельным уточняющим вопросом
и в этот ограниченный scope не включено. Ограничения документов паспортов,
задач, базы знаний и иконок также не определяют лимит отправки клиенту и не
изменялись. Миграции и backfill для этого изменения не требуются.

## Проверка

Проверяется настоящий embedded Tomcat с production application.yml: файл 61 МиБ
и текстовое multipart-поле 3 МиБ проходят полностью, размер и число прочитанных
байтов совпадают. Отдельный настоящий Nginx принимает body 61 МиБ, сохраняет
upstream 413 с его собственной причиной и не навязывает прежний предел 25 МиБ.
Это локальные fixtures, не отправки реальным клиентам.

Конфигурационные значения:
[Nginx client_max_body_size](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_max_body_size),
[Spring MultipartProperties 3.2.5](https://docs.spring.io/spring-boot/docs/3.2.5/api/org/springframework/boot/autoconfigure/web/servlet/MultipartProperties.html),
[Tomcat maxPostSize/maxSwallowSize](https://tomcat.apache.org/tomcat-10.1-doc/config/http.html).
