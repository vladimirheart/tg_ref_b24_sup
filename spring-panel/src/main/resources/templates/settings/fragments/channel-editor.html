Очередь обращений

Определяет, какая команда сопровождает новые обращения именно у этого бота и нужно ли сразу назначать ответственного.

Можно выбрать несколько операторов. Для множественного выбора используйте `Ctrl` / `Cmd`.
Если переключатель выключен, очередь всё равно получит обращение, но ответственный останется неназначенным до ручного действия оператора.

Платформенные настройки

Отдельные настройки только для VK/MAX, чтобы не шумели в общих сценариях.

Используйте для Bot API mirror или self-hosted endpoint. Поле заменяет обращения к `api.telegram.org`, а не настраивает proxy.
Сейчас MAX работает через long polling, поле оставлено только для быстрого возврата к webhook-режиму.
Управление ботом

Операционные действия и текущий статус процесса без смешивания с остальными настройками.

Процесс: —
Бот запускается в отдельном Java-процессе и работает через canonical PostgreSQL/queue/API contract панели; отдельная business SQLite-база для канала не создаётся.
Учётные данные и синхронизация

Просмотр текущего токена, его безопасная замена и обновление карточки бота.

Текущий токен бота
—
Введите новый токен только если действительно хотите заменить текущие учётные данные канала.
Принудительно обновляет имя и username через Telegram API. После смены токена можно сразу синхронизировать карточку бота.
Сетевой маршрут

Индивидуальная прокси/VPN-конфигурация этого бота поверх общей подсистемы.

Профили можно выбирать обычными кликами. Повторный клик снимает выбор.
Профиль можно переиспользовать для нескольких ботов; порядок выбора определяет failover-цепочку.
Цепочка пока не выбрана.
Если выбранный маршрут не доступен, бот перейдёт к следующему и вернётся к этому после истечения интервала.
Если оставить «Наследовать настройки ботов», конкретный бот возьмёт маршрут из блока «Подсистема ботов».
Настройки применяются только к выбранному боту и имеют приоритет над общими параметрами подсистемы.

Как подключить Callback API
  1. В разделе «Работа с API» → «Callback API» задайте адрес вида https://ваш-домен/webhooks/vk/<group_id>.
  2. Вставьте код подтверждения и при необходимости секретный ключ, чтобы проверять исходящие запросы.
  3. Включите события сообщений и запустите Java-бот через панель или команду Spring Boot.
