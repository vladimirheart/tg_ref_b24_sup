# Задача [01-159]

## Краткое описание

Обновить документацию Iguana и подготовить переносимый пакет проекта для запуска на другой машине.

## Цель

Сделать документацию по Iguana подробной и операционно полезной, а также сформировать воспроизводимый переносимый каталог проекта в `C:\Intel`, чтобы систему можно было запустить на другом Windows-хосте с минимальными ручными действиями.

## Контекст

- Пользователь попросил максимально подробно обновить документацию к проекту Iguana.
- Дополнительно требуется скопировать проект в `C:\Intel` для запуска на другой машине вместе с актуальной документацией.
- В репозитории уже есть разрозненные документы по запуску, конфигурации, БД и ботам, но не хватает единой входной точки и отдельного сценария переноса.
- Для масштабирования лучше оставить не только сами документы, но и воспроизводимый способ экспорта переносимого пакета.

## Что сделать

- Обновить `README.md` как главную входную точку документации Iguana.
- Добавить подробный эксплуатационный guide по проекту с описанием архитектуры, каталогов, конфигурации, БД, запуска и эксплуатации.
- Добавить отдельный документ по переносу Iguana на другую Windows-машину.
- Подготовить воспроизводимый экспорт проекта в `C:\Intel`, исключив локальные кэши и служебный шум, но сохранив всё необходимое для запуска.
- Выполнить копирование проекта в целевой каталог и проверить итоговый состав пакета.

## Критерии готовности

- В репозитории есть подробная актуальная документация Iguana с понятной навигацией.
- Есть отдельная инструкция по переносу и запуску на другой Windows-машине.
- В `C:\Intel` создан переносимый каталог проекта с документацией и рабочими артефактами запуска.
- Пользователь в финале получает краткую сводку по документации, по составу пакета и по ограничениям/следующим шагам.

## Обязательные дополнительные условия

- По завершении задачи показать алерт через `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно не отменил это требование.
- В финальном ответе подготовить `Резюме для коммита` по формату из `ai-context/baseline/guides/tasks.md`.
- После любых file changes создать отдельный changelog-файл в `ai-context/changelog` по правилу «одно изменение = один файл» и включить в него пользовательский промпт, который привёл к изменению.
