# Задача 01-304

## Короткое описание

Показать выполнение добавления RMS в форме мониторинга.

## Цель

Сделать состояние создания новой записи RMS очевидным для оператора, пока
серверный запрос выполняется.

## Контекст

Страница `/analytics/rms-control` создаёт RMS через форму `rmsCreateForm` и
`POST /api/monitoring/rms/sites`. В ней отсутствует локальный статус операции,
в отличие от запуска и перезапуска ботов в настройках каналов.

## Что сделать

- Добавить индикатор выполнения и доступный текстовый статус в кнопке создания RMS.
- Блокировать повторную отправку формы до завершения текущего запроса.
- Восстанавливать форму после успешного ответа и после ошибки.
- Добавить регрессионную проверку сценариев ожидания, ошибки и повтора.

## Критерии готовности

- Во время POST оператор видит spinner и текст «Добавляем RMS…».
- Повторная отправка не создаёт второй POST.
- После успеха или ошибки кнопка и ARIA-статус возвращаются в исходное состояние.

## Обязательные дополнительные условия

- По завершении задачи показать алерт через
  `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно
  не отменил это требование.
- В финальном ответе подготовить `Резюме для коммита` по формату из
  `ai-context/baseline/guides/tasks.md`.
- После любых file changes создать отдельный changelog-файл в
  `ai-context/changelog` по правилу «одно изменение = один файл» и включить в
  него пользовательский промт, который привел к изменению.
