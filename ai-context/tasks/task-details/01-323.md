эмодзи, прокрутка к новым сообщениям, персональные непрочитанные и изоляция

b27c873b65e9595dbd0c645f22d32f58ba800ef2 на старте. Во время работы пользователь

Решение: V107 хранит персональный монотонный read marker; bounded batch read
показывает счётчики в списке и disclosure. READ/полный owner проверяются заново;
свои сообщения не считаются непрочитанными. Mark-read требует реально показанный
ID того же обращения, не закрывает более новые сообщения и не меняет клиентский unread.

## Реализовано

- Постоянная поясняющая строка и повтор «Только сотрудникам» у каждого сообщения
  удалены. Status остаётся скрытым при нормальной работе и появляется для ошибки
  или read-only режима. Заголовок блока сохраняет обозначение внутренней переписки.
- authorName читается из users.full_name по numeric author_user_id; при пустом ФИО
  возвращается сохранённый логин. Авторизация и audit snapshot не меняются.
- Внутреннее поле использует тот же installSendModeControl, общую настройку
  dialogs.replySendMode и split-button с самолётиком: Enter/Ctrl+Enter и Shift+Enter
  совпадают с основным диалогом. Отдельные textarea, request ID, draft и endpoint
  не позволяют внутреннему тексту попасть в клиентскую отправку.
- Добавлен выбор эмодзи с вставкой в позицию курсора. Browser storage не нужен
  для генерации UUID: crypto.getRandomValues работает и на HTTP в локальной сети.
- Первая загрузка/своя отправка показывают последнее сообщение. Polling дополняет
  историю; у нижнего края viewport следует за новыми. При чтении старых сообщений
  позиция сохраняется и появляется «Новые сообщения ↓». Prepend старых сохраняет
  scroll offset; текст/ФИО выводятся через textContent.
- Счётчик персональный, исключает свои сообщения, виден в свёрнутом summary и
  в client cell списка с пометкой «Внутр.». Batch ограничен 100 public IDs,
  возвращает только current READ scopes; UI опрашивает видимые IDs раз в 5 секунд.
- Прочтение фиксируется только в открытой видимой переписке у нижнего края;
  marker монотонен, принимает существующий ID того же owner, требует READ,
  не требует OPERATE/приглашения и не помечает более поздние сообщения.
  Отсутствие marker означает непрочитанные прежние сообщения других сотрудников;
  автоматического backfill прочтения не выполнялось.
- CSS блокирует page overflow при открытом диалоге; wheel/touch допускают
  прокрутку внутри видимого окна и блокируют передачу на background у границы,
  включая короткую историю и закрытие вложенной modal.
