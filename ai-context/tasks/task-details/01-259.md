# Задача [01-259] Пересобрать паспорт объекта и каталог оборудования в view-first workspace

## Контекст

Текущий `/object-passports/{id}` открывает тот же большой editor, что и создание паспорта. Из-за этого карточка объекта воспринимается как длинная форма: десятки input/select имеют одинаковый визуальный вес, разделы разнесены крупными card/collapse-блоками, а оборудование дублирует справочник из Настроек.

Справочник оборудования уже существует в `it_equipment_catalog` и синхронизируется из NetBox по уникальной комбинации `type + vendor + model`. Паспорт объекта хранит экземпляры оборудования с SN/IP/status и другими локальными данными. Эти два уровня нужно визуально и логически связать.

## Что сделать

- Разделить режим просмотра и редактирования:
  - `/object-passports/{id}` — новый компактный read-only workspace;
  - `/object-passports/{id}/edit` — существующий полный editor;
  - `/object-passports/new` остаётся editor создания.
- В новом паспорте сделать компактную идентификационную шапку, KPI-полосу и вкладки: Обзор, IT и сеть, Оборудование, Обращения, Задачи, Фото.
- На Overview показывать только заполненные значения плотными property/value строками; вынести контакты, расписание и вычисляемую заполненность в компактную правую колонку.
- Не смешивать обращения/задачи/фото/оборудование с основной формой — показывать их отдельными вкладками.
- Перерисовать оборудование паспорта как asset cards: фото/placeholder, тип, имя/модель, status, IP, SN, catalog ID; расширенные поля только в disclosure.
- Использовать `it_equipment_catalog` как master-каталог моделей:
  - передавать его `id` в passport UI;
  - сначала связывать экземпляр по `catalog_id`, если он есть;
  - для legacy/NetBox записей делать fallback match по `type + vendor + model`;
  - брать из каталога фото/ссылки и базовую комплектацию.
- Перерисовать `Настройки → IT → Каталог оборудования` из inline editable table в searchable card grid; добавление/редактирование оставить в существующей modal.
- Не выполнять schema/data migration в этом пакете.

## Критерии готовности

- Existing passport route возвращает `passports/detail`, отдельный `/edit` сохраняет существующий editor.
- Source-contract фиксирует view-first workspace, asset cards, catalog enrichment и card-grid в settings.
- `git diff --check`, JS syntax check и targeted Maven tests проходят.
- Generated `static/css/app.css` и `static/css/settings.css` напрямую не редактируются.
- Задача остаётся 🟣 до production rollout и ручной визуальной проверки.


## R4 — визуальная приёмка production

- Добавить серверно синхронизируемый `pageFontScales` в существующие пользовательские UI preferences: размер текста хранится индивидуально для пользователя и отдельно по нормализованному route.
- Сделать KPI «Фото» кликабельным и добавить lightbox с предыдущим/следующим фото, счётчиком, Esc и стрелками клавиатуры.
- Перевести `/object-passports/{id}/edit` на тот же workspace в edit-mode; старый editor оставить только на `/legacy-edit` как временный fallback.
- Редактировать основные поля, контакты, даты, сеть, расписание, оборудование и фото из нового workspace частичным PUT без обнуления скрытых данных.
- Исправить обращения: привязка по локации не должна ломаться из-за формата города, один `ticket_id` считается один раз.
- В Settings показывать master-каталог вместе с виртуальными моделями, обнаруженными в существующих паспортах; виртуальная карточка не пишет БД, пока пользователь явно не нажал «Добавить в каталог».
- NetBox catalog sync принимает `type + model` даже при пустом vendor.
- Schema/data migration и массовый backfill не выполнять.

## R4.4 — фото оборудования и историческое снятие с объекта

- В карточке master-каталога тип оборудования размещать по центру всей карточки, а не внутри левой photo-зоны; catalog id показывать в правом нижнем углу.
- Edit/delete icon-actions выстроить вертикально: редактирование сверху, удаление снизу; удаление master-модели всегда подтверждается и backend запрещает его, пока есть хотя бы один активный экземпляр в паспортах объектов; связь проверяется по catalog_id с fallback type + vendor + model.
- Добавить несколько фото на persisted-модель каталога без schema migration: структурированные media-метаданные хранятся совместимо в существующем photo_url CLOB рядом с legacy links.
- Для каждого фото обязательны тип (title / general) и комментарий; в edit-modal показывать фото компактной полосой thumbnail-иконок. Новое title-фото переводит предыдущее title в general.
- Карточка модели использует только собственное загруженное title-фото (fallback — первое general); внешние ссылки больше не считаются фотографией.
- Удаление экземпляра оборудования из паспорта превращать в архивирование по подтверждению: запись остаётся зачёркнутой в истории, может быть восстановлена и не участвует в usage_count/object_count, поэтому не блокирует последующее удаление master-модели.
- NetBox sync, ownership contract, DB schema и массовый backfill не изменять.

## R4.6 — целостность фото и modal stack

- Увеличить превью фото в карточке оборудования до читаемого размера; добавление вынести из основной вкладки в icon-action и отдельную компактную modal.
- Исправить lost-update для media envelope: несколько последовательных/параллельных загрузок должны добавляться, а сохранение основной карточки не должно перетирать уже загруженные фотографии.
- Все mutation фото выполнять под row lock; при сохранении links брать актуальный media envelope из БД, а не ранее загруженный snapshot.
- Гарантировать не более одного title-фото на уровне backend; назначение нового title при существующем разрешать только после явного replace_title confirmation.
- Редактирование фото должно редактировать весь объект: файл, тип и обязательное описание. Замена бинарника сохраняет photo id и удаляет старый binary только после успешного commit.
- При удалении/снятии title с текущего титульного фото сохранять fallback promotion первого оставшегося фото в title.
- Исправить Escape для вложенных settings-modal глобально: при нескольких открытых modal Esc закрывает только верхнюю по stack/z-index и не закрывает родительское окно под ней.
- DB schema, data backfill, NetBox sync и ownership contract не изменять.
