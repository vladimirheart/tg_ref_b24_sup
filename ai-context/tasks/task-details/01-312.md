# Задача 01-312

## Промт пользователя

> так, ну ок. тогда продолжай по SSE и `minimumIdle`  . `minimumIdle` 5 `maximumPoolSize` 20, если это будет ок для работоспособности панели

## Цель и решение

- Задать отдельный бюджет дочерних ботов: минимум 5, максимум 20 соединений,
  освобождение лишних idle после 120 секунд. Panel service pool остаётся 6.
- Явно передавать child-параметры через BotRuntimeContractService и читать их
  в bot-core DataSourceConfig; проверять границы до подключения.
- Для трёх работающих child JVM: минимум 15 и максимум 60 соединений, вместо
  прежних 30 постоянно открытых. Server max_connections=550.
- Для двух SSE endpoints отключить Nginx buffering/cache и установить read
  timeout 180 секунд; обычные HTTP endpoints сохраняют 60 секунд.
- Основной SSE controller возвращает no-store и X-Accel-Buffering=no.
- Heartbeat UI и GENERAL выполняются независимо на отдельном scheduler из двух
  потоков с прежним интервалом 25 секунд. Проверки сессии/доступа сохранены.
- Обнаружен SQL role CONNECTION LIMIT 16 у трёх managed child identities.
  V103 согласует его с maximumPoolSize=20: меняет только исходную квоту
  активных journal-bound ролей с совпадающим OID и без повышенных прав.
  Роли с изменённой identity, manual principals и custom quotas не затрагиваются.
  Существующая provisioning function сохраняется целиком с заменой единственного
  CONNECTION LIMIT 16 на 20; прежние миграции/checksums не переписываются.
- После первого rollout выявлен конфликт default PUBLIC grants pg_stat_statements
  с child startup isolation check 6. Infrastructure SQL дополнен REVOKE только на
  diagnostic views/functions, выполнен на рабочей БД без её restart. Сам guard
  сохранён. Supervisor повторно запущен после проверки отсутствия diagnostic
  доступа у всех трёх child roles; владелец продолжает читать статистику.
