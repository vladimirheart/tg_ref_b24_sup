# Задача [01-276]

## Краткое описание

Устранить дублирующиеся bell-уведомления вокруг создания, новых сообщений и автоматического закрытия обращений; показывать пользователю канонический номер обращения вместо технического `ticketId`/UUID; сохранить follow-up задачи auto-close без отдельного лишнего bell и добавить ленивую cursor-пагинацию уведомлений по 20 элементов.

## Scope

### S1 — Notification semantics

- initial inbound, создающий обращение, формирует одно bell `Новое обращение №<номер>`;
- последующие сообщения формируют одно bell `Новое сообщение в обращении №<номер>`;
- inactivity auto-close формирует одно bell `Обращение №<номер> автоматически закрыто из-за отсутствия активности.`;
- auto-close follow-up task продолжает создаваться, но не порождает отдельный bell `Новая задача ...` для этого сценария;
- внутренние URL сохраняют технический `ticketId`, но UUID не показывается пользователю.

### S2 — Notification pagination

- backend отдаёт максимум 20 уведомлений на страницу;
- используется стабильный keyset cursor `(createdAt,id)` в descending order;
- frontend подгружает следующую страницу при прокрутке вниз и de-dup'ит записи по notification id;
- SSE/poll refresh обновляет head page и не ломает уже загруженную историю;
- unread badge остаётся полным count, не count текущей страницы;
- read-on-visible остаётся 2 секунды при threshold `0.6`;
- `read-all` применяется ко всему набору уведомлений;
- DB migration для pagination не требуется.

### S3 — Display-number hotfix

- historical bell-записи с `/dialogs/<ticketId>` нормализуются на read в `№ обращения`;
- historical task bell `Новая задача «...#<ticketId>...»` также нормализуется на read;
- auto-close task title/body, task list/detail/Kanban показывают номер обращения, а не UUID;
- ручное создание задачи из диалога передаёт `requestNumber` в task context вместо использования `ticketId` как пользовательского номера;
- канонический display-number ограничен форматом `YYYYMMDD-NNN...`; raw UUID/group id не принимается за номер обращения;
- trailing punctuation в historical task body отделяется от технического id перед lookup и сохраняется после нормализации.
