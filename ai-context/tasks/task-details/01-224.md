# Задача [01-224] Реализовать coordinated Redis/MinIO persisted credential migration и restart choreography

## Краткое описание

После `01-223` в apply-контуре оставались `redis` и `minio`, где простой rewrite
`.env` недостаточен: нужен coordinated switch, проверка живого runtime и безопасный
recreate зависимых сервисов.

## Почему это важно

- `redis` используется панелью, ботами и observability/exporter-контуром;
- `minio` хранит объектные данные, и ротация его root-учётки не должна ломать доступ к
  уже существующему bucket/object set;
- для обоих компонентов опасно обновлять конфиг вслепую без verify/rollback path.

## Что сделано

1. `scripts/docker-production-credential-migration-apply.ps1` расширен на:
   - `redis`;
   - `minio`.
2. Для `redis` реализованы:
   - live auth preflight через `redis-cli --no-auth-warning`;
   - controlled `CONFIG SET requirepass`;
   - запись `IGUANA_REDIS_PASSWORD` и при необходимости `SPRING_DATA_REDIS_PASSWORD`;
   - coordinated recreate `redis`, `redis-exporter`, `ops-worker`, `panel-web` и живых bot-сервисов;
   - post-change auth verification;
   - best-effort rollback.
3. Для `minio` реализованы:
   - чтение live `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` из runtime env;
   - bucket access verification через ephemeral `minio/mc` внутри compose network;
   - controlled update `APP_STORAGE_OBJECT_ACCESS_KEY` / `APP_STORAGE_OBJECT_SECRET_KEY`;
   - recreate `minio`, `minio-init`, `ops-worker`, `panel-web` и живых bot-сервисов;
   - ожидание `minio-init` как `service_completed_successfully`;
   - post-change runtime/bucket verification;
   - best-effort rollback через restore `.env` и повторный recreate.
4. Apply workflow теперь автоматически добавляет
   `docker-compose.production-observability.yml`, если observability overlay уже поднят,
   чтобы при recreate не потерять overlay-настройки.
5. Обновлён runbook `docs/runbooks/persisted-credential-rotation-apply.md`.
6. Обновлён source-contract
   `spring-panel/src/test/java/com/example/panel/runtime/PersistedCredentialRotationApplySourceContractTest.java`.

## Проверка

На поднятом compose project `tg_ref_b24_sup` dry-run выполнен успешно:

- `powershell -ExecutionPolicy Bypass -File .\scripts\docker-production-credential-migration-apply.ps1 -Component redis`
  показал готовый plan для `redis`, `redis-exporter`, `ops-worker`, `panel-web`;
- `powershell -ExecutionPolicy Bypass -File .\scripts\docker-production-credential-migration-apply.ps1 -Component minio`
  показал готовый plan для `minio`, `minio-init`, `ops-worker`, `panel-web`;
- оба dry-run подтвердили live auth/runtime verification без реальных изменений.
