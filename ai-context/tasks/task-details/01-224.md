# Задача [01-224] Реализовать coordinated Redis/MinIO persisted credential migration и restart choreography

## Краткое описание

После Windows-first apply slice для `postgresql` и `rabbitmq` остаётся более
сложный persisted credential contour: `redis` и `minio`. Для них недостаточно
сменить пароль и обновить `.env`; нужно координировать клиентов и restart order.

## Почему это важно

- `redis` используется панелью, ботами и observability/exporter-контуром;
- `minio` держит объектные данные и должен оставаться согласованным с runtime
  credential contract без потери доступа к bucket/object set;
- blind restart или простой env rewrite здесь рискованнее, чем у PostgreSQL и
  RabbitMQ.

## Что нужно сделать

1. Реализовать controlled apply-path для `redis`:
   - live auth preflight;
   - coordinated password switch;
   - update `.env`;
   - recreate зависимых клиентов;
   - post-change verification.
2. Реализовать controlled apply-path для `minio`:
   - live runtime/auth reconciliation;
   - update `.env`;
   - recreate зависимых сервисов;
   - object-access verification без потери доступа к данным.
3. Добавить runbook и smoke для partial-failure/rollback сценариев.

## Критерии готовности

- `redis` и `minio` имеют repeatable apply path.
- После apply нет drift между runtime и `.env`.
- Есть rollback guidance и post-change verification.
