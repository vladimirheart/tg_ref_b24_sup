# Задача [01-246] Запретить локальный monolith launcher рядом с Docker production ролями

## Цель

Исключить повторный запуск Spring Panel в роли `all` через Windows launcher рядом с разделённым Docker production-контуром.

## Контекст

- `spring-panel/run-windows.bat` запускает `spring-boot:run`; без явной роли приложение работает как monolith `all`.
- При занятом `8080` launcher выбирал свободный `8081`, поэтому старый локальный процесс мог одновременно читать общие PostgreSQL/RabbitMQ контуры и запускать bot polling.
- Это приводило к дублированию AI/system side effects и Telegram `409 Conflict`.

## Что сделано

- Launcher проверяет running Docker services `panel-web`, `ops-worker` и `bot-runner` в production compose.
- При обнаружении любой роли старт блокируется до запуска Maven и до изменения local bootstrap secrets.
- Для намеренной изолированной диагностики добавлен явный override `IGUANA_ALLOW_LOCAL_PANEL_RUN=true`.
- Добавлен source-contract тест на production guard.

## Критерии готовности

- При работающем Docker production-контуре local launcher не выбирает альтернативный порт и не создаёт второй worker.
- Локальный dev-start без production Docker ролей сохраняет прежнее поведение.

## Результат

- Guard проверен при работающем `panel-web`: launcher завершился до preflight, Maven и backup runner с понятной причиной блокировки.
- Source-contract тест проходит.
- Production runbook явно называет Docker edge единственным production entrypoint.
