# Задача [01-177]

## Краткое описание

Устойчиво привязать сохранение настроек NetBox к фактическим значениям полей в UI и добавить понятное серверное логирование для операций save/run.

## Цель

Исключить сценарии, когда пользователь видит введённые URL/token в форме, но backend сохраняет старое или пустое состояние из-за рассинхронизации JS-state, а в логах при этом нет полезной диагностики.

## Контекст

- Пользователь сообщает, что введённые данные подключения к NetBox всё ещё не сохраняются.
- На диске `config/shared/settings.json` значения `base_url` и `api_token` есть, но до сих пор не хватает прозрачности, что именно пришло в backend и что именно было после этого сохранено.
- Текущий runtime NetBox сериализует данные из in-memory state, который может отставать от видимых значений полей.

## Что сделать

- Перед save/run NetBox собирать payload из реальных DOM-полей с синхронизацией state.
- Добавить логирование `SettingsNetBoxSyncController` для save/run и результата persist без вывода token в открытом виде.
- Возвращать из save/run сохранённый backend-state NetBox и применять его в runtime напрямую.

## Критерии готовности

- Save/run используют текущее видимое состояние полей NetBox, даже если JS-state не успел обновиться.
- В логах панели есть запись о входящем и сохранённом состоянии NetBox save/run без утечки token.
- UI после save/run показывает фактически сохранённое backend-состояние блока.
