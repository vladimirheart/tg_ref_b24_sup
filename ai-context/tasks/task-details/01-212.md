# Задача [01-212]

## Короткое описание

Реализовать реальные production backup jobs PostgreSQL и MinIO с off-host хранением и автоматизированным restore rehearsal.

## Цель

Закрыть разрыв между мониторингом backup readiness (`01-198`) и фактическим disaster-recovery механизмом: Iguana должна регулярно создавать recoverable backup артефакты, выносить их за пределы основного host/storage failure domain и периодически доказывать восстановимость автоматизированным restore-test.

## Контекст

- `01-198` уже реализует monitoring freshness backup и restore evidence, но monitoring не создаёт backup.
- Production data plane использует PostgreSQL и MinIO/S3; локальные bind/named volumes не являются off-host disaster recovery.
- `01-211` разделила backend runtime roles и закрепила explicit operational ownership.
- Backup execution не должен выполняться внутри `panel-web`.
- Backup encryption/credentials должны идти через отдельный secret boundary и не попадать в Git.

## Что сделать

### PostgreSQL

- Добавить отдельный one-shot/scheduled `postgres-backup` container/job.
- Использовать `pg_dump`/custom format или обоснованный эквивалент.
- Делать atomic artifact publication: временный файл -> validation -> final name.
- Добавить checksum и metadata manifest.
- Добавить retention policy.
- Не хранить единственную копию на том же Docker host/volume.

### MinIO/S3

- Реализовать backup/replication объектов в отдельный bucket/endpoint/failure domain.
- Сохранять bucket/object metadata, необходимую для восстановления.
- Не считать обычный primary MinIO volume backup-копией самого себя.

### Off-host destination

Поддержать минимум один production target из:

- отдельный S3-compatible endpoint;
- NAS/SMB/NFS mount, предоставленный host-ом;
- отдельный backup host.

Credentials не должны храниться в repository files.

### Restore rehearsal

- Автоматизировать periodic restore в isolated temporary PostgreSQL/MinIO target.
- Выполнять минимум structural checks и выборочные domain integrity checks.
- После успешного drill обновлять evidence, которое уже читает `01-198`.
- Failed restore должен давать non-zero result и alert-ready evidence.

### Operations

- Добавить PowerShell/Bash helpers из корня репозитория.
- Добавить runbook RPO/RTO, retention, restore и rotation backup credentials.
- Добавить Docker smoke без destructive действий над production data.

## Критерии готовности

- PostgreSQL backup реально создаётся и валидируется.
- MinIO/object backup реально создаётся/реплицируется.
- Есть off-host copy, находящаяся в другом failure domain.
- Есть retention и checksum/manifest.
- Есть автоматизированный isolated restore rehearsal.
- `01-198` получает фактические backup/restore evidence вместо ручного placeholder flow.
- Backup job не выполняется в `panel-web`.
- Ни один backup secret не попадает в Git.
- Есть проверяемый runbook и real Docker smoke.
- После AI implementation статус только `🟣`; `🟢` — после ручной проверки пользователя.
