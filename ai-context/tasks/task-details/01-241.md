# Задача [01-241] Передать ручной lifecycle bot runtime из web API в подтверждаемые команды dynamic bot-runner

## Цель

Панель должна отображать фактический статус каждого динамического бота и безопасно запускать или останавливать его только через владельца процесса `bot-runner`.

## Текущий контекст

- Статус дочерних JVM был локальным для `bot-runner`, из-за чего `panel-web` показывал неактивных ботов.
- Состояние runtime теперь сохраняется в общем production-config volume.
- При рестарте runner сохранённый статус мог быть устаревшим и блокировать автозапуск.

## Что сделать

- Сбрасывать устаревший статус активных каналов перед их автозапуском в новом runner.
- Не блокировать readiness `bot-runner` ожиданием старта дочерних JVM и учитывать фактическое время холодного запуска bot jars.
- Проверить после rollout, что все активные каналы создают дочерние процессы и отображаются как active в UI.
- Продолжить передачу ручных команд в runner с подтверждением фактического результата.

## Критерии готовности

- После рестарта `bot-runner` все активные каналы запускаются без ручного `docker start`.
- В sidebar и мониторинге статус совпадает с фактическим дочерним процессом.
- Запуск одного канала не создаёт второй runtime owner.


## Progress: command routing slice 2026-09-19

- `panel-web` больше не должен завершать ручной lifecycle запросом `409`: web API маршрутизирует `start/stop` в единственного `bot-runner`.
- Для межролевой команды используется уже существующий internal API security contract: token + optional/production-required HMAC signature + idempotency key.
- `bot-runner` возвращает acknowledgement с `commandId`, `channelId`, `action`, фактическим runtime status и `runnerInstanceId`; web принимает ответ только если identity команды совпадает.
- Internal endpoint отказывается исполнять lifecycle в `panel-web`, `ops-worker` и migrator ролях.
- Текущий slice не выполняет production rollout и не переводит задачу в `🟣`/`🟢`; после source review нужны targeted tests, deployment и ручная проверка start/stop/status в UI.
