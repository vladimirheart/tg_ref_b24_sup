# Задача [01-154]

## Короткое описание

Довести страницу `AI Ops` до фактического control-center сценария и вывести в UI уже существующие backend-возможности review queue и offline eval.

## Цель

Сделать `AI Ops` не декоративной страницей мониторинга, а рабочим операторским центром для AI-контура: с обзором метрик, очередью ручной ревизии AI-памяти и запуском/диагностикой offline evaluation без перехода в код или прямых API-вызовов.

## Контекст

- В проекте уже есть отдельная страница `dialogs/ai-ops` и page-level runtime `spring-panel/src/main/resources/static/js/ai-ops.js`.
- Backend уже поддерживает через `DialogAiOpsController` и `DialogAiOpsService`:
  - очередь ревизий `GET /api/dialogs/ai-reviews`;
  - approve/reject по query key;
  - offline eval summary `GET /api/dialogs/ai-monitoring/offline-eval`;
  - ручной запуск offline eval `POST /api/dialogs/ai-monitoring/offline-eval/run`.
- Внутри `dialogs-ai-runtime.js` уже есть готовая логика для review queue и monitoring, но отдельная страница `AI Ops` использует сильно урезанный standalone-скрипт и поэтому не раскрывает значимую часть AI Ops контура.
- Конфиг `config/shared/settings.json` показывает, что AI agent включён (`ai_agent_enabled=true`, `ai_agent_mode=auto_reply`), поэтому проблема не в глобальном disable, а в неполной/неудобной UI-реализации.

## Что сделать

- Расширить страницу `spring-panel/src/main/resources/templates/dialogs/ai-ops.html` новыми рабочими секциями:
  - review queue для pending AI review;
  - offline eval summary с dataset/run meta и ручным запуском.
- Расширить `spring-panel/src/main/resources/static/js/ai-ops.js`:
  - загрузкой очереди ревизий;
  - approve/reject действий;
  - переходом в связанный диалог из review queue;
  - загрузкой offline eval summary;
  - запуском offline eval с обновлением состояния после completion.
- Сохранить существующий monitoring/memory контур и не ломать вкладку `Bitrix24 + iiko automation`.
- Проверить, что страница продолжает рендериться и что JS синтаксически корректен.

## Критерии готовности

- На странице `AI Ops` видна очередь pending review без ручного вызова API.
- Из `AI Ops` можно принять или отклонить review item и открыть связанный диалог.
- На странице виден статус offline eval: dataset/version, последний прогон и базовые KPI.
- Из `AI Ops` можно вручную запустить offline eval, а UI показывает обновлённый результат.
- Существующие monitoring и solution memory блоки не деградируют.

## Ограничения и риски

- Не смешивать page-level `AI Ops` с runtime диалогов так, чтобы сломать `dialogs/index`.
- Не переписывать backend-контракт, если его можно переиспользовать в уже существующем виде.
- Не трогать unrelated runtime-файлы и текущие пользовательские изменения в БД/логах.
