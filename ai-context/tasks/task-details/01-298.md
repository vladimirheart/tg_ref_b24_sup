# Задача 01-298

## Короткое описание

Исправить открытие и номера обращений в паспорте объекта и обрезание статусов оборудования.

## Цель

Во вкладке «Обращения» показывать принятый в списке диалогов номер и открывать
связанный диалог. Длинные названия и статусы оборудования остаются внутри карточек.

## Контекст и ограничения

- Baseline HEAD/origin/main: `f8647bcb2e9742da99d87104c8e582dd40f7ddfe`;
  parent `86b9b4e25f9268e881ab96457175422202a97e08`.
- Применимы `rules/00-agent-operating-protocol.md`,
  `rules/01-guarded-change-operator.md`,
  `rules/03-multibusiness-s0-contract.md`,
  `rules/backend/05-iguana-production-storage-boundaries.md`.
- Изменения готовятся в detached sandbox `.tmp/passport-cases-20261120`.
- Навигация использует точную связь сообщения с ticket по user/id/channel.
  Названия бизнеса и локации служат прежним фильтром списка, не назначают владельца.
- Обычный диалог открывается через `/dialogs?ticketId=…&channelId=…`;
  GENERAL — через существующий `/general-dialog-work/{publicId}`.
- Старые записи без корня и неоднозначные legacy ID не получают выдуманные номера
  или ссылки; последние не поддерживаются общей карточкой диалогов. Права чтения
  целевых страниц не меняются.
- Человеческий номер считается до фильтра локации по первому сообщению, дате и
  дневной последовательности уникальных non-GENERAL обращений, как в общем списке.
- Рабочая БД и Docker другой машины не затрагиваются; migrations/backfill нет.

## Что сделать

- Расширить projection обращений номером, каналом и безопасной ссылкой.
- Сохранить последнюю карточку для каждой составной идентичности обращения.
- Сделать карточку обращения обычной ссылкой, поддержать клавиатуру и экранирование.
- Разрешить перенос названия и статуса оборудования; обновить CSS и cache version.
- Проверить PostgreSQL, MVC и браузер на мобильной/настольной ширине.

## Критерии готовности

- Пользователь видит номер вместо UUID и может открыть связанный диалог.
- Позднее сообщение и фильтр локации не перенумеровывают обращение.
- Совпадение ID разных каналов/пользователей не склеивает карточки и не даёт
  ссылки на чужой диалог.
- Длинные статусы, включая текст без пробелов, полностью видны при ширине 320–1440 px.
- GREEN-проверки и точные content/file guards предшествуют source apply.
