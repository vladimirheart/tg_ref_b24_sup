## Краткое описание

Перевести исторические вложения и аватары из legacy local filesystem в production object storage и завершить переход так, чтобы локальные каталоги больше не являлись runtime dependency. Физический cleanup выполняется отдельно, только через доказанный manifest-driven quarantine и с сохранённым rollback window.

## Цель

- canonical runtime storage — MinIO/S3;
- attachment metadata соответствует реальной доступности canonical objects;
- local fallback после успешного cutover выключен;
- известные невосстановимые исторические вложения явно зафиксированы и не маскируются placeholder-объектами;
- оставшиеся локальные файлы инвентаризируются и сопоставляются без destructive операций;
- quarantine и физическое удаление отделены друг от друга и требуют отдельных решений оператора.

During the subsequent `-Apply -WhatIf` run both storage gates passed GREEN, but Windows PowerShell 5.1 leaked the script-level `$WhatIfPreference` into `Get-FileHash` provider handling. On the first source SHA check PowerShell emitted a provider `WhatIf` operation and `Get-FileHash` did not return a normal object with `.Hash`, causing `PropertyNotFoundStrict`.

The failure occurred in source-plan verification before the plan was completed and before the `ShouldProcess` / `Move-Item` loop. Therefore the failed rehearsal did not reach any move operation. Physical deletion remains impossible in this helper and `physical_delete_authorized` stayed false.

## Current implementation step

Patch `scripts/docker-production-storage-quarantine.ps1` for Windows PowerShell 5.1 `-Apply -WhatIf` semantics:

- introduce a dedicated read-only SHA helper that temporarily sets `$WhatIfPreference=false` only while executing `Get-FileHash` and restores it in `finally`;
- retain the original invocation `$WhatIfPreference` for the later `ShouldProcess` move loop, so `-WhatIf` still prevents every move;
- stream storage cutover/client-avatar gate output instead of buffering it;
- add explicit runtime-health and manifest-source-verification stage markers;
- preserve all existing manifest integrity, clean-tree, rollback backup, runtime health, exact path/size/SHA, same-volume, authorization and no-delete gates.

Any new repository commit makes the `20260828-184146` manifests stale because manifest/inventory evidence is commit-bound. They must not be reused after pulling the hotfix.
