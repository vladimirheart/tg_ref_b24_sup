# Задача [01-205]

## Короткое описание

Расширить credential rotation registry на network proxy / route secrets и auto-import expiry metadata из внешних secret backends.

## Цель

Сделать credential rotation registry полнее и ближе к production reality:

- охватить секреты сетевых маршрутов, через которые реально ходят panel/bot integrations;
- убрать ручной metadata-only blind spot для тех секретов, по которым source of truth уже живёт во внешнем secret backend;
- сохранить текущий принцип: registry знает наличие секрета и его lifecycle metadata, но не хранит raw secret values.

## Контекст

- В `01-202` registry уже покрывает bot/provider/runtime secrets, но пока не видит proxy/token/password из `integration_network`, `integration_network_profiles` и channel-level `network_route`.
- В проекте уже есть зрелый network route contract:
  - `settings.integration_network.project`;
  - `settings.integration_network.bots`;
  - `settings.integration_network_profiles`;
  - `channels.deliverySettings.network_route`.
- Реальные route secrets находятся прежде всего в `proxy.password` и `proxy.token` (`http/https/socks/vless` scenarios).
- В `01-202` metadata rotation/expiry пока полностью manual. Для production contour это недостаточно, если secret lifecycle already tracked outside Iguana.
- В docker/docs уже зафиксировано, что внешний secret manager является отдельным infra layer, поэтому для этой задачи уместен узкий import contract по metadata, а не хранение/чтение самих секретов через registry.

## Что сделать

- Расширить discovery в `CredentialRotationRegistryService` на network-route secrets:
  - project-level proxy credentials;
  - bots-level proxy credentials;
  - profile-level proxy credentials;
  - channel-level `network_route.proxy` credentials.
- Отслеживать как минимум:
  - `proxy.password`;
  - `proxy.token`;
  - при необходимости legacy/mirror route cases, если в route есть proxy secret fields.
- Добавить optional import contract для внешних metadata backends:
  - backend definitions в shared settings;
  - link-мэппинг `entry_key -> backend_id + secret_ref`;
  - импорт только metadata (`expires_at`, `rotated_at`, `rotation_interval_days`, `owner`, `note`) без чтения secret value.
- Реализовать безопасный precedence rule:
  - imported metadata может auto-fill gaps;
  - при явном флаге link может override-ить manual metadata.
- Покрыть это тестами на:
  - discovery network secrets;
  - import metadata application;
  - корректную деградацию при отсутствии backend data / ошибке fetch.

## Ограничения и допущения

- В рамках `01-205` не нужен vendor-specific universal secret manager SDK; достаточно узкого generic contract для внешнего metadata endpoint.
- Registry не должен хранить raw secret value даже временно.
- Ошибка metadata import не должна ломать весь refresh registry: запись должна остаться в registry и деградировать к manual/empty metadata поведению.
- Если external link не настроен, прежний manual metadata path должен работать без изменений.

## Критерии готовности

- Credential rotation registry видит project/bot/profile/channel network proxy secrets.
- Для linked entries registry умеет автоматически подтянуть expiry/rotation metadata из внешнего backend metadata endpoint.
- Импорт не раскрывает secret values и не ломает refresh при частичном отказе backend.
- Изменения покрыты целевыми тестами.
