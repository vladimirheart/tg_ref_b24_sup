# Задача [01-197]

## Короткое описание

Расширить мониторинг классических support-систем и внешних зависимостей.

## Цель

Довести Iguana до роли реального support control center, где помимо внутренних workflow видны состояние классических support-систем, внешних сервисов, delivery-каналов и ключевых корпоративных зависимостей.

## Контекст

- В проекте уже есть monitoring-сценарии по SSL, RMS, iiko и части transport/runtime.
- Для полноценной службы поддержки не хватает мониторинга инфраструктурных и смежных систем: почта, VPN, backup freshness, DNS, токены внешних SaaS, очереди доставки и сервисные деградации.

## Что сделать

- Сформировать целевую карту monitoring coverage для support-систем.
- Добавить backlog по недостающим источникам сигналов и каналам оповещения.
- Зафиксировать приоритеты внедрения по критичности для службы поддержки.

## Критерии готовности

- В репозитории есть согласованный roadmap расширения monitoring coverage.
- Понятно, какие системы обязательны для первой волны и какие метрики/алерты ожидаются по каждой группе.

## Обязательные дополнительные условия

- По завершении задачи показать alert через `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно не отменил это требование.
- В финальном ответе подготовить `Резюме для коммита` по формату из `ai-context/baseline/guides/tasks.md`.
- После любых file changes создать отдельный changelog-файл в `ai-context/changelog` и включить в него пользовательский промпт, который привел к изменению.
