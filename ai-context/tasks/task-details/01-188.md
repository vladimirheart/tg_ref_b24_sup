# Задача [01-188]

## Короткое описание

По результатам live-smoke после v47 восстановить PostgreSQL-first runtime для media, edit events, feedback/rating и системных сообщений, а также убрать повторную отправку reply и мелкие questionnaire/list regressions.

## Дефекты smoke 2026-08-24

- inbound/outbound media падают в `ChatAttachmentMetadataService` из-за VARCHAR вместо TIMESTAMPTZ;
- client edit доходит до panel, но `ui_event_outbox.created_at` получает VARCHAR;
- pending feedback request не создаётся из-за VARCHAR в `expires_at`;
- resolve/system notification падает на `chat_history.timestamp`;
- быстрые повторные действия Send порождают несколько параллельных одинаковых reply;
- media на choice-question молча игнорируется вместо подсказки выбрать допустимый вариант;
- в shared settings сохранён текст `Тип бизнесаx`;
- AJAX row refresh теряет `dialog-status-line`, поэтому unread badge визуально уезжает к колонке канала.

## Реализация v48

- temporal JDBC parameters передаются как `OffsetDateTime`, а строковое представление остаётся только на API boundary;
- media metadata, feedback expiry, UI event outbox и system history приведены к PostgreSQL TIMESTAMPTZ contract;
- details reply получает общий DOM in-flight guard для click/hotkey/media path;
- media/unsupported payload во время choice-question не принимается как ответ и возвращает читаемую подсказку со списком вариантов;
- исправлен `Тип бизнесаx`;
- AJAX renderer использует тот же `dialog-status-line`, что серверный шаблон;
- добавлены regression tests для temporal binding и choice-question message contract.

## Ручная проверка

1. Создать fresh Telegram dialog и отправить photo/document/voice/sticker: media должны появляться в panel без rollback.
2. Из panel отправить media клиенту: HTTP success, одно сообщение в history, файл доступен клиенту.
3. Отредактировать client message: panel должен получить edit event без HTTP 500; полная version history остаётся задачей 01-189.
4. Быстро нажать Send несколько раз: клиент получает один reply.
5. Закрыть dialog: клиент получает close + rating prompt, rating 1..5 сохраняется и отображается.
6. На choice-question отправить media: бот читабельно просит выбрать один из вариантов.
7. Проверить текст `Тип бизнеса` без `x`.
8. Дождаться AJAX refresh списка: unread остаётся внутри status cell.

Статус: 🟣 код подготовлен; требуется fresh runtime smoke.
