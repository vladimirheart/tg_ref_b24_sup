# Задача [01-218] Выполнить финальный cutover legacy media: пересобрать runtime с metadata backfill, отключить local fallback и подготовить purge legacy storage

## Краткое описание

Довести перенос legacy media до состояния, когда production contour больше не зависит от локального `attachments/**` даже как от fallback-источника: новый runtime должен сам досоздать недостающие `chat_attachment_metadata`, подтянуть исторические ссылки из `chat_history`, а затем позволить безопасно выключить `app.storage.object.legacy-local-fallback-enabled`.

## Почему это важно

- На 27 августа 2026 года backfill в MinIO уже выполнен, но в PostgreSQL ещё остаются строки `chat_history`, для которых `chat_attachment_metadata` не создана автоматически.
- В коде уже добавлен безопасный переключатель `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED`, но по умолчанию он оставлен включённым, чтобы не ломать рабочий контур до новой выкладки.
- Без финального cutover мы всё ещё зависим от локального legacy storage для части исторических диалогов и аватаров.

## Что нужно сделать

1. Пересобрать и перевыкатить `iguana-panel:local` с последними изменениями `ChatAttachmentMetadataAvailabilityService`, `AttachmentService` и `AttachmentObjectStorageService`.
2. После старта обновлённого runtime проверить, что missing metadata rows из `chat_history` были созданы автоматически и перешли в корректные `availability_status`.
3. Повторно прогнать `scripts/docker-production-storage-backfill.ps1`, при необходимости уже с `-RestartRuntime`, и замерить остаточный хвост.
4. После ручной валидации UI, карточек диалогов, медиа и аватаров перевести `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED=false` в production contour.
5. Подготовить отдельный purge-runbook для удаления локального legacy storage только после подтверждения, что rollback больше не нужен.

## Критерии готовности

- `chat_history` больше не содержит значимого хвоста строк без `chat_attachment_metadata`.
- Исторические вложения открываются через текущие URL панели без чтения из local fallback.
- Аватары клиентов и панели доступны после отключения legacy fallback.
- `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED=false` не ломает `/login`, диалоги и media preview.
- Есть отдельный ручной план purge legacy files и rollback для этого шага.
