# Задача [01-218] Выполнить финальный cutover legacy media: пересобрать runtime с metadata backfill, отключить local fallback и подготовить purge legacy storage

## Краткое описание

Довести перенос legacy media до состояния, когда production contour больше не зависит от локального `attachments/**` даже как от fallback-источника: новый runtime должен сам досоздать недостающие `chat_attachment_metadata`, подтянуть исторические ссылки из `chat_history`, а затем позволить безопасно выключить `app.storage.object.legacy-local-fallback-enabled`.

## Почему это важно

- На 27 августа 2026 года backfill в MinIO уже выполнен, но в PostgreSQL ещё оставались строки `chat_history`, для которых `chat_attachment_metadata` не был создан автоматически.
- В коде уже добавлен безопасный переключатель `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED`, но по умолчанию он оставлен включённым, чтобы не ломать рабочий контур до финальной проверки.
- Без финального cutover production contour продолжает сохранять потенциальную зависимость от local legacy storage для исторических медиа и аватаров.

## Что нужно сделать

1. Пересобрать и перевыкатить `iguana-panel:local` с последними изменениями `ChatAttachmentMetadataAvailabilityService`, `AttachmentService` и `AttachmentObjectStorageService`.
2. После старта обновлённого runtime проверить, что missing metadata rows из `chat_history` были созданы автоматически и перешли в корректные `availability_status`.
3. Повторно прогнать `scripts/docker-production-storage-backfill.ps1` и замерить остаточный хвост.
4. Запустить read-only cutover gates:
   - `scripts/docker-production-storage-cutover-gate.ps1` — authoritative gate для attachment metadata и panel/operator avatars; он независимо проверяет attachment keys через HEX UTF-8 и canonical MinIO `mc stat`, а reviewed historical loss сверяет с `ai-context/storage-known-unrecoverable-dialog-attachments.json`;
   - `scripts/docker-production-client-avatar-cutover-audit.ps1` — client avatar runtime keys `<userId>.jpg` / `<userId>_full.jpg` для клиентов с avatar history.
   - `scripts/docker-production-storage-cutover-audit.ps1` остаётся raw diagnostic audit и может честно показывать физически отсутствующие known-unrecoverable historical attachments.
5. После ручной валидации UI, карточек диалогов, доступных исторических медиа и аватаров перевести `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED=false` в production contour с recreate runtime containers, а не простым `restart`.
6. Повторить cutover gate, client-avatar audit и UI/media checks уже с отключённым fallback.
7. Подготовить отдельный purge-runbook для удаления локального legacy storage только после подтверждения, что rollback больше не нужен.

## Критерии готовности

- `missing_metadata_rows=0`: `chat_history` не содержит object-backed attachment rows без `chat_attachment_metadata`.
- `unexpected_missing_s3_dialog_objects=0` в `docker-production-storage-cutover-gate.ps1`.
- Reviewed historical loss в точности совпадает с `ai-context/storage-known-unrecoverable-dialog-attachments.json`; на 28 августа 2026 года это 20 записей с `availability_status=missing`, для которых исходные байты не найдены ни в canonical MinIO, ни в legacy unprefixed MinIO, ни в текущих/старых local attachment roots, ни при read-only поиске по Windows user profile.
- `stale_known_unrecoverable_entries=0`: manifest не содержит уже восстановленных, изменённых или исчезнувших metadata records.
- `missing_s3_panel_avatars=0` и `invalid_panel_avatar_refs=0`.
- `missing_s3_client_avatars=0` для клиентов, у которых есть `client_avatar_history`.
- Все доступные исторические вложения открываются через текущие URL панели без чтения из local fallback; reviewed known-unrecoverable attachments явно остаются недоступными, а не подменяются фиктивными объектами.
- Аватары клиентов и панели доступны после отключения legacy fallback.
- `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED=false` не ломает `/login`, диалоги и media preview для реально существующих объектов.
- Есть отдельный ручной план purge legacy files и rollback для этого шага.

## Safety gates

- До GREEN `docker-production-storage-cutover-gate.ps1`, GREEN client-avatar audit и ручной UI-проверки `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED` остаётся `true`.
- Reviewed known-unrecoverable manifest не является wildcard-исключением: gate требует точное совпадение `metadata_id`, `storage_key`, `availability_status=missing` и фактического отсутствия canonical S3 object. Любое новое отсутствие вне manifest блокирует cutover.
- Если любой manifest object появляется в S3, metadata key/status меняется или запись исчезает, gate останавливается до ручного обновления manifest.
- Нельзя создавать пустые/фиктивные MinIO objects для прохождения audit: это скроет потерю данных и нарушит integrity исторических вложений.
- Bulk mirror не является доказательством завершённой миграции сам по себе: source of truth для attachment correspondence — `chat_attachment_metadata.storage_key`, а финальное доказательство для существующих объектов — `mc stat` canonical runtime S3 key.
- Backfill/audit/gate scripts не удаляют local legacy source.
- Перед любым live operator script сначала выполняется `-ValidateOnly` на Windows host.
- Physical purge не входит в автоматический cutover и требует отдельной ручной процедуры после подтверждённого rollback window.

## Update 2026-08-28 - cutover tooling hardening

- Production contour явно передаёт `APP_STORAGE_OBJECT_KEY_PREFIX` в panel и bot containers; `.env.example` фиксирует default `iguana`.
- Backfill зеркалит legacy roots в canonical prefix, затем для каждой metadata row точечно проверяет `prefix/attachments/storage_key`; `available` выставляется только после S3 verification.
- Убрано угадывание Compose network и строковая подстановка MinIO credentials.
- Добавлены read-only audits для attachment mappings, panel/operator avatar references и client avatar runtime keys.
- Windows CRLF/native quoting проблемы в storage operator scripts изолированы статическими LF-only shell helpers.
- Live repair 28 августа 2026 года подтвердил 52 canonical attachment objects и 20 отсутствующих object-backed attachments без execution errors.
- Последующий read-only поиск подтвердил, что для этих 20 нет источника в legacy MinIO, текущих attachment roots, старом абсолютном `Documents\tg_bot\...` checkout или других каталогах Windows user profile.
- Эти 20 зафиксированы как reviewed known-unrecoverable historical loss; local fallback уже не может обслужить их, поскольку локальные байты отсутствуют.
