# Задача [01-218] Выполнить финальный cutover legacy media: пересобрать runtime с metadata backfill, отключить local fallback и подготовить purge legacy storage

## Краткое описание

Довести перенос legacy media до состояния, когда production contour больше не зависит от локального `attachments/**` даже как от fallback-источника: новый runtime должен сам досоздать недостающие `chat_attachment_metadata`, подтянуть исторические ссылки из `chat_history`, а затем позволить безопасно выключить `app.storage.object.legacy-local-fallback-enabled`.

## Почему это важно

- На 27 августа 2026 года backfill в MinIO уже выполнен, но в PostgreSQL ещё остаются строки `chat_history`, для которых `chat_attachment_metadata` не создана автоматически.
- В коде уже добавлен безопасный переключатель `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED`, но по умолчанию он оставлен включённым, чтобы не ломать рабочий контур до новой выкладки.
- Без финального cutover мы всё ещё зависим от локального legacy storage для части исторических диалогов и аватаров.

## Что нужно сделать

1. Пересобрать и перевыкатить `iguana-panel:local` с последними изменениями `ChatAttachmentMetadataAvailabilityService`, `AttachmentService` и `AttachmentObjectStorageService`.
2. После старта обновлённого runtime проверить, что missing metadata rows из `chat_history` были созданы автоматически и перешли в корректные `availability_status`.
3. Повторно прогнать `scripts/docker-production-storage-backfill.ps1`, при необходимости уже с `-RestartRuntime`, и замерить остаточный хвост.
4. Запустить read-only mapping audits и убедиться, что все runtime object keys реально существуют в MinIO:
   - `scripts/docker-production-storage-cutover-audit.ps1` — attachment metadata + `users.photo` panel/operator avatars;
   - `scripts/docker-production-client-avatar-cutover-audit.ps1` — client avatar runtime keys `<userId>.jpg` / `<userId>_full.jpg` для клиентов с avatar history.
5. После ручной валидации UI, карточек диалогов, медиа и аватаров перевести `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED=false` в production contour с recreate runtime containers, а не простым `restart`.
6. Повторить read-only audits и UI/media checks уже с отключённым fallback.
7. Подготовить отдельный purge-runbook для удаления локального legacy storage только после подтверждения, что rollback больше не нужен.

## Критерии готовности

- `chat_history` больше не содержит значимого хвоста строк без `chat_attachment_metadata`.
- `missing_s3_dialog_objects=0` для всех object-backed attachment metadata.
- `missing_s3_panel_avatars=0` и нет неразрешимых `users.photo` ссылок, которые должны обслуживаться object storage.
- `missing_s3_client_avatars=0` для клиентов, у которых есть `client_avatar_history`.
- Исторические вложения открываются через текущие URL панели без чтения из local fallback.
- Аватары клиентов и панели доступны после отключения legacy fallback.
- `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED=false` не ломает `/login`, диалоги и media preview.
- Есть отдельный ручной план purge legacy files и rollback для этого шага.

## Safety gates

- До GREEN live audits `APP_STORAGE_OBJECT_LEGACY_LOCAL_FALLBACK_ENABLED` остаётся `true`.
- Bulk mirror не является доказательством завершённой миграции сам по себе: source of truth для attachment correspondence — `chat_attachment_metadata.storage_key`, а финальное доказательство — `mc stat` canonical runtime S3 key.
- Backfill/audit scripts не удаляют local legacy source.
- Перед любым live backfill сначала выполняется `-ValidateOnly` на операторской Windows машине; этот шаг предназначен для реального PowerShell parser + Compose model gate без runtime data mutation.
- Physical purge не входит в автоматический cutover и требует отдельной ручной процедуры после подтверждённого rollback window.

## Update 2026-08-28 - cutover tooling hardening

- Production contour теперь явно передаёт `APP_STORAGE_OBJECT_KEY_PREFIX` в panel и bot containers; `.env.example` фиксирует default `iguana`.
- Backfill зеркалит legacy roots в canonical prefix, затем для каждой metadata row точечно проверяет `prefix/attachments/storage_key`; `available` выставляется только после S3 verification.
- Убрано угадывание Compose network и строковая подстановка MinIO credentials.
- Добавлены read-only audits для attachment mappings, panel/operator avatar references и client avatar runtime keys.
- Java tests фиксируют exact S3 keys с `iguana/attachments/...` и `iguana/avatars/...`.
- До первого live запуска при сверке с MinIO CLI docs исправлен unsupported `mc cp --overwrite` на `mc cp`; `--overwrite` остаётся только у `mc mirror`.
- GitHub Actions на эти изменения автоматически не запускались; live Windows `-ValidateOnly`, rebuild/redeploy и runtime audits ещё не выполнены.
