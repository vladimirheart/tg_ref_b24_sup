## Реализовано

- Участник задачи с PAGE_TASKS получает READ без отдельной разрешающей строки
  shared_work_grants. Явный can_read=false, blocked/disabled, текущая identity и
  запрет страницы остаются обязательными ограничениями.
- Существующий NULL owner больше не отменяет numeric assignee/co/watcher READ
  и явные EDITOR/VIEWER назначения. Владелец не угадывается; orphan OWNER исключён.
- По уточнению пользователя READ проекта открывает все связанные задачи.
  «Мои задачи» дополнительно требуют личного assignee/co/watcher участия.
  Project EDITOR не получает task WRITE/OWNER; несвязанные задачи остаются скрыты.
- People API ищет по логину и ФИО, возвращает fullName и точный numeric ID.
  Дополнительный скрытый допуск больше не обнуляет список кандидатов.
  UI поясняет общие права; обновлены версии двух скриптов в шаблонах.
- Исправлена гонка Bootstrap: отказ доступа во время открытия backdrop закрывает
  окно после shown.bs.modal. Результат неопределённой mutation повторно не отправляется.
- Отзыв project membership/link ждёт выполняющийся READ/доставку. Первый общий
  запрет сериализуется по account: отдельный pre-lock statement даёт permission
  statement свежий READ COMMITTED snapshot после ожидания INSERT can_read=false.
  Для stale/deleted identity список по-прежнему пуст, прямой READ закрыт.
