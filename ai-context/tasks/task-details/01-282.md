# Задача [01-282]

## Короткое описание

Перевести список диалогов на серверную пагинацию, фильтрацию и сортировку без загрузки всех обращений в HTML и браузер.

## Цель

Размер HTML, JSON и DOM списка ограничен выбранной страницей независимо от количества обращений в PostgreSQL. Сводные счётчики остаются общими; обновления списка не возвращают весь архив.

## Контекст

- Пользователь подтвердил реализацию после проверки текущего поведения `/dialogs`: полная выборка, полный HTML и скрытие строк при клиентской пагинации.
- Исходный baseline: `eebffe9bf34a36648e22fab73f14e5b63e594967`; `HEAD`, `origin/main` и remote main совпадают, основной checkout чистый.
- Связанные задачи: `01-276` (номера обращений и отдельная пагинация уведомлений), `01-278` (scope/identity), `01-281` (сохранить принятый UI).
- Статус: 🟣 AI завершил, ожидается ручная проверка пользователя. Изменения сначала выполнены и проверены в detached sandbox.

## Что сделать

- Добавить ограниченную SQL-выборку страницы с общим количеством, стабильной сортировкой, поиском, статусом, triage/SLA-фильтрами.
- Ограничить первоначальную HTML-выборку; убрать режим неограниченного размера страницы.
- Отдельно считать агрегаты и ограничить вспомогательные списки «Мои диалоги», не выводить их из текущей страницы.
- Подключить серверную пагинацию в браузере: смена фильтров/страницы, защита от устаревших ответов, SSE/poll перечитывает только страницу.
- Сохранить прямое открытие обращения, точные opaque ID, номера, права доступа, групповые действия только над явно выбранными загруженными строками.
- Проверить SQL на настоящем изолированном PostgreSQL, HTTP-контракты, frontend и поведение на тысячах записей.

## Критерии готовности

- `/dialogs` и `/api/dialogs` не загружают/не сериализуют весь список; лимит действует и при отсутствии/некорректности параметров.
- Поиск, фильтры и сортировка работают по всей допустимой выборке, не только по загруженной странице.
- Счётчики, пагинация, пустые страницы, быстрые смены фильтров и обновления после SSE корректны.
- GENERAL и raw-ID collisions не попадают в legacy список; scope не расширен.
- Нет миграций, backfill, изменения feature flags или перезапуска ботов. Deploy — отдельный проверяемый шаг, без попутного развёртывания незавершённых серверных изменений.
- Targeted тесты GREEN, guard-перенос в основной checkout проверен; фактическое состояние и ограничения отражены в отчёте.

## Фактический результат — 26.10.2026

- SQL-пагинация и count в одном snapshot; страница по умолчанию 20, максимум 100. Поиск, статус, triage/SLA-фильтры и порядок выполняются до limit. Номера считаются до фильтрации.
- Ограничены первоначальный HTML, JSON, DOM и preview «Мои диалоги». Полные счётчики независимы от страницы; закрепления дополняют preview адресно.
- Read-only POST передаёт фильтры и точные ID без URL-length/comma-splitting, требует PAGE_DIALOGS/CSRF; старый GET тоже ограничен.
- Debounce/abort/generation guard, coalescing SSE, повторное чтение при возвращении к вкладке, обработка ошибки/повтора и time-based SLA refresh. Выбор строк не переносится на другую страницу.
- 178 Java-тестов / 11 suites GREEN; 98 JS runner tests GREEN; 4 browser contexts и 8 снимков GREEN. Изолированный PostgreSQL с 10 000 обращений: 20/100 строк страницы, preview 20 при общем count 10 000.
- Расширенный прогон отдельно выявил 4 прежних 404 в DialogListIntegrationTest и прежний VM-тест заметок; все воспроизведены на неизменённом baseline, не скрыты ослаблением проверок.
- Из sandbox guarded-перенос в основной checkout; 28 файлов с metadata. Commit/push не выполнялись.
- Обновлён только panel-web: `iguana-panel:dialogs-pagination-20261026`, image `sha256:1a8f1c4f2ca630fb15314fcba23123fadc00b2c79bf5cd04db58420679e16733`, healthy. 17 остальных Compose-контейнеров и 4 bot JVM сохранены.
- Flyway остаётся V82, история миграций, настройки мониторинга, полный environment и 4 bind mounts не изменены; нет backfill и смены flags.
- Rollback: `iguana-panel:rollback-dialogs-pagination-web-20261026` → прежний R20 image. Первая попытка выпуска откатилась из-за трактовки native stderr в PowerShell 5.1; версия release-v2 проверяет exit code и успешно выпущена.
