# 01-324 — Файлы во внутренней переписке

Статус: 🟣 Установлено, ожидается ручная проверка.

Добавить выбор нескольких файлов, paste/drop, предпросмотр/удаление перед
отправкой и защищённое скачивание в операторской переписке.
Baseline HEAD/origin/main: 581002b2fe2a2934cddc697e1a22617dad8bee74, clean.
Detached sandbox, targeted PostgreSQL/MVC/storage/browser проверки и те же
patches в main после content/file-set guards. Без stage/commit/push и
реальных тестовых отправок клиенту.

Контракт: отдельный object-storage domain и PostgreSQL metadata. READ для
скачивания, OPERATE для отправки; full owner/current account checks.
Клиентская история, transport/outbox и AI не получают внутренних файлов.
До 10 файлов, суммарно до 50 МБ; размер запроса укладывается в текущие 60 МБ.

Применимые правила: 00 operating protocol, 01 guarded changes, 02 production
checkpoint, 05 storage boundary и 12 dialog history/internal collaboration.

## Реализовано

- Отдельная скрепка во внутреннем поле; выбор нескольких файлов, вставка из
  буфера и drag/drop. Предпросмотр изображений и удаление из очереди до отправки.
  Общий Enter/Ctrl+Enter и split-button сохранены; можно отправить только файлы.
- Собственные draft/queue/request UUID отделены от клиентского composer.
  При ошибке текст и файлы остаются; повтор использует тот же request UUID.
  На сервере replay сверяет текст и упорядоченные имя/MIME/размер/SHA-256.
- V108 добавляет append-only metadata и разрешает пустой текст файлового
  сообщения. Запись сообщения и всех metadata атомарна. Потоковая загрузка
  выполняется вне JDBC locks; перед SQL commit повторяются account/grants/owner.
- Бинарники изолированы в internal_dialogs; нет записи в клиентскую историю,
  transport/outbox или AI. GET проверяет PAGE_DIALOGS и current READ полного owner.
  Inline только для распознанных raster/audio/video; остальное скачивается с
  no-store/nosniff. Поддержаны single-range 206/416 для воспроизведения media.
- Известный rollback/неполная загрузка удаляют новые объекты. При неизвестном
  результате commit бинарники сохраняются приватными, чтобы не удалить уже
  зафиксированное вложение. Незарегистрированные объекты API не выдаёт;
  автоматическая фоновая сверка осиротевших объектов в этот scope не входит.
- Polling сохраняет media DOM nodes; загрузка preview следует за нижним краем.
  Read marker учитывает clipping всех scroll ancestors и не отмечает скрытую
  историю прочитанной при прокрутке к очереди файлов.

## Ручная проверка

1. Ctrl+F5; во внутреннем блоке выбрать несколько файлов скрепкой, вставить
   скриншот, перетащить файл и удалить один из очереди.
2. Отправить с подписью и без текста; проверить скачивание во второй операторской
   сессии и сохранность после reload, изображение/audio/video при наличии.
3. Убедиться, что клиент не получил внутренние файлы, а клиентский draft остался.
4. При сетевой ошибке повторить отправку: очередь сохраняется, дубля не возникает.
