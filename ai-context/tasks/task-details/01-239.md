# Задача [01-239] Актуализировать README и production-документацию под dynamic bot-runner и PostgreSQL contour

## Цель

Пересобрать входную и эксплуатационную документацию так, чтобы она описывала фактический production-контур после миграции bot runtime: PostgreSQL, RabbitMQ, Redis, MinIO/S3 и единый dynamic `bot-runner`.

## Контекст

- Задачи `01-237` и `01-238` ввели single-replica supervisor, который автоматически запускает runtime для всех active Telegram, VK и MAX channels.
- В README и части runbooks оставались устаревшие формулировки про SQLite как основной набор БД, external static bot containers и прежний `APP_DB_MODE=worker` contract.

## Что сделать

- Обновить README как короткую актуальную точку входа.
- Синхронизировать current architecture snapshot, Docker contour, runtime roles runbook и bot runtime contract.
- Зафиксировать single-replica правило, границу static emergency profiles и проверочные команды.

## Критерии готовности

- Документы не называют SQLite live production source of truth.
- Production запуск описывает `bot-runner=1` и автоматическое обнаружение active channels.
- Нет противоречия между datasource contract, compose topology и runbook.

## Выполнение

- README переработан как актуальная входная точка: production data находятся в PostgreSQL, media - в MinIO/S3, coordination - в Redis, transport - в RabbitMQ.
- Зафиксирован single-replica `bot-runner`, который запускает runtime для неограниченного числа active channels; static bot profiles описаны как emergency-only.
- `docs/CURRENT_PROJECT_DOCUMENTATION.md`, `docs/docker-production-contour.md`, `docs/runbooks/runtime-deployment-roles.md` и `docs/BOT_RUNTIME_CONTRACT.md` синхронизированы с этим contract.
- Проверены отсутствие устаревших production-формулировок, существование README-ссылок и `git diff --check`.
