# Задача [01-279]

## Короткое описание

Ограничить накопление неиспользуемых Docker-образов проекта и контейнерных логов.

## Цель и контекст

После ручной очистки Docker Desktop пользователь разрешил встроить обслуживание
в проект. Общий builder уже использует GC с порогом 20 ГБ; его настройки являются
настройками машины. Репозиторий содержит PowerShell/Bash launchers и несколько
Compose-контуров. Baseline HEAD/origin/main: `4cc81f8a799f748063655762fa3ef00f0a9563f8`.

## Что сделать

- Помечать собираемые образы меткой проекта.
- Добавить PowerShell/Bash обслуживание: отчёт по умолчанию, явная очистка,
  недельный интервал и привязка состояния к Docker daemon и Compose project.
- Автоматически запускать очистку после успешного detached-запуска с пересборкой.
- Ограничить Docker stdout/stderr logs во всех Compose-контурах.
- Описать настройки, ручной запуск и границы обслуживания.

## Ограничения и критерии готовности

- Удаляются только dangling-образы проекта старше retention; tagged rollback
  images, контейнеры, volumes и данные других проектов сохраняются.
- Общий build cache, Docker Desktop, WSL и VHDX не изменяются автоматически.
- Ошибка обслуживания не превращает успешный запуск приложения в ошибку.
- Windows PowerShell 5.1 и Bash проверены с подменённым Docker; реальные prune,
  builds, up/down и deploy не выполняются во время разработки.
- Compose config проверен для всех контуров и нестандартного project name.

## Проверка и фактическое состояние

Готово AI, статус 🟣; ожидается ручная проверка пользователя.

- 32 поведенческих теста PowerShell/Bash, включая launchers, прошли с fake Docker.
- После уточнения обработки повреждённого timestamp повторно прошли четыре
  целевых проверки; CRLF/LF stamps совместимы.
- PowerShell 5.1 parser и Bash syntax checks прошли.
- Docker Compose config: 14 комбинаций файлов, 206 проверок сервисов, default /
  custom project name и overrides ротации логов прошли.
- Проверка сначала выполнена в detached temporary worktree; применяются только
  проверенные изменения при сохранении исходного HEAD/origin/main.
- Реальные prune, сборки, up/down, WSL shutdown и сжатие VHDX не выполнялись.
- Staging, commit, push, deployment и production acceptance не выполнялись.
