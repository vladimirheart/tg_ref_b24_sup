# Задача [01-166]

## Краткое описание

Показать в мониторинге фактический runtime-статус запущенных ботов по каналам.

## Цель

Сделать так, чтобы на странице мониторинга/аналитики пользователь видел реальные статусы bot runtime по каналам, а не искал их только в настройках каналов или по косвенным признакам.

## Контекст

- Пользователь сообщил, что в мониторинге не видно, что боты запущены.
- В проекте уже существует `BotProcessService` и API `/api/bots/{channelId}/status`, которые умеют определять `running/stopped/error` и время старта.
- В sidebar уже есть mini-индикаторы по ботам, а в monitoring/analytics-странице отдельного блока bot runtime сейчас нет.
- Значит, проблема не в отсутствии базового runtime status service, а в том, что monitoring surface не подключён к существующему контракту.

## Что сделать

- Добавить backend surface для bot runtime monitoring summary/list на analytics-страницу.
- Использовать существующий `BotProcessService` как источник истины по статусам.
- Показать в monitoring UI:
  - сводку по числу `running/stopped/error/inactive`;
  - список каналов с платформой, именем, статусом и временем старта;
  - автообновление и ручное обновление.
- По возможности подписать UI на уже существующие SSE-события `sidebar_bots_changed`, чтобы статус обновлялся без перезагрузки страницы.

## Критерии готовности

- На странице аналитики/мониторинга появляется отдельный bot runtime блок.
- Пользователь видит, какие именно каналы реально запущены.
- Статус обновляется после старта/остановки бота без необходимости идти в настройки канала.
