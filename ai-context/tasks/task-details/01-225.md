# Задача [01-225] Довести persisted credential rotation до Bash parity и remaining apply contour

## Краткое описание

После Windows-first apply-path для `postgresql`, `rabbitmq`, `redis` и `minio`
нужно было добиться Bash parity, чтобы ротацию можно было выполнять и в
Linux/Git Bash контуре без зависимости от PowerShell.

## Почему это важно

- production cutover не должен зависеть только от PowerShell/Windows;
- одинаковый contract для PowerShell и Bash снижает вероятность ручных ошибок;
- MinIO probe в Git Bash требует отдельной защиты от MSYS path conversion, иначе
  проверка bucket access падает не по бизнес-логике, а на уровне shell/runtime.

## Что сделано

1. Добавлен Bash entrypoint `scripts/docker-production-credential-migration-apply.sh`.
2. Bash workflow покрывает те же компоненты:
   - `postgresql`;
   - `rabbitmq`;
   - `redis`;
   - `minio`.
3. Для Bash-версии реализованы:
   - dry-run и real apply параметры;
   - live auth preflight для PostgreSQL, RabbitMQ и Redis;
   - bucket access verification для MinIO;
   - `.env` checkpoint и best-effort rollback;
   - coordinated recreate зависимых сервисов;
   - auto-append observability overlay, если monitoring contour уже поднят.
4. Для MinIO в Git Bash добавлена защита
   `MSYS_NO_PATHCONV=1` и `MSYS2_ARG_CONV_EXCL='*'`, чтобы `docker run --entrypoint /bin/sh`
   не ломался из-за преобразования пути.
5. Обновлены:
   - `docs/runbooks/persisted-credential-rotation-apply.md`;
   - `spring-panel/src/test/java/com/example/panel/runtime/PersistedCredentialRotationApplySourceContractTest.java`.

## Проверка

Через `C:\Program Files\Git\bin\bash.exe` успешно прошли:

- `bash -n ./scripts/docker-production-credential-migration-apply.sh`;
- dry-run `--component postgresql`;
- dry-run `--component rabbitmq`;
- dry-run `--component redis`;
- dry-run `--component minio`.

Отдельно подтверждено, что MinIO dry-run падал именно из-за MSYS path conversion, и
после фикса probe начал проходить штатно.

## Что осталось

- controlled apply-path для `grafana`;
- bulk rotation нескольких компонентов за один прогон;
- rehearsal flow для multi-component rotation;
- optional pre-apply backup snapshot, а не только `.env` checkpoint.
