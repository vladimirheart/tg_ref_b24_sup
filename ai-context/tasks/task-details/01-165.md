# Задача [01-165]

## Короткое описание

Починить падение `spring-panel` на startup из-за битой `chat_attachment_metadata` в availability reconcile.

## Цель

Сделать запуск панели устойчивым к corruption/ошибкам чтения `chat_attachment_metadata`, чтобы availability reconcile не валил весь Spring context.

## Контекст

- По логу запуска от `2026-07-31` приложение доходит до инициализации Spring context, Flyway проходит успешно, затем падает в `ChatAttachmentMetadataAvailabilityService`.
- Причина падения:
  - `SELECT ... FROM chat_attachment_metadata`
  - `SQLITE_CORRUPT` / `database disk image is malformed`
- Это non-critical reconcile-проход availability status для attachment metadata, а не основная бизнес-функция старта панели.
- Ранее уже добавлен degraded history fallback в `DialogConversationReadService`, поэтому metadata corruption не должен блокировать ни UI history, ни startup.

## Что сделать

- Убрать startup-фатальность из `ChatAttachmentMetadataAvailabilityService`.
- При проблемах чтения/обновления `chat_attachment_metadata` логировать degraded warning и продолжать запуск панели.
- Зафиксировать поведение unit-level тестом.
- Подтвердить реальным запуском `spring-panel` на текущем workspace.

## Критерии готовности

- `spring-panel` не падает на `BeanCreationException` из-за `ChatAttachmentMetadataAvailabilityService`.
- При corruption metadata сервис логирует предупреждение и пропускает reconcile.
- Запуск панели доходит до `Started PanelApplication` на текущей runtime БД.

## Результат выполнения

- В `ChatAttachmentMetadataAvailabilityService` startup reconcile переведён в degraded-safe режим:
  - при `DataAccessException` сервис больше не роняет Spring context;
  - пишет warning и пропускает availability reconcile для битой `chat_attachment_metadata`.
- Добавлен unit-level regression test, фиксирующий сценарий corrupted metadata без startup exception.
- На текущем workspace подтверждено:
  - `spring-panel\\mvnw.cmd -q -DskipTests compile` проходит успешно;
  - `run-windows.bat` больше не падает на `chatAttachmentMetadataAvailabilityService`;
  - в runtime-логе появляется warning `Skipping attachment metadata availability reconcile...`;
  - приложение доходит до `Started PanelApplication in 66.861 seconds`.
- Поднятый после проверки процесс был остановлен вручную, чтобы не держать порт `8099` занятым.
