# Задача [01-208]

## Короткое описание

Собрать dockerized production contour Iguana и развести lifecycle `spring-panel` и `java-bot` runtime.

## Цель

Подготовить для репозитория реальный container-first contour, который соответствует текущей production-архитектуре проекта: `spring-panel` как backend-owner, `PostgreSQL + RabbitMQ + Redis + S3-compatible storage` как обязательный infra foundation и bot runtimes как отдельные контейнеры, а не child-process внутри панели.

## Контекст

- По состоянию на `25 августа 2026 года` проект уже мыслится как `PostgreSQL-first` contour с обязательными `Redis`, `RabbitMQ` и object storage.
- В репозитории до этого был только локальный compose для `PostgreSQL` и `RabbitMQ`, а panel-side `BotProcessService` и `BotAutoStartService` всё ещё тянули lifecycle ботов как локальных процессов.
- Для containerized contour это создаёт operational ambiguity: panel одновременно выступает backend-owner и process supervisor, что противоречит целевой production-модели.
- Для новых infra-изменений нужно удерживать project rule про backend-owned storage boundaries и не возвращать bot runtime в роль владельца business state.

## Что сделать

- Добавить production-like compose contour с сервисами `spring-panel`, `postgres`, `rabbitmq`, `redis`, `minio` и отдельными bot containers.
- Подготовить Dockerfile для `spring-panel` и общий Dockerfile для bot modules.
- Добавить явный runtime guardrail, который позволяет отключить panel-side auto-start bot child processes в containerized deployment.
- Обновить документацию и env contract так, чтобы новый contour был описан как рекомендуемый operational path.
- Зафиксировать ограничение, что lifecycle bot containers принадлежит `docker compose`, а panel-side process control остаётся только compatibility/dev convenience path.

## Критерии готовности

- В репозитории есть отдельный dockerized contour-файл для full production-like stack.
- Есть Dockerfile для `spring-panel` и bot runtime.
- Panel-side autostart child processes можно явно отключить конфигом, и этот путь покрыт тестом.
- Документация и `.env.example` описывают новый contour и его обязательные env keys.
