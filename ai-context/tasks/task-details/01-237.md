# Задача [01-237] Выделить единый dynamic bot-runner для неограниченного числа активных каналов

## Цель

Убрать ограничение статических Docker profiles `telegram`, `vk` и `max`: один выделенный supervisor должен запускать отдельный prebuilt JAR для каждого активного канала из PostgreSQL.

## Контекст

- Каналы, токены и настройки хранятся в PostgreSQL.
- `BotAutoStartService` уже умеет обходить все активные каналы, но пустой список runtime-ролей не создавал bean в split production contour.
- Запуск из `panel-web` недопустим при горизонтальном масштабировании web-реплик: он создаст дублирующиеся child-процессы.

## Выполнение

- Добавлена роль `bot-runner` и назначена `BotAutoStartService`.
- В production compose добавлен единственный health-checked сервис `bot-runner`.
- `bot-runner` передаёт child-ботам внутренний адрес `http://panel-web:8080` и общий PostgreSQL/RabbitMQ/Redis/S3 contract.
- Production launchers принудительно удерживают `bot-runner=1`.

## Критерии готовности

- После restart `bot-runner` запускает все активные Telegram, VK и MAX каналы.
- Для каждого Telegram token есть ровно один Redis ingress lease и отсутствует `409 Conflict`.
- `panel-web` можно масштабировать независимо, без запуска дубликатов bot-процессов.
- В child process logs нет SQLite JDBC.

## Проверка пользователя

- Отправить по одному текстовому сообщению в каждый активный Telegram и MAX канал.
- В панели проверить создание диалога и ответ бота; для Telegram дополнительно отправить sticker.

## Выполнение

- `bot-runner` развернут из `iguana-panel:local` и проходит healthcheck.
- Супервизор запустил три active runtime: Telegram channel `1`, MAX channel `2`, Telegram channel `3`.
- В Redis подтверждены два независимых Telegram lease по SHA-256 fingerprint токенов и один MAX lease.
- В свежих Telegram process logs подтверждены успешное подключение и active ingress owner; `409 Conflict` и SQLite JDBC не обнаружены.
