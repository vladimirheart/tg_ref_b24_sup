## Реализация

- ReleasingHibernateJpaDialect выполняет штатную Spring cleanupTransaction,
  включая восстановление isolation/readOnly, затем возвращает physical lease
  request-bound EntityManager через managed logical connection manualDisconnect.
  OSIV остаётся включённым для прежнего lazy rendering. Режим HOLD сохранён:
  простая глобальная замена на AFTER_TRANSACTION ломала бы Spring custom isolation.
  При последующем lazy read logical connection может получить новый lease.
- Для findPage/findForUser/summary оповещений используется SET LOCAL jit=off
  внутри существующей транзакции. SQL access predicates, порядок сортировки и
  cursor semantics сохранены. В ответе максимум 10 записей; SQL читает до 11
  для определения hasMore, не выгружает всю историю.
- Web pool задаётся отдельно APP_PANEL_WEB_DB_MAX_POOL_SIZE, default 15.
  Текущий rollout явно задаёт APP_DB_MAX_POOL_SIZE=15 только panel-web.
  Остальные service pools и child minimumIdle=5/maximumPoolSize=20 не изменены.
- NotificationSnapshotReader читает готовый счётчик и первую страницу по
  numeric stream identity/session version с актуальными account/role/grants.
  SecurityContext подставляется только для внутреннего trusted recipient и
  восстанавливается в finally; routing name не разрешается в другой аккаунт.
- NotificationPushService объединяет bursts на пользователя, использует два
  executor threads и один pending slot на recipient. Изменение во время чтения
  вызывает один follow-up. Транзакция Reader завершена до сетевой отправки.
  Commit-публикация адресных уведомлений отложена до afterCommit; rollback
  ничего не публикует, ошибка публикации после commit не превращает запись в 500.
- SSE отправляет готовые notifications_snapshot с instance/sequence, unread и
  page. Первое соединение и heartbeat 25 секунд сверяют состояние, поскольку
  Redis pub/sub не обеспечивает replay. Отозванный аккаунт/сессия закрывают
  поток; после чтения снова проверяется текущая session version перед отправкой.
  Legacy notifications_changed сохраняется для старых вкладок.
- Браузер принимает новые snapshots, игнорирует старую sequence и старые HTTP
  responses. При здоровом push не перечитывает счётчик на каждом изменении
  диалогов. Колокольчик использует свежую первую страницу, старые страницы
  запрашиваются по скроллу порциями по 10; single-flight, coalescing, backoff,
  timeout и generation guard сохраняются при close/reopen и ошибках.
- Обнаружены и устранены скрытые GET списка из notification-sounds.js:
  инициализация, generic sound, входящее сообщение и оценка больше не читают
  /api/notifications. Категория звука берётся из готового snapshot, сообщения
  и оценки сохраняют свои realtime sounds.
- Scoped rating event обогащается маленькой latest-value projection после
  current READ/full-owner проверки. Браузер меняет звёзды в строке и открытом
  диалоге по public ID/business ID/version без reload списка; bell не создаётся.
- После SSE reconnect сверяется также открытая история. События в процессе
  загрузки истории объединяются в один follow-up; чужой owner response не
  отображается. Таймеры не переносят refresh бесконечно при непрерывном потоке.
- Nginx пишет JSON request ID/request_time/upstream_time/status без query/body.
  HTTP filter возвращает X-Request-ID и пишет медленные/ошибочные запросы с
  длительностью и path, async completion ровно один раз. Продолжительность SSE
  означает время жизни потока, а не latency обычного API.
- При pending дольше 15 секунд Hikari reporter сохраняет thread dump, с cooldown
  5 минут и максимум 32 stack frames на поток; диагностический путь не берёт JDBC.

  Native изолированный PostgreSQL: 20 concurrent request-bound EM при pool 6,
  затем 15; READ COMMITTED/REPEATABLE READ/readOnly, настоящий
  JdbcIndexedSessionRepository save/find/delete, после завершения active/pending=0.

  targeted rating без list reload и прежние files/unread/emoji/scroll guards.
