# Задача [01-176]

## Краткое описание

Исправить NetBox sync, который падает на `HTTP 403` при обходе пагинации по `next` URL из ответа NetBox, и сделать блок NetBox в UI перечитывающим серверное состояние после сохранения и запуска sync.

## Цель

Убрать ложное ощущение, что URL/token не сохраняются, и сделать импорт из NetBox устойчивым к absolute `next` ссылкам с отличающейся схемой или host-представлением.

## Контекст

- В `logs/spring-panel.log` зафиксирован сбой:
  - `NetBox вернул HTTP 403 для http://netbox.sushivesla.su/api/dcim/sites/?limit=100&offset=100: {"detail":"Authentication credentials were not provided."}`
- При этом прямые запросы с тем же token к `https://netbox.sushivesla.su` и к основным API endpoint отвечают `200`.
- Текущий `NetBoxApiService` безусловно использует `next` URL из ответа NetBox как есть.
- UI NetBox после save/run опирается в основном на локальное JS-состояние и не перечитывает сохранённую backend-конфигурацию.

## Что сделать

- В `NetBoxApiService` канонизировать absolute URL из ответов NetBox к базовому `base_url` настроек для same-host ссылок.
- Применить ту же канонизацию к скачиванию файлов/фото из NetBox.
- После `save` и `run` в runtime NetBox принудительно перечитывать секцию `locations` с backend и рендерить фактическое сохранённое состояние.

## Критерии готовности

- Полный sync не падает на `403 Authentication credentials were not provided` при переходе по `next` ссылкам NetBox.
- После сохранения подключения в UI остаётся фактический сохранённый `base_url`, а token отражается через `api_token_saved` и подсказку backend.
- Сборка проходит.
