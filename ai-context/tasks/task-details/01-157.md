# Задача [01-157]

## Краткое описание

Обновить live-синхронизацию шаблонов вопросов и UX сохранения в настройках ботов.

## Цель

Сделать так, чтобы новые шаблоны вопросов сразу появлялись в селектах ботов без ручного обновления страницы, ошибки сохранения визуально читались как ошибки, а успешное сохранение закрывало соответствующие модальные окна.

## Контекст

- Страница настроек уже разделена на несколько runtime-модулей, и каталог шаблонов вопросов для каналов живёт отдельно от редактора шаблонов бота.
- Сейчас после сохранения шаблона вопроса обновляется backend, но клиентский runtime селектов каналов продолжает использовать старый in-memory каталог до полного reload страницы.
- В статусных строках редактора бота базовый класс `text-muted` конфликтует с ошибочными сообщениями и делает их визуально серыми.
- В части runtime-уведомлений тип popup не передаётся явно, поэтому ошибки и успехи получают одинаковый инфо-стиль.

## Что сделать

- Добавить обновляемый каталог шаблонов в runtime каналов и синхронизировать его после сохранения шаблонов/настроек бота.
- Исправить стилизацию status line и popup-уведомлений для error/success сценариев.
- Закрывать модальные окна после успешного сохранения там, где это ожидается по текущему UX-паттерну проекта.

## Критерии готовности

- Новый шаблон вопросов появляется в выборе шаблона бота без ручного обновления страницы.
- Ошибки сохранения отображаются красным стилем, а не серым.
- После успешного сохранения модалка настройки бота и редактор канала закрываются автоматически.

## Обязательные дополнительные условия

- По завершении задачи показать алерт через `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно не отменил это требование.
- В финальном ответе подготовить `Резюме для коммита` по формату из `ai-context/baseline/guides/tasks.md`.
- После любых file changes создать отдельный changelog-файл в `ai-context/changelog` по правилу «одно изменение = один файл» и включить в него пользовательский промт, который привёл к изменению.
