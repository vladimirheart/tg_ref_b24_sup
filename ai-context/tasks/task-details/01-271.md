# Задача [01-271]

## Короткое описание

Вынести управление backup destination в админку: тип хранилища, безопасный auth boundary, host-side connection probe, нормализованные ошибки, history и DR classification.

## Контекст

- `01-212` технически умеет создавать и восстанавливать production backup, но остаётся `🟡`, потому что текущий `C:\\1C\\backup` находится на локальном диске production-host и не доказывает отдельный failure domain.
- `01-236` workflow-ready, но real credential rotation заблокирована до DR proof либо отдельного явного принятия риска пользователем.
- Backup policy уже управляется через `Настройки -> Backup & recovery`, хранит non-secret policy в `backup.properties` и исполняется host policy runner'ом.
- Пользователь одобрил добавление полноценного destination management для local/network storage с authentication, availability checks, error parsing, alerts/logging и последними записями в admin UI.
- Код `01-271` выбран как следующий глобально однозначный task code: строки task-list заканчиваются на `01-260`, но changelog фаз `01-260` уже использует заголовки `01-261..01-270`, поэтому повторно занимать `01-261` нельзя.

## Цель

Сделать backup destination отдельным управляемым контрактом, не смешивая secret material с `backup.properties` и не выполняя host/network операции из `panel-web`.

## Декомпозиция

### A — destination model + UI/API contract

- типы `local-filesystem`, `smb-unc`, `mounted-network-filesystem`;
- migration текущего `IGUANA_BACKUP_DESTINATION_DIR`;
- SMB server/share/subpath вместо одного непрозрачного UNC string;
- auth modes без plaintext secret;
- `credential_ref` как ссылка на отдельный host-managed secret boundary;
- server-side запрет inline password/secret fields;
- автоматическая классификация local destination как `NOT_DR`;
- read-only probe steps/error-code JSON contract;
- UI card и save/load contract;
- source/unit tests;
- без host/network execution.

### B — host-side probe/auth execution

- shared request/status boundary;
- Windows/Linux host runner claim/execute;
- Local filesystem probe;
- staged SMB probe: host -> TCP 445 -> authentication -> share -> path -> read -> free space;
- optional write/delete probe отдельным explicit switch;
- safe credential resolution по `credential_ref`;
- никаких secrets в logs/status/API.

### C — history + monitoring + alerts

- destination probe history;
- последние записи и summary в admin UI;
- интеграция `backup_destination_availability` в existing monitoring/history;
- warning/critical/error semantics и free-space threshold.

### D — remote transports

Отдельным последующим slice: SFTP/SSH и S3-compatible direct transport со staging/publish/download abstraction.

## Safety / ограничения

- `panel-web` не получает Docker socket, SMB session и host credentials.
- `backup.properties` остаётся non-secret.
- API/UI никогда не возвращают password/private key/access key plaintext.
- Local fixed storage не может считаться DR только по checkbox.
- Network destination не считается подтверждённым только по сохранённому пути; host-side probe и explicit acknowledgement обязательны для финального DR gate.
- На phase A не выполнять backup, restore, network probe, credential mutation, deploy или container restart.

## Критерии phase A

- legacy `destination_path` продолжает читаться и сохраняться для существующего backup runtime;
- UNC автоматически раскладывается на SMB fields;
- новый UI различает Local / SMB / mounted network;
- credential boundary представлен только non-secret metadata + `credential_ref`;
- inline secret fields отклоняются backend model'ю;
- Local destination отображается как `NOT_DR`;
- probe contract содержит согласованные steps и stable error codes, но execution явно disabled до phase B;
- targeted Maven tests GREEN;
- `git diff --check` GREEN;
- exact changed-file set подтверждён.


## Phase B implementation slice

- shared request/status boundary: `backup-destination-probe-request.properties`, `.running`, `backup-destination-probe-status.properties`;
- panel-web только ставит non-secret snapshot в очередь и читает sanitized status; host runner выполняет probe;
- read-only по умолчанию, write/delete только через explicit `write_test`;
- Windows SMB: DNS -> TCP 445 -> auth/share -> path -> read -> free space;
- Unix SMB: `smbclient`, Kerberos current identity или credential-ref через временный mode 0600 auth file;
- credential-ref `backup-destination-main` разрешается только на host в `IGUANA_BACKUP_CREDENTIAL_BACKUP_DESTINATION_MAIN_USERNAME/PASSWORD` (+ optional DOMAIN);
- `destination_signature` предотвращает повторное использование stale probe для изменённого пути/auth;
- новое DR acknowledgement разрешается backend только после matching successful probe; legacy acknowledgement не переносится на изменённую destination;
- UI показывает queued/running/success/error, normalized error code, step и free bytes.

### Критерии phase B code acceptance

- secrets отсутствуют в backup.properties/request/status/API/logging contract;
- panel-web не получает SMB session, Docker socket или host secret;
- runner Windows/Linux claims probe request независимо от backup execution;
- default probe не пишет в destination; explicit write test создаёт уникальный временный probe-файл и удаляет его;
- source/unit tests и syntax checks GREEN;
- реальный network probe и production deploy не выполняются validate-оператором.
