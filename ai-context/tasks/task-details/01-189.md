# Задача [01-189]

## Короткое описание

Сделать историю диалога полноценной хронологией: хранить все редакции сообщений клиента и оператора и отображать служебные действия в компактном Telegram-подобном timeline.

## Требования

- отдельный append-only ledger редакций вместо единственного `original_message`;
- каждая версия хранит previous/new text, sender/actor, timestamp и связь с canonical chat_history message;
- client и operator edit используют один contract;
- в UI виден текущий текст, предыдущая версия и раскрываемая полная история изменений;
- system/lifecycle events (взял в работу, передал, закрыл, переоткрыл, отправил запрос оценки, auto-close и другие значимые действия) отображаются компактной нейтральной строкой, а не обычным message bubble;
- системная хронология сохраняет timestamp и actor, но не перегружает ленту техническими деталями.
