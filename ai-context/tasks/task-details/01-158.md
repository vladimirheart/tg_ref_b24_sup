# Задача [01-158]

## Краткое описание

Развязать автозакрытие диалога от падения follow-up задачи по `task_links`.

## Цель

Сделать так, чтобы scheduler автозакрытия завершал закрытие тикета даже при ошибке создания follow-up задачи для auto-close сценария.

## Контекст

- В логах `java-bot/bot-max/logs/bot-telegram.log` один и тот же тикет многократно логируется как auto-closed каждые 10 минут.
- Параллельно падает `AutoCloseFollowUpTaskService` с `SQLITE_CONSTRAINT_NOTNULL: task_links.user_id`, что указывает на сбой follow-up задачи уже после попытки закрыть тикет.
- С высокой вероятностью ошибка follow-up задачи происходит внутри общей транзакции scheduler-а и откатывает само закрытие диалога.

## Что сделать

- Изолировать создание follow-up задачи для auto-close в отдельную транзакцию, чтобы сбой в `task_links` не откатывал `closeTicket`.
- Зафиксировать понятный логический контракт: auto-close не зависит от follow-up task side effect.
- Проверить результат на компиляции и по затронутым тестам/синтаксису.

## Критерии готовности

- Ошибка follow-up задачи больше не мешает фактическому закрытию тикета по неактивности.
- В коде явно видно, что side effect follow-up задачи исполняется независимо от основной транзакции auto-close.

## Обязательные дополнительные условия

- По завершении задачи показать алерт через `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно не отменил это требование.
- В финальном ответе подготовить `Резюме для коммита` по формату из `ai-context/baseline/guides/tasks.md`.
- После любых file changes создать отдельный changelog-файл в `ai-context/changelog` по правилу «одно изменение = один файл» и включить в него пользовательский промт, который привёл к изменению.
