# Задача [01-277]

## Статус

🟡 В работе

## Цель

Сделать PostgreSQL единственной SQL/реляционной БД проекта. Полностью удалить поддержку и технические остатки MySQL, SQLite и H2 из живого runtime, зависимостей, migration chains, tooling и test harnesses.

## Принятый целевой контракт

- spring-panel работает только с PostgreSQL;
- java-bot и dynamic bot children работают только с PostgreSQL;
- worker/transport mode не создаёт локальный SQLite datasource;
- единственный Flyway migration chain — db/migration/postgresql;
- Maven dependency graph не содержит SQLite/MySQL/H2 drivers или dialect modules;
- tests, которым нужна SQL БД, используют PostgreSQL-compatible test contour вместо SQLite/H2;
- Redis, RabbitMQ и MinIO остаются отдельными infrastructure boundaries и не являются SQL-БД.

## План

1. S1 — runtime/dependency contract: убрать selectable MySQL/SQLite/worker DB modes, SQLite bot bootstrap и драйверы MySQL/SQLite/H2.
2. S2 — legacy runtime/import/recovery: удалить SQLite import/compaction/recovery services, properties и production/archive tooling.
3. S3 — migration chains: удалить db/migration/mysql и db/migration/sqlite, Java SQLite migrations и связанные source-contract tests.
4. S4 — tests: заменить jdbc:sqlite/jdbc:h2 fixtures PostgreSQL test harness или unit mocks.
5. S5 — current docs/UI/scripts: убрать живые ссылки на SQLite/MySQL/H2, оставив исторические changelog/task records как историю.
6. S6 — full compile/test/build, production rollout и ручная acceptance.

## Ограничения

- никаких DB migration/data mutation в cleanup-slices без отдельной необходимости;
- historical changelog/task records не переписываются как будто SQLite/MySQL никогда не существовали;
- source slices не stage/commit/push до GREEN;
- rollout выполняется отдельно после source/test checkpoint.

## S2 — legacy runtime/import/recovery cleanup

- Удаляется archive/import/recovery runtime graph SQLite: source-path properties, import/reconciliation/recovery/compaction runners и bot shard consolidation.
- Удаляется dedicated legacy SQLite compose override и staging/verification scripts.
- Удаляются dead bot database-dir/worker-env compatibility branches из live source.
- Normal application config больше не содержит legacy SQLite source paths.
- MySQL/SQLite migration chains намеренно остаются до S3; SQLite/H2 test fixtures вне удаляемого legacy tooling остаются до S4.
## S3 — migration chains cleanup

- Удалены MySQL и SQLite SQL migration chains из spring-panel.
- Удалены Java Flyway migrations package db.migration.sqlite и dedicated SQLite migration tests.
- Source-contract tests переведены на единственный canonical PostgreSQL migration chain.
- Из FlywayConfig удалён SQLite-specific schema-history remap для legacy client_phones; PostgreSQL baseline/checksum normalization сохранён.
- PostgreSQL migration chain не изменяется; DB migrations/data mutation в S3 не выполняются.
- Общие jdbc:sqlite/jdbc:h2 test fixtures остаются отдельным S4.


## S4.1 — PostgreSQL integration-test harness

- Added a reusable PostgreSQL Testcontainers harness for Spring integration tests.
- Migrated the seven integration fixtures explicitly deferred from S3 away from the removed SQLite Flyway chain and SQLite datasource paths.
- The users JdbcTemplate now exercises the same canonical PostgreSQL datasource as production configuration.
- SQLite-only test helper SQL is replaced with PostgreSQL-compatible metadata/upsert/time expressions where required.
- No production runtime, production database, queue, image, or environment mutation is performed by the runner; the only container mutation is an ephemeral PostgreSQL test container created by Maven tests.


## S4.1 continuation — PostgreSQL fixture portability and test isolation

- PostgreSQL integration contexts now use isolated temporary shared-config and storage roots instead of repository runtime paths.
- Test-only safe security/bootstrap values satisfy production-like startup guards without reading production secrets.
- Bot process control is mocked and auto-start disabled for these fixtures so integration tests do not touch tracked runtime PID files.
- SQLite numeric booleans are converted to PostgreSQL booleans and explicit identity inserts use OVERRIDING SYSTEM VALUE.
- Docker Desktop 29 compatibility remains test-only via docker-java.properties api.version=1.44.
