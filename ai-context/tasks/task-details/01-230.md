# Задача [01-230] Сверить и безопасно консолидировать изменившиеся legacy bot shard-файлы

## Короткое описание

Проверить предупреждение мигратора по shard-файлам `bot-1.db` и `bot-3.db`; переносить только доказанно отсутствующие данные и не создавать дубли.

## Цель

Закрыть последний data-specific SQLite хвост перед удалением compatibility perimeter: PostgreSQL должен содержать всю ценную историю ботов, а SQLite-источники должны остаться только архивом.

## Контекст

- В логах контролируемого запуска `01-228` мигратор предупредил о changed-state для `bot-1.db` и `bot-3.db` и не выполнил автоматический повторный импорт.
- Финальная сверка marker-полей на 2026-09-01 уже показала совпадение staged shard с marker по размеру и UTC-времени. Предупреждение нужно объяснить по журналу и доказать delta до любой записи в PostgreSQL.
- `LegacyBotShardConsolidationService` блокирует повтор по размеру и времени модификации, чтобы не продублировать записи.
- Общие critical-table counts из `panel_runtime.db` уже проверены как покрытые PostgreSQL; этот контур касается только локальных bot shard.

## Что сделать

- Снять неизменяемые копии `bot-1.db` и `bot-3.db` и зафиксировать SHA-256, размер и UTC-время.
- Сопоставить marker, журнал запуска, таблицы и стабильные идентификаторы shard-данных с PostgreSQL, определить, существует ли delta-набор.
- Если delta доказан, реализовать отдельный идемпотентный reconciliation/import path с dry-run и явным evidence ledger.
- Если delta отсутствует, зафиксировать evidence и закрыть предупреждение без повторного импорта.
- Отключить legacy auto-import в пользовательском `.env` вручную после приёмки `01-228`; не удалять источники до окончания rollback window.

## Критерии готовности

- Есть воспроизводимый dry-run и отчёт по каждому изменённому shard.
- PostgreSQL покрывает все согласованные записи без дублей.
- Evidence ledger фиксирует источник, хеш, delta и время переноса.
- После ручной приёмки `01-228` и `01-230` SQLite не участвует в runtime; `01-229` может удалить compatibility perimeter.

## Обязательные дополнительные условия

- Не выполнять destructive operations над SQLite-источниками или PostgreSQL.
- По завершении показать алерт через `./ai-context/baseline/scripts/show-completion-alert.sh`.
- В финальном ответе подготовить `Резюме для коммита`.
- После file changes создать отдельный changelog в `ai-context/changelog` с пользовательским промптом.
