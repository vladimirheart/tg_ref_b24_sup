# 01-287 — Перезапуск и выполнение команд бота

Статус: 🟣 — реализация и локальные проверки завершены, ожидается проверка пользователя. Baseline HEAD / origin/main: `31ecce7f06d5f6ed0283c0762374fa8dd797b5de`.

Промт пользователя:

```text
в настройках бота нужно не только старт\стоп кнопку, но и перезапуск. плюс нужно отображение, что действие выполняется, хотя-бы крутящийся вид
```

Существующий BotProcessService.start уже останавливает прежний процесс и ждёт готовности нового. Явная кнопка перезапуска использует тот же подтверждаемый API start и штатный signed bot-runner путь. Раздельные stop/start из браузера не нужны. Серверные права и lifecycle-протокол не меняются.

План: кнопки в списке и редакторе; spinner/текст на всё время действия; блокировка повторной команды по каналу; защита от старых GET-ответов и записи результата в другой открытый канал; восстановление управления при ошибке. Проверки JS, браузер, контракт реального одноразового probe-процесса. Рабочие боты и провайдеры не запускаются и не останавливаются.

Дополнительное сообщение пользователя в ходе работы: «продолжи».

Результат: в строке канала и редакторе добавлена кнопка «Перезапустить»; доступна при running. Запуск, остановка и перезапуск показывают spinner на нажатой кнопке и в статусе, текст действия, aria-busy/aria-live. Кнопки этого канала блокируются до подтверждения или ошибки; другой канал независим. Перерисовка списка сохраняет состояние операции. Старые GET до команды отсеиваются по версии; поздний ответ другого канала не меняет открытый редактор. Чтение статусов и завершение команды учитывают EDIT_SETTINGS_CHANNELS в существующем SettingsPermissions. HTTP/сеть/неверное подтверждение/тайм-аут снимают индикатор и показывают ошибку; автоматического повтора команды нет. Клиентский timeout 125 секунд превышает штатный runner timeout 110 секунд.

Проверки: 7 Node-тестов — GREEN; 35 Java-тестов / 4 набора — GREEN, failures/errors/skipped=0. BotProcessLifecycleContractTest запускает только локальный probe JAR без API провайдеров: повторный start меняет PID, старый процесс завершён, новый alive/ready, затем остановка и finally cleanup. Сохранены проверки signed runner client/API/ролей и UI-контракты. Изменённые тестовые классы скомпилированы javac с текущим Surefire classpath; production Java не менялась, полной Maven/package-сборки в этой задаче нет.

Первый Java-прогон выявил устаревшие fixtures: probe-канал не был active, а два теста полного runtime-contract не задавали право изменения каналов после прежнего аудита прав. Fixtures исправлены: active=true и явный WithMockUser с PAGE_SETTINGS/EDIT_SETTINGS_CHANNELS только для этих двух тестов; прежние assertions сохранены. Серверные права и редактирование рабочих пользователей не менялись. Повторный прогон зелёный.
