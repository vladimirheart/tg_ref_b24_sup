# Задача [01-244] Устранить задержки, повторную обработку worker-событий и разрывы двустороннего MAX/Telegram media-контура

## Цель

Обеспечить предсказуемую доставку текста и медиа между клиентами Telegram/MAX и панелью без дублей, потерь и многосекундных внутренних пауз.

## Контекст

- Одно событие общей PostgreSQL-очереди может быть обработано старым или конкурирующим worker-экземпляром повторно.
- MAX upload URL падает на TLS-маршруте с `PKIX path building failed`, хотя создание upload-сессии и текстовая отправка работают.
- Входящие MAX-вложения сохраняются как внешняя ссылка или имя, а не как объект управляемого MinIO-контура.
- Bot transport outbox опрашивается с базовой задержкой 1500 мс, что увеличивает end-to-end latency.

## Что сделать

- Усилить единоличную обработку UI outbox и исключить повторный AI/system side effect при конкурирующих worker-экземплярах.
- Сократить интервал публикации integration outbox до безопасного для текущей нагрузки значения.
- Добавить безопасный direct TLS fallback для выданного MAX upload URL без отключения проверки сертификатов.
- Загружать входящие MAX-медиа в объектное хранилище и передавать панели стабильный storage key с метаданными.
- Сохранить прямую ссылку/скачивание как fallback для Telegram TGS, если браузер не может отрисовать Lottie.

## Критерии готовности

- Один client event создаёт не более одного AI/system ответа.
- Текстовые события без внешней сетевой задержки доходят до integration transport менее чем за секунду.
- MAX-вложение отправляется оператором и открывается в истории после входящего сообщения клиента.
- Telegram-стикер доступен для просмотра или скачивания даже при ошибке декодирования TGS.
- Сборка и целевые тесты проходят, изменения развёрнуты в Docker-контуре.

## Результат

- Устранён конкурирующий повышенный Windows runtime, который повторно владел Telegram-токенами и обрабатывал общую PostgreSQL-очередь.
- Для каждого Telegram-канала используется собственный token source; оба runtime удерживают long polling без `409 Conflict`.
- MAX API и upload переведены на актуальный API2/TLS-контур, входящие и исходящие вложения интегрированы с MinIO/S3.
- Исправлены streaming upload и S3 availability metadata, добавлен безопасный fallback Telegram TGS.
- Внутренние outbox-интервалы сокращены до 250 мс; все текущие outbox-записи опубликованы.
- Исправлена PostgreSQL-несовместимость follow-up задач автозакрытия.
- `panel-web`, `bot-runner` и `ops-worker` развёрнуты и находятся в состоянии healthy; целевые тесты и статические проверки проходят.
