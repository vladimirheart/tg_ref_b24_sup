# Задача [01-174]

## Краткое описание

Добавить в блок синхронизации NetBox отдельное сохранение конфигурации подключения, чтобы base URL, token и related-параметры можно было сохранить без общего сохранения всей страницы настроек.

## Цель

Сделать NetBox-блок самодостаточным по UX: пользователь должен иметь возможность отдельно сохранить подключение и сразу понимать, что конфигурация зафиксирована в `settings.json`.

## Контекст

- Сейчас в блоке NetBox есть общий save страницы и ручной `sync`, но нет отдельного действия `Сохранить подключение`.
- Это создаёт неочевидный сценарий: настройки подключения уже введены, но пользователь не видит отдельного подтверждённого шага сохранения именно для NetBox.
- После предыдущей доработки ручной sync уже умеет использовать текущее состояние формы, но отдельное сохранение конфигурации всё равно нужно как самостоятельный UX-сценарий.

## Что сделать

- Добавить backend endpoint сохранения `netbox_sync` настроек без запуска sync.
- Добавить в UI NetBox отдельную кнопку сохранения конфигурации подключения рядом с ручным запуском sync.
- После успешного сохранения обновлять локальное runtime-состояние так же, как после общего save: очищать поле токена из формы и помечать token как сохранённый.

## Критерии готовности

- В блоке NetBox есть отдельная кнопка сохранения подключения.
- Нажатие этой кнопки сохраняет `base_url`, `api_token`, `enabled`, `interval_minutes` и флаг очистки токена без общего сохранения страницы.
- После успешного сохранения UI показывает сохранённое состояние токена и не требует дополнительного общего save.
- Сборка затронутого модуля проходит.
