# Задача [01-160]

## Краткое описание

Спроектировать data lifecycle и стратегию масштабируемого хранения Iguana для роста вложений и исторических данных.

## Цель

Зафиксировать целевую архитектуру хранения Iguana при росте объёма вложений, историй диалогов, telemetry и архивов, чтобы проект не деградировал по размеру БД, стоимости переносов и времени восстановления.

## Контекст

- Пользователь отдельно поднял риск разрастания данных при большом количестве вложений и попросил не просто комментарий, а оформленную техзадачу.
- В проекте уже есть правила по canonical SQLite-контурам и retention для monitoring/telemetry, но нет единой стратегии по жизненному циклу всех типов данных Iguana.
- Особый риск создают `attachments/`, long-tail история диалогов, transport-дубли у ботов, а также тяжёлые переносы проекта между машинами.
- Ранее уже были оформлены:
  - `01-140` по retention monitoring history;
  - `01-141`/`01-142` по топологии SQLite-контуров;
  - `01-159` по документации и переносимому пакету Iguana.

## Что сделать

- Зафиксировать единый design-doc по data lifecycle, storage tiers, retention, архивированию и режимам экспорта Iguana.
- Развести в целевой архитектуре:
  - business facts;
  - transport/runtime history;
  - monitoring/telemetry;
  - attachment metadata;
  - binaries вложений;
  - backup/archive слой.
- Описать storage-стратегию для вложений с абстракцией над локальным FS и object storage (`S3`/`MinIO`).
- Зафиксировать стандартные retention-политики, исключения и legal-hold сценарии.
- Описать phased rollout, чтобы команда могла внедрять изменения постепенно, без big bang миграции.

## Критерии готовности

- В репозитории есть отдельный документ со стратегией хранения и lifecycle-политикой Iguana.
- Документ описывает не только вложения, но и БД, архивы, экспорт, мониторинг роста и phased migration plan.
- Задача оформлена в `ai-context` и может использоваться как источник следующих implementation-задач.

- По завершении задачи показать алерт через `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно не отменил это требование.
