# 01-199 — DNS/TLS/public ingress probes в monitoring contour Iguana

## Статус

`🔴` -> `🟣` после завершения AI implementation wave.

## Контекст

После внедрения backup readiness остаётся следующий `P0` blind spot из roadmap `01-197`:

- DNS resolution health;
- public endpoint reachability;
- TLS certificate / expiry health;
- webhook callback availability;
- timeline и operator action surface по public ingress.

Существующий SSL monitoring закрывает только часть TLS expiry, но не даёт единого public ingress probe с DNS + HTTP + TLS в одном operator-facing контуре.

## Что нужно сделать

1. Добавить новый monitoring source для public ingress probes.
2. Ввести отдельную сущность/таблицу с конфигурацией endpoint-а:
   - `monitor_name`
   - `endpoint_url`
   - `scheme`
   - `host`
   - `port`
   - `expected_http_status`
   - `enabled`
   - runtime snapshot полей DNS/HTTP/TLS.
3. Реализовать probe-слой:
   - DNS resolve (`A/AAAA` через system resolver);
   - HTTP/HTTPS availability probe;
   - TLS cert expiry probe для `https`.
4. Собирать aggregate severity и summary:
   - `ok`
   - `warning`
   - `critical`
   - `error`
   - `disabled`
5. Писать timeline в `monitoring_check_history`.
6. Добавить scheduler с lease.
7. Добавить analytics page + JS runtime:
   - overview availability
   - table with CRUD
   - manual refresh
   - timeline modal
8. Обновить `AnalyticsController`, `analytics/index.html`, SQLite bootstrap и PostgreSQL migration.
9. Добавить тесты на:
   - DNS/HTTP healthy flow
   - TLS warning/critical aggregation через test doubles
   - analytics route rendering
   - bootstrap schema presence.

## Ожидаемый результат

В Iguana появляется отдельный operator-facing monitoring contour, который показывает:

- резолвится ли публичный ingress hostname;
- доступен ли endpoint снаружи по HTTP/HTTPS;
- жив ли TLS и сколько дней до expiry;
- как менялось состояние во времени;
- какой endpoint уже требует эскалации до того, как упадёт приём webhook-ов.
