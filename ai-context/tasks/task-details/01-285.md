# 01-285 — Первый показ списка диалогов

Статус: 🟣 — реализация и локальные проверки завершены, ожидается проверка пользователя. Baseline HEAD / локальный origin/main: `85ebb04c9d635fbdeb9ddc6ed70b55b744a637bd`.

Промт пользователя:

```text
есть мини-проблема. на странице диалога, при переходе на неё или обновлении, сначала как будто отображается дефолтное отображение, потом пустеет страница и лишь потом возвращает список как я его настроил
```

Причина: серверная выдача по умолчанию, независимые стартовые запросы списка и настроек, очистка SSR-строк при стартовом setViewTab; восстановление настроек могло также запланировать их автоматическую запись.

Решение: сервер учитывает настройки привязанной учётной записи и передаёт начальный запрос/настройки клиенту. Клиент последовательно восстанавливает настройки без сохранения, использует подходящие SSR-строки либо один ограниченный запрос. Первый показ таблицы происходит после восстановления колонок и размеров; до него виден индикатор загрузки. Ошибка допускает повторный запрос.

Проверки: MVC с сохранёнными настройками и недоступным хранилищем; нормализация ограниченного запроса; JS-гонки, отсутствие стартовой записи; реальный браузер с задержкой скриптов/настроек, переходом и обновлением, текущие фильтры/пагинация. Рабочий экземпляр и данные не затрагиваются.

Результат: сервер сразу применяет сохранённые view/page size/SLA/sort, используя существующую проверку привязки Authentication. Клиент использует переданные настройки и SLA-сигналы, повторно не запрашивает подходящую SSR-страницу и сохраняет её DOM-строки. Локальные pinned/snoozed и отличающиеся настройки вызывают один запрос уже с итоговыми фильтрами. Колонки, их порядок, ширина, режим «Только список», селекторы и пагинация восстанавливаются до показа списка. Стартовая инициализация ничего не записывает в настройки; изменения пользователя сохраняются штатно.

Первый показ имеет индикатор подготовки. Резервная загрузка настроек ограничена 3 секундами, первый запрос списка — 10 секундами; ошибка открывает явное состояние для повторного запроса. Отсутствующий основной runtime возвращает SSR через 8 секунд. Запоздалые настройки не перезаписывают уже изменённый пользователем фильтр. Удаление строк при настоящей смене фильтра сохранено: чужой результат не остаётся доступен для действий при ошибке.

Валидация: последний полный целевой Maven-прогон — 39 тестов в 6 наборах, 0 failures/errors/skipped. После финальных изменений шаблона отдельно повторён MVC-захват реального HTML — GREEN. Браузер: 6 сценариев открытия/обновления с покадровым наблюдением первого показа; текущая пагинация/поиск/SSE на 390/1440 px в светлой/тёмной теме. Артефакты: `spring-panel/target/dialogs-pagination-qa/first-paint-report.json`, `browser-report.json`, 14 снимков.
