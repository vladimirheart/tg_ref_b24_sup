# Задача [01-236] Настроить постоянный защищённый secret source для Docker bot profiles

## Цель

Исключить зависимость Docker bot profiles от временных environment-переменных при `compose recreate`, сохранив секреты вне Git и не выводя их в логи.

## Контекст

- `bot-telegram` успешно работает с временно переданным token из recovery-архива.
- `.env` и `config/shared` не содержат активного Telegram token.
- После удаления или пересоздания контейнера такой token нельзя будет восстановить автоматически.

## Что сделать

- Выбрать и внедрить единственный persistent secret source: Docker secrets, внешний secret manager или защищённый host env bootstrap.
- Поддержать безопасное чтение secret file/env в Telegram, VK и MAX profiles.
- Исключить попадание secret в Git, compose output и application logs.
- Добавить production runbook для rotation и controlled restart.

## Критерии готовности

- `docker compose ... up --force-recreate bot-telegram` работает без ручного извлечения token из recovery-архива.
- Секрет не хранится в Git и не выводится диагностическими командами.
- После restart сохраняются PostgreSQL runtime и Redis token-fingerprint lease.
