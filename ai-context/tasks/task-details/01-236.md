# Задача [01-236] Провести контролируемую ротацию паролей persistent Docker-инфраструктуры

## Цель

Заменить default-пароли PostgreSQL, RabbitMQ, Redis и MinIO в уже созданных Docker volumes, синхронизировав новые значения с приложением и клиентами без потери данных.

## Контекст

- Это не задача о токенах Telegram/MAX и не простая замена строк в `.env`.
- У четырёх компонентов есть persistent volumes. Их первоначальные учётные данные уже сохранены внутри PostgreSQL, RabbitMQ, Redis и MinIO.
- Если поменять только `.env`, сервисы и клиенты начнут использовать разные пароли, а contour станет недоступен.
- `docker-production-credential-migration-status.ps1` сейчас возвращает `migration_required` именно по этим четырём компонентам.

## Что сделать

- Сгенерировать новые уникальные значения вне Git и подготовить dry-run/rehearsal.
- Для каждого компонента изменить сохранённую credential в самом сервисе, затем обновить защищённый source для всех его клиентов.
- Пересоздать только зависимые роли в контролируемом порядке, выполнить health/auth probes и иметь rollback-план до начала каждого шага.
- Исключить секреты из Git, compose output и application logs; обновить runbook с точной последовательностью.

## Критерии готовности

- Status-check больше не возвращает `migration_required` для PostgreSQL, RabbitMQ, Redis и MinIO.
- После ротации все backend roles, bot-runner, migrations и storage probes проходят readiness без default-паролей.
- Данные в volumes сохраняются, а секреты не хранятся в Git и не выводятся диагностическими командами.
