# Задача [01-163]

## Краткое описание

Починить запуск `spring-panel` после нового Flyway checksum mismatch для baseline `V1`.

## Цель

Вернуть стабильный запуск `spring-panel` в Windows/runtime-сценарии после того, как локальный checksum `V1__baseline_schema.sql` снова изменился, а текущая логика в `FlywayConfig` не перехватывает этот случай до `flyway.migrate()`.

## Контекст

- По логу запуска от `2026-07-31`:
  - приложение доходит до Flyway;
  - затем падает на `FlywayValidateException`;
  - mismatch для migration version `1`:
    - applied checksum: `823443258`
    - resolved locally: `1965522692`
- Текущий `FlywayConfig` уже содержит legacy-нормализацию history и попытку `repair()`, но:
  - всё ещё использует жёсткий `BASELINE_FALLBACK_CHECKSUM=823443258`;
  - может переписывать schema history этим устаревшим checksum до старта migrate;
  - из-за этого новый baseline checksum не чинится автоматически.
- Нужно сохранить compatibility-логику, но убрать привязку к одному устаревшему checksum baseline-скрипта.

## Что сделать

- Разобрать текущую логику `FlywayConfig` вокруг baseline checksum normalization.
- Убрать зависимость от устаревшего hardcoded baseline checksum как источника истины.
- Сделать startup recovery устойчивым:
  - если baseline checksum в БД не совпадает с текущим локальным скриптом;
  - если текущий локальный checksum не удаётся заранее безопасно вычислить через `flyway.info()`.
- Подтвердить исправление реальным запуском `spring-panel` в текущем workspace.

## Критерии готовности

- `spring-panel` больше не падает на `FlywayValidateException` только из-за checksum mismatch для `V1`.
- `run-windows`/`spring-boot:run` сценарий стартует успешно на текущей runtime БД.
- Исправление не ломает уже существующую legacy-нормализацию history для прежних случаев.

## Результат выполнения

- В `FlywayConfig` убрана зависимость от устаревшего hardcoded baseline checksum как fallback-источника истины.
- Перед `flyway.migrate()` добавлен устойчивый repair-путь: если в history уже есть успешный baseline `V1__baseline_schema.sql`, выполняется `flyway.repair()` для выравнивания mutable checksum.
- На текущем workspace подтверждено:
  - `spring-panel\\mvnw.cmd -q -DskipTests compile` проходит успешно;
  - `run-windows.bat` больше не падает на checksum mismatch для `V1`;
  - `spring-panel` доходит до `Started PanelApplication`;
  - в `panel_runtime.db` checksum для `version=1` обновлён до `1965522692`.
