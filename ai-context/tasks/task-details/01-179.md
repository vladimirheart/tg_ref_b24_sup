# Задача [01-179]

## Краткое описание

Сделать синхронизацию NetBox устойчивой к локальным ошибкам отдельных `site`, чтобы `HTTP 500` по `image-attachments` или другой сбой на одном объекте не обрывал весь прогон.

## Цель

Перевести sync в режим частичной деградации: проблемный объект даёт warning, но остальные сайты продолжают импортироваться.

## Контекст

- В логе панели зафиксировано падение всего sync на `NetBox HTTP 500` для `.../api/extras/image-attachments/?object_id=160`.
- Текущая защита уже пропускает неподдерживаемые файлы на этапе `photoStorageService.store(...)`, но не перехватывает ошибки API до входа в `mergeSitePhotos(...)`.
- `buildFullOverwritePayload(...)` и `upsertPassports(...)` вызывают `buildPassportPayload(...)` без site-level fallback, поэтому исключение по одному объекту поднимается до `syncNow(...)` и завершает весь прогон ошибкой.

## Что сделать

- Для фото NetBox добавить мягкий fallback: если `fetchSiteImages(...)` падает, импортировать объект без фото и записывать warning.
- На уровне циклов по `site` защитить sync от локального сбоя одного объекта: логировать предупреждение, пропускать проблемный объект и продолжать обработку остальных.
- Прокинуть собранные warnings в итоговый статус sync.

## Критерии готовности

- `HTTP 500` по image attachments одного сайта не валит весь sync.
- Остальные сайты продолжают импортироваться.
- В итоговом статусе sync и логах есть понятный warning с идентификатором site и причиной пропуска/частичной деградации.
- Сборка проходит.
