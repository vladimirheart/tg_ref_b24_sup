# Задача 01-307

## Запрос пользователя

> карточка задачи выглядит очень не красиво, шумно и крайне неудобно для получения информации о ней и редактировании - начиная от состава участников, о статусов. плюс участники без аватарок и отображаются их логины. да и саму карточку сотрудника, чтобы понять кто этот сотрудник, нельзя открыть (это касается и диалогов)

## Цель

Упростить просмотр и редактирование задачи: основные сведения видны сразу, второстепенные раскрываются по запросу. Показывать сотрудников по имени и фотографии; открывать рабочий профиль без потери контекста задачи или диалога.

## Критерии

- Отдельные основные сведения, состав команды, свернутые проекты/теги, история и управление доступом.
- Поиск и изменение ответственного, соисполнителей и наблюдателей сохраняют native values/FormData и серверный scope.
- Имена и фотографии либо инициалы в задачах и участниках диалогов.
- Read-only профиль доступен действующему сотруднику панели без административного PAGE_USERS; приватные данные и настройки безопасности исключены.
- Статус и состав сохраняются существующим API; ошибки сохраняют введенные изменения.
- Проверки backend доступа/проекции, реального Thymeleaf и браузера в обеих темах и узких viewport.

## Границы

Существующие правила назначения и допуска к задачам, проектам и обращениям сохраняются. Endpoint профиля не является списком кандидатов и не выдает права назначения. Миграции и изменение рабочих данных не требуются.

Работа выполняется в detached worktree от cb6484b1fc60dcd5fc211da576f44538d78f3340. После проверок переносится в исходный checkout без staging/commit/push/deploy.

## Результат и проверки

- Карточка расширена до 1080 px; основные сведения и комментарии отделены от параметров. Проекты, теги, история и управление доступом свернуты. На узком экране одна колонка, статус и состав расположены перед комментариями.
- Один сотрудник отображается один раз с фотографией/инициалами и всеми его ролями. Изменение состава выполняется общим EmployeePicker с прежними native values/FormData. Исторический ответственный не теряется при открытии задачи; дополнительные исторические options не переходят в создание новой задачи.
- Поддержаны изменение статуса, явное сохранение, индикатор изменений, блокировка повторного сохранения, сохранение полей при ошибке, защита черновика комментария. Read-only пользователю недоступно редактирование полей.
- Рабочий профиль открывается поверх текущего интерфейса по имени/аватару. Показаны имя, отдел и логин, поддержаны Escape, возврат фокуса, повтор при ошибке и fallback при недоступном фото.
- Ссылки работают у участников и ответственного в карточке/списке диалогов; display name не используется вместо известного username. Кандидаты назначения по-прежнему берутся из прежних scoped/native списков.
- Endpoint `/api/panel-users/profile?username=…` использует SharedSystemAccessService и минимальную SQL-проекцию. Неоднозначный username дает 404. Пароли, контакты, дата рождения, административные роли и права не возвращаются. Фото разрешается штатным PanelUserPhotoService, включая старые пути и поиск по ID.
- Maven main compile и SCSS generate-resources GREEN. 17 Java tests / 6 suites GREEN, включая API, method access, минимальную JDBC-проекцию и реальный Thymeleaf render. Проверки JDBC используют mock adapter; настоящий PostgreSQL не запускался, Docker engine недоступен.
- 2 существующих Node suites GREEN: query details и quick actions (16 URL call sites, 11 выполненных fetches). Обновлены только точные cache-version assertions для измененных assets; остальные проверки сохранены.
- 6 браузерных сценариев: 320/768/1440 px, light/dark, реальные task HTML и production scripts/styles, fixture API. Проверены изменение состава с Enter, сохранение/повтор после ошибки, reopening, черновик комментария, read-only, повторное открытие профиля при редактировании, ошибки/повтор профиля, участники и первоначальный/измененный ответственный диалога. Ошибок JS, отсутствующих JS/CSS и горизонтального переполнения нет. Снимки и отчет: `spring-panel/target/task-card-qa/`.
- JavaScript syntax и `git diff --check` GREEN. Изменения перенесены из проверенного worktree без staging/commit/push/deploy/миграций и изменения рабочих данных.

Статус 🟣: требуется ручная проверка. Запущенная панель не обновлялась. Штатный completion-alert script использует macOS osascript и неприменим на этой Windows-машине.
