# Задача [01-272]

## Короткое описание

Провести системный UI/UX-проход с упором на единые переиспользуемые паттерны и убрать текстовый helper/disclosure «Подробнее» там, где статическое пояснение можно открыть компактной `i`-иконкой.

## Контекст

- Пользователь зафиксировал глобальное правило: одинаковая пользовательская функция должна иметь одинаковый UI/interaction pattern; локальные одноразовые решения не должны раздувать runtime-файлы.
- Статический help/why/how-it-works текст предпочтительно скрывать за компактным `i`, но operational status, ошибки и предупреждения должны оставаться видимыми.
- Первый read-only audit нашёл runtime-текст «Подробнее» в `content-disclosure.js`, `passport-detail-equipment-runtime.js` и `settings-partner-contacts-runtime.js`.
- R1 частично изменил эти три JS и остановился на CRLF-sensitive SCSS marker; R2 заблокировался до apply, потому что его known-state fingerprint не распознал фактический R1 partial state.
- R3.3 продолжает работу только вперёд из подтверждённого exact partial state без `reset`, `clean` или broad `checkout`; R3 и R3.1 остановились до первой записи на Maven preflight, R3.2 — до первой записи на неоднозначном JS marker после полностью GREEN Maven preflight.

## Первый implementation slice

- generic `content-disclosure` становится `i`-only: preview-копия убирается, полный helper body находится в общем info panel;
- page-header и generic disclosure используют одну JS-функцию open/close interaction;
- DOM mount order сначала закрепляет wrapper в исходном parent, затем переносит helper body в panel, исключая `HierarchyRequestError`;
- helper body явно остаётся видимым внутри открытого panel (`element.hidden = false`);
- карточка оборудования использует компактный `bi-info-circle` в native `<details>`;
- карточка контакта партнёра сохраняет whole-card action и заменяет текстовый affordance на `bi-info-circle`;
- obsolete textual disclosure SCSS удаляется, equipment summary получает минимальный native-details reset;
- source contract запрещает повторное появление «Подробнее» в application runtime JS/templates, не затрагивая changelog/history/test/vendor.

## Ограничения

- backend/API semantics не меняются;
- runtime/deploy/container/DB/queue mutations не входят в этот slice;
- generated CSS должен контролироваться после Maven: unrelated Sass output возвращается к HEAD, сохраняется только минимальный counterpart текущего UI change;
- task остаётся `🟡` до ручной UI-приёмки пользователя;
- AI не переводит задачу в `🟢` самостоятельно.

## Критерии текущего slice

- exact pre-state: HEAD/origin main `000c6bc804e947a12028a1e6530b47e1276234ca`, dirty scope ровно из трёх подтверждённых R1 JS;
- `node --check` GREEN для изменённых application JS;
- `UiInfoDisclosureSourceContractTest` GREEN;
- `git diff --check` GREEN;
- отсутствует runtime UI string «Подробнее» в application JS/templates;
- no stage/commit/push;
- после apply требуется ручная UI-проверка перед дальнейшим batching/commit.

## Статус

🟡 В работе. Первый info-disclosure slice подготовлен как continuation R3.3; дальнейшие UI-комментарии пользователя продолжают собираться в эту же задачу, если не образуют отдельный функциональный scope.

## Sidebar + dialogs hygiene — S1

- Sidebar: уплотнение вертикального ритма, полное удаление пользовательского reorder/drag&drop, действия аккаунта открываются кликом по карточке пользователя вместо отдельной звёздочки.
- Для пользователей с PAGE_SETTINGS добавлен переход из account-menu прямо в редактирование собственного профиля через существующий authorized users editor (`editSelf=1`), без расширения backend permissions.
- Dialogs: удалён отдельный user-facing compact toggle; сохраняются только `Только список` / `Полная страница`.
- Исправлен конфликт старого route-open fix: открытие диалога больше не сбрасывает сохранённый `Только список` и не пишет `list-only-mode=0`.
- Checkbox/select column скрыта по умолчанию, но остаётся доступной через настройку колонок.
- Actions уплотнены: открыть — icon action, secondary menu расположен вертикально; основные текстовые колонки ограничены по ширине и получают full-text title.
- Шумный префикс `Уточнение после ответов на вопросы...` удаляется из Problem, сохраняя содержательный остаток.
- SLA pie и client WoW/MoM/YoY намеренно оставлены следующему data-backed slice.

## Dialogs corrective — S2 R3

- Ручная preview-приёмка S1 выявила client-side init regression: после удаления compact toggle в `dialogs.js` остался dead `if (dialogCompactToggle)`, вызывавший `ReferenceError` до binding/list-column/SLA initialization.
- Dead reference удалён; source-contract теперь явно запрещает любое возвращение `dialogCompactToggle`.
- Existing browser preferences получают одноразовую schema migration: select/checkbox колонка выключается, `Действия` перемещаются первым столбцом, остальные пользовательские visibility/order сохраняются.
- Problem sanitizer удаляет фразу `Уточнение после ответов на вопрос/вопросы` независимо от позиции в тексте и сохраняет остальное содержимое.
- SLA list cell становится двухстрочным: сверху состояние, снизу срок; для закрытых обращений используется `resolvedAt`, чтобы показывать факт просрочки или закрытие в SLA.
- Open action остаётся icon-only, но получает явный transparent background; action dropdown у первого столбца открывается вправо.
- Sidebar из принятого S1 не меняется.

## Dialogs density — S3

- После ручной preview-приёмки S2 пользователь принял логику sidebar/dialogs и запросил дополнительное уплотнение списка.
- Высота строки уменьшается не только через cell padding: уменьшаются две вертикальные action-кнопки, client/responsible avatars и высота channel/business pills.
- Колонки `Клиент`, `Статус`, `Бизнес` дополнительно сужаются; существующий ellipsis/title pattern сохраняет доступ к полному значению.
- `Действия` остаются первым столбцом, но видимый текст заголовка скрывается; скрытый `Действия` остаётся в DOM, поэтому выбор колонок продолжает показывать корректное название.
- Sidebar и dialogs state/SLA semantics в этом slice не меняются.

## Client period comparisons — S4

- Sidebar и dialogs после S3 визуально приняты пользователем; этот slice их поведение не меняет.
- В карточку клиента добавляется компактная динамика количества обращений WoW / MoM / YoY.
- Сравниваются period-to-date интервалы: текущая неделя/месяц/год против эквивалентного отрезка предыдущего периода.
- Обращения дедуплицируются по `ticket_id`, поэтому несколько строк `messages` одного обращения не раздувают тренды.
- «Тип обращения» использует уже существующую категорию/тему (`category`); показываются до трёх наиболее заметных типов как `сейчас / предыдущий период`.
- Рост/снижение отображается как направление, без семантики «хорошо/плохо».
- Backend API и схема БД не меняются; расчёт выполняется из уже загруженных данных карточки клиента.
