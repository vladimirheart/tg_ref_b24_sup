# Задача [01-175]

## Краткое описание

Устранить сохранение подсказок UI в поле `api_token` NetBox и добавить защиту, чтобы в sync больше не уходили placeholder/hint значения вместо реального токена.

## Цель

Сделать сохранение и использование NetBox API token устойчивыми: битые или текстовые подсказки не должны сохраняться как секрет и не должны доходить до HTTP-запроса в виде `Authorization: Token ...`.

## Контекст

- В `config/shared/settings.json` обнаружен сохранённый `netbox_sync.api_token`, совпадающий по смыслу с UI-подсказкой `Укажите API token NetBox`, но в mojibake-виде.
- Из-за этого ручной sync падает в `HttpRequestBuilderImpl.header(...)` с ошибкой `invalid header value`.
- Текущая валидация NetBox settings проверяет только непустое значение токена, поэтому подсказки и другой текстовый мусор проходят слишком далеко.

## Что сделать

- Добавить нормализацию API token в `NetBoxSyncSettingsService`, чтобы placeholder/hint строки не считались сохранённым токеном.
- Усилить валидацию перед запуском sync, чтобы невалидный token отбрасывался с понятной ошибкой уровня продукта.
- Исправить frontend runtime NetBox, чтобы поле token явно синхронизировалось с состоянием и очищалось после сохранения.
- Добавить тесты на нормализацию и сохранение NetBox token.

## Критерии готовности

- Значение вида `Укажите API token NetBox` или его битая версия не сохраняется как рабочий token.
- Ручной sync больше не падает с `invalid header value`, а при невалидном token возвращает понятную ошибку.
- После успешного сохранения поле token очищается и UI остаётся в консистентном состоянии.
- Сборка и целевые тесты проходят.
