# Задача [01-167]

## Краткое описание

Починить автозапуск bot runtime после падения Spring-контекста на `AutoCloseFollowUpTaskService`.

## Цель

Вернуть рабочий автозапуск ботов, чтобы sidebar runtime и мониторинг показывали реальные `running`-статусы, а активные каналы после старта `spring-panel` действительно поднимали свои bot-процессы.

## Контекст

- Пользователь сообщил, что в sidebar runtime все боты отображаются как `stopped`, и это соответствует реальности: боты действительно не работают.
- В проекте уже есть `BotAutoStartService`, который на `ApplicationReadyEvent` пытается стартовать все активные каналы через `BotProcessService`.
- По свежему `spring-panel.log` за 2026-08-03 автозапуск запускается, но каждый бот падает во время старта с сообщением Maven runtime.
- По `support-bot-telegram-3-process.log` причина падения — `UnsatisfiedDependencyException` в bot runtime: Spring не может создать bean `AutoCloseFollowUpTaskService`, потому что ищет default constructor.
- В `AutoCloseFollowUpTaskService` есть два конструктора, и без явного указания Spring не может однозначно выбрать конструктор для DI.

## Что сделать

- Исправить wiring `AutoCloseFollowUpTaskService`, чтобы Spring однозначно использовал runtime-конструктор с `PlatformTransactionManager`.
- Сохранить тестовый конструктор/возможность unit-тестирования без поднятия полного Spring-контекста.
- Прогнать точечную проверку по `bot-core`, подтверждающую, что сервис снова создаётся и автозапуск ботов не ломается на этом месте.

## Критерии готовности

- `AutoCloseFollowUpTaskService` больше не валит Spring-контекст bot runtime на старте.
- Активные боты перестают падать на `No default constructor found` при автозапуске.
- Есть хотя бы одна локальная проверка/тест, подтверждающая исправление или отсутствие ошибки компоновки.

## Обязательные дополнительные условия

- По завершении задачи показать алерт через `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно не отменил это требование.
- В финальном ответе подготовить `Резюме для коммита` по формату из `ai-context/baseline/guides/tasks.md`.
- После любых file changes создать отдельный changelog-файл в `ai-context/changelog` по правилу «одно изменение = один файл» и включить в него пользовательский промпт, который привёл к изменению.
