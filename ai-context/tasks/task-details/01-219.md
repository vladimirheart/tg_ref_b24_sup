# Задача [01-219] Восстановить production bot launcher в panel contour: упаковать prebuilt bot jars в образ и вернуть ручной запуск каналов

## Краткое описание

После перевыкладки production contour ручной запуск ботов из панели перестал работать: `APP_BOT_LAUNCH_MODE=jar` остался включённым, но в образ `iguana-panel:local` не попали исполняемые jar-файлы модулей `bot-telegram`, `bot-vk` и `bot-max`.

## Почему это важно

- На 28 августа 2026 года `panel-web` действительно стартует child bot-процессы через `jar`-launcher.
- Внутри контейнера есть только JRE; `javac` отсутствует, поэтому fallback `auto -> maven` для production неработоспособен.
- Из-за этого любая попытка ручного запуска из панели завершается ошибкой `Не найден собранный jar для модуля ...`.

## Что нужно сделать

1. Обновить `docker/panel.Dockerfile`, чтобы он собирал `bot-telegram`, `bot-vk` и `bot-max` на build stage и складывал готовые runtime jars в predictable directory.
2. Закрепить explicit runtime contract через `app.bots.executable-jars`, чтобы panel не зависела от случайного `target` scan внутри контейнера.
3. Пересобрать `iguana-panel:local` и перевыкатить `panel-web`/`ops-worker`.
4. Проверить, что внутри контейнера появились `dist/bot-telegram-runtime.jar`, `dist/bot-vk-runtime.jar`, `dist/bot-max-runtime.jar`, а ручной запуск больше не падает на missing jar.

## Критерии готовности

- `panel-web` видит explicit bot jar contract в `app.bots.executable-jars`.
- В runtime image присутствуют все три bot runtime jar.
- Ручной запуск Telegram/VK/MAX канала из панели больше не падает с ошибкой `Не найден собранный jar`.
- `BotRuntimeContractServiceTest` и `BotProcessServiceTest` остаются зелёными.

## Текущий результат на 28 августа 2026

- `docker/panel.Dockerfile` обновлён: теперь образ панели собирает `bot-telegram`, `bot-vk` и `bot-max` на отдельном build stage.
- `spring-panel` получил явный env-driven contract для `app.bots.executable-jars`, а `docker-compose.production-contour.yml` прокидывает пути `dist/bot-telegram-runtime.jar`, `dist/bot-vk-runtime.jar` и `dist/bot-max-runtime.jar`.
- Адресные тесты `BotRuntimeContractServiceTest` и `BotProcessServiceTest` прошли успешно.
- `iguana-panel:local` пересобран, `ops-worker` и `panel-web` перевыкатены.
- В живом `panel-web` подтверждены:
  - `APP_BOT_LAUNCH_MODE=jar`
  - `APP_BOT_EXECUTABLE_JAR_TELEGRAM=dist/bot-telegram-runtime.jar`
  - `APP_BOT_EXECUTABLE_JAR_VK=dist/bot-vk-runtime.jar`
  - `APP_BOT_EXECUTABLE_JAR_MAX=dist/bot-max-runtime.jar`
- В `/opt/iguana/java-bot/dist/` внутри контейнера лежат все три runtime jar.

## Что остаётся проверить вручную

- Нажать ручной запуск Telegram/VK/MAX канала из панели под авторизованной сессией.
- Убедиться, что вместо ошибки про missing jar бот переходит в `running` и пишет обычный startup log.
