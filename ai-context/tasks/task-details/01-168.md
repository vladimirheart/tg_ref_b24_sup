# Задача [01-168]

## Краткое описание

Стабилизировать сохранение оценок диалога и добавить настраиваемый сброс question-flow при молчании клиента после первого сообщения бота.

## Цель

Сделать контур post-close feedback и pre-ticket question-flow надёжным и управляемым:

- оценка клиента после закрытия диалога должна стабильно сохраняться и отображаться в списке диалогов;
- отсутствие ответа клиента на первый вопрос/первое сообщение бота должно приводить к автоматическому закрытию незавершённой сессии без ручной чистки runtime;
- таймаут и текст закрытия должны настраиваться на уровне активного шаблона вопросов и одинаково работать в Telegram, MAX и VK.

## Контекст

- Пользователь сообщил, что у нового бота `тостов` после закрытия диалога и отправки оценки оценка не отображается в списке диалогов.
- Проверка `spring-panel/panel_runtime.db` показала, что по каналу `id=3` есть `pending_feedback_requests`, но по соответствующему `ticket_id` нет записи в `feedbacks`.
- В `logs/support-bot-telegram-3-process.log` уже есть ошибки `SQLITE_BUSY_SNAPSHOT` на обновлении `pending_feedback_requests` внутри `EngagementTasks.dispatchPendingFeedbackRequests()`, что создаёт риск отката feedback-сценария на SQLite.
- В текущем runtime question-flow живёт в in-memory `ConversationSession` для Telegram/MAX/VK и не имеет отдельной политики автоматического завершения, если клиент начал сценарий, но не ответил на первый вопрос.

## Что сделать

- Развести сохранение feedback и обновление `pending_feedback_requests`, чтобы блокировка SQLite на служебной записи не откатывала саму клиентскую оценку.
- Устранить или заметно снизить вероятность `SQLITE_BUSY_SNAPSHOT` в scheduled dispatch feedback-запросов.
- Добавить в модель шаблона вопросов настройки:
  - таймаут ожидания первого ответа клиента в минутах;
  - сообщение клиенту при автоматическом закрытии незавершённой question-flow сессии.
- Поддержать эти настройки в sanitization/serialization `bot_settings`, settings UI и runtime всех каналов.
- Добавить sweep inactive question sessions в Telegram/MAX/VK с единым поведением: если после первого сообщения бота не было ни одного клиентского ответа/реакции в пределах таймаута, сессия сбрасывается и клиент получает настроенное сообщение.

## Критерии готовности

- Оценка, отправленная клиентом после закрытия диалога, сохраняется в `feedbacks` и отображается в списке диалогов без дополнительных ручных действий.
- Scheduled feedback dispatch больше не валится на типовом обновлении `pending_feedback_requests` из-за длинной транзакции вокруг network send.
- В редакторе шаблонов вопросов можно настроить таймаут первого ответа и текст автоматического закрытия.
- Telegram/MAX/VK runtime автоматически очищают брошенные pre-ticket question-flow сессии по этим настройкам.
- Есть локальные проверки/тесты на обновлённый feedback/question-flow контур.
