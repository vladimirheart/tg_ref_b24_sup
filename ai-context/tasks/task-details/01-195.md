# Задача [01-195]

## Короткое описание

Усилить надежность ingress/egress интеграций и внутреннего API.

## Цель

Довести контракт обмена с внешними системами и внутренним bot API до production-уровня: сигнатуры, идемпотентность, retries, delivery visibility, dead-letter и повторная обработка.

## Контекст

- В проекте уже есть RabbitMQ-transport, internal bot API и прикладной integration runtime.
- Следующий production шаг — убрать слабые места вокруг входящих webhook, исходящих отправок, таймаутов, повторов и деградации провайдеров.

## Что сделать

- Формализовать требования к inbound webhook/API auth и idempotency.
- Усилить правила retries, timeout budget и dead-letter/replay для исходящих событий.
- Зафиксировать диагностический и операторский контур для failed delivery.

## Критерии готовности

- Контур внешних интеграций описан и закрывает базовые production failure modes.
- Для ключевых путей есть явный договор по auth, retry и replay.

## Обязательные дополнительные условия

- По завершении задачи показать alert через `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно не отменил это требование.
- В финальном ответе подготовить `Резюме для коммита` по формату из `ai-context/baseline/guides/tasks.md`.
- После любых file changes создать отдельный changelog-файл в `ai-context/changelog` и включить в него пользовательский промпт, который привел к изменению.
