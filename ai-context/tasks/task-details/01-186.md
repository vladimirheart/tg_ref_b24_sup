# Задача [01-186]

## Короткое описание

Закрыть дефекты, обнаруженные повторным AI live-smoke после восстановления RabbitMQ ingestion: solution memory должна использовать операторский текст без генеративной обвязки, успешная внешняя отправка reply не должна превращаться в ложный HTTP 500 при локальном логировании, а PostgreSQL должен иметь runtime-таблицу dialog_action_audit.

## Фактический smoke 2026-08-24

После v45 новое обращение дошло до canonical panel runtime и AI suggestion path. Выявлены три отдельных дефекта:

1. сохранённый в AI Ops solution `тестовый ответ оператора` показывался как сгенерированный шаблон `Подсказка на основе источника ... / Коротко / Что сделать / ...`;
2. после редактирования текста и отправки сообщение реально доставлялось клиенту, но `/api/dialogs/{ticket}/reply` возвращал внутреннюю ошибку, потому что `chat_history.timestamp TIMESTAMPTZ` получал VARCHAR;
3. `DialogAuditService` постоянно логировал `relation dialog_action_audit does not exist`, потому что PostgreSQL migration для этой runtime-таблицы отсутствовала.

## Реализация v46

- memory candidate использует только `ai_agent_solution_memory.solution_text`; derived knowledge больше не может подменить операторский текст кандидата;
- operator suggestion для source=memory возвращает exact solution text без source-prefix, deterministic template и LLM composer;
- разрешённый auto-reply для source=memory также отправляет exact solution text из AI Ops;
- knowledge/history/tasks сохраняют существующий compose flow;
- `DialogReplyTargetService` bind-ит `chat_history.timestamp` и `ticket_active.last_seen` как `OffsetDateTime`, включая media path;
- PostgreSQL V34 создаёт `dialog_action_audit` и индексы для ticket/action/result и created_at;
- добавлены regression tests для exact-text memory и PostgreSQL temporal binding.

## Ручная проверка

1. Перезапустить panel и убедиться, что Flyway применил V34.
2. На том же test memory получить suggestion ровно `тестовый ответ оператора` без дополнительной обвязки.
3. Отредактировать suggestion в поле оператора и отправить: UI должен вернуть success, сообщение должно появиться один раз.
4. В логе не должно быть `timestamp ... character varying` для chat_history/ticket_active.
5. В логе не должно быть повторяющегося `relation dialog_action_audit does not exist`.
6. При explicit auto_reply_allowed проверить, что автоматический ответ клиенту равен сохранённому solution text.
