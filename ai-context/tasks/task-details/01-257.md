# Задача [01-257] Добавить общее время в статистику клиента и восстановить варианты статуса

## Контекст

После rollout 01-256 карточка клиента стала компактнее. Пользователь попросил:

- показать в блоке «Статистика» общее затраченное время по обращениям, уже используемое в общем списке клиентов;
- исправить пустой список при изменении статуса клиента.

## Что сделать

- Переиспользовать существующий ClientsService.loadTotalMinutes(userId) и formatTimeDuration(...), не вводя вторую формулу времени.
- Расширить ClientProfileStats полями totalMinutes и formattedTime.
- Добавить KPI «Затрачено времени» в блок «Статистика».
- Сохранить компактный layout: 5 KPI в desktop-grid и responsive fallback на узких экранах.
- Для status dropdown строить эффективный список из:
  - settings.json/client_statuses;
  - ключей client_status_colors;
  - уже используемых значений из client_statuses table;
  - исторических messages.client_status;
  - текущего статуса клиента.
- Если эффективный список всё равно пуст, показывать явный пункт «Статусы не настроены».
- Не менять API сохранения статуса клиента.
- Обновить app.css cache-buster.
- Generated CSS напрямую не редактировать.

## Критерии готовности

- В статистике карточки клиента видно то же общее затраченное время, что рассчитывается для общего списка клиентов.
- Значение времени использует существующую формулу first operator response -> resolved_at только для resolved обращений.
- Dropdown статуса не теряет настроенные, ранее использованные и текущий статус.
- При полном отсутствии вариантов UI объясняет, что статусы не настроены.
- Сохранение/снятие статуса продолжает работать через существующий endpoint.
- Source-contract tests, node --check, git diff --check и isolated SCSS compile проходят.
