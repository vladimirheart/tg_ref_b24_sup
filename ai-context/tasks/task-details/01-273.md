## Goal

Make every Dialogs list column independently resizable and persist the chosen widths per authenticated user.

## Scope correction R8

- R2/R3 targeted the Settings overview grid. Manual review showed the actual target is the table on the Dialogs page.
- The wrong Settings implementation was withdrawn before this continuation.
- R7 started the correct Dialogs implementation but stopped on a CRLF-sensitive marker in dialogs.js after writing only the preference/service/cache-bust subset. R8 resumes from that exact five-file partial state with line-ending-neutral source edits.
- The Dialogs shell already contained dormant resize code, but headers did not opt in. R8 activates a divider for every data-column-key header and uses server-backed UI preferences instead of the old shared localStorage width key.

## Behavior

- Every Dialogs table column has its own right-edge divider. Dragging one divider changes only that column; other visible widths are frozen.
- The table may grow horizontally inside the existing responsive scroll container.
- Widths are persisted as dialogsColumnWidths through /profile/ui-preferences and are isolated by authenticated username.
- Reload, Ctrl+F5 and re-login preserve the saved widths for the same user. A different user gets their own values/defaults.
- Keyboard Left/Right on a focused divider changes the selected column by 8px.
- Column visibility/order controls remain unchanged.
- No DB/schema migration.
