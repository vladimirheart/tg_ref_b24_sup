# Задача [01-156]

## Короткое описание

Сохранять стартовый текст клиента в новое обращение при запуске question-flow, чтобы исходное сообщение не терялось до ответа на последний вопрос.

## Цель

Убрать сценарий, в котором клиент пишет содержательное первое сообщение после закрытого предыдущего обращения, но этот текст не попадает ни в историю, ни в итоговое поле проблемы новой заявки, пока не завершён весь вопросник.

## Контекст

- Сейчас при старте нового обращения через question-flow боты сначала открывают сессию вопросов, а само стартовое текстовое сообщение клиента не сохраняется как часть будущего обращения.
- В результате большой исходный текст клиента может потеряться с точки зрения финальной заявки, если пользователь не дублирует его на последнем шаге `Опишите проблему`.
- В Telegram, MAX и VK используются очень похожие runtime-потоки conversation session, поэтому исправление важно держать консистентным между каналами.
- Пользователь отдельно уточнил, что перенос стартового текста нужен именно для нового обращения с учётом закрытого предыдущего диалога.

## Что сделать

- Ввести общий способ объединения стартового текста клиента с ответом на финальный вопрос `problem`.
- При старте новой question-flow сессии из первого клиентского текста сохранять этот текст как bootstrap-сообщение новой заявки.
- При заполнении последнего вопроса подмешивать стартовый текст в итоговое значение `problem`, избегая дублирования.
- Сохранять bootstrap-сообщение и в историю нового тикета после его фактического создания.
- Применить поведение консистентно для Telegram, MAX и VK.

## Критерии готовности

- Если клиент начинает новое обращение большим текстом, этот текст не теряется после question-flow.
- В итоговой заявке поле проблемы содержит и стартовый текст, и финальное уточнение клиента.
- История нового обращения включает исходное стартовое сообщение клиента.
- Поведение не затрагивает активные открытые диалоги и не смешивает сообщения со старым закрытым тикетом.

## Ограничения и риски

- Не дублировать стартовый текст, если клиент повторил его на финальном шаге почти дословно.
- Не переносить команды вроде `/start` как содержимое проблемы.
- Не ломать уже работающую маршрутизацию вопросов, `step back`, reuse prompt и активные диалоги.
