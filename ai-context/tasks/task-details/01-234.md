# Задача [01-234] Перевести production bot runtime на обязательный PostgreSQL datasource

## Короткое описание

Убрать SQLite worker fallback из launcher и Docker-профилей production-ботов.

## Цель

Telegram, VK и MAX используют PostgreSQL как единственный runtime datasource независимо от RabbitMQ transport mode.

## Контекст

- `bot-core` уже поддерживает `APP_DB_MODE=postgresql` и `SPRING_DATASOURCE_*`.
- Launcher ошибочно выбирал `APP_DB_MODE=worker` при RabbitMQ и создавал временный SQLite datasource.
- RabbitMQ предназначен для transport-сообщений, а не замены канонического storage.

## Что сделать

- Передавать PostgreSQL contract всем ботам, включая RabbitMQ runtime.
- Исправить Docker profiles Telegram/VK/MAX на PostgreSQL datasource.
- Проверить compose и bot contract tests, затем перезапустить ботов только после устранения `01-232` 409 Conflict.

## Критерии готовности

- В production bot env есть `APP_DB_MODE=postgresql` и `SPRING_DATASOURCE_URL`.
- В runtime log нет загрузки SQLite JDBC.
- Не запускается второй long-polling экземпляр для проверки.

## Выполнение

- RabbitMQ больше не меняет datasource-контракт бота: launcher всегда передаёт `APP_DB_MODE=postgresql` и `SPRING_DATASOURCE_*`.
- Production profiles `bot-telegram`, `bot-vk` и `bot-max` используют PostgreSQL контейнер `postgres`.
- Обновлены contract-тесты: они фиксируют передачу PostgreSQL-параметров при RabbitMQ transport mode.
- Проверено: `mvnw.cmd -Dtest=BotRuntimeContractServiceTest,BotProcessServiceTest,RmsLicenseMonitoringServiceTest test` — 48 tests, 0 failures.
- Проверено: `docker compose -f docker-compose.production-contour.yml config -q`.
- Production-перезапуск намеренно не выполнялся: сначала нужно устранить конфликт Telegram long polling в `01-232`, иначе новый экземпляр снова будет конкурировать за токен.

## Обязательные дополнительные условия

- Не перезапускать Telegram bot до устранения `01-232`.
- По завершении показать алерт через `./ai-context/baseline/scripts/show-completion-alert.sh`.
- В финальном ответе подготовить `Резюме для коммита`.
- После file changes создать отдельный changelog в `ai-context/changelog` с пользовательским промптом.
