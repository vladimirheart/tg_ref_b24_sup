# Задача [01-164]

## Короткое описание

Починить исчезающую историю диалога после ответа оператора при сбое `chat_attachment_metadata`.

## Цель

Вернуть стабильное отображение текущей и предыдущей истории диалогов даже если metadata-слой вложений поврежден, недоступен или временно не читается.

## Контекст

- По пользовательскому сценарию:
  - оператор открывает диалог;
  - отправляет ответ;
  - после этого исчезает вся история, включая новые сообщения;
  - кнопка загрузки предыдущих сообщений ничего не подгружает.
- В текущем workspace подтверждено, что `spring-panel/panel_runtime.db` отдает ошибку SQLite `database disk image is malformed` при чтении `chat_attachment_metadata`.
- `DialogConversationReadService` использует `LEFT JOIN chat_attachment_metadata` при чтении `/api/dialogs/{ticketId}/history`.
- При `DataAccessException` сервис возвращает пустой список сообщений, и фронт перерисовывает историю в пустое состояние.

## Что сделать

- Добавить отказоустойчивый fallback в чтение истории диалога: если metadata-join падает, повторно читать `chat_history` без `chat_attachment_metadata`.
- Не ломать legacy URL/preview/reply-preview поведение истории, когда fallback активирован.
- Зафиксировать регрессию тестом для `DialogConversationReadService`.
- Подтвердить ручной проверкой, что история и подгрузка предыдущих сообщений больше не исчезают из-за metadata-сбоя.

## Критерии готовности

- `/api/dialogs/{ticketId}/history` возвращает реальные сообщения даже при сбое чтения `chat_attachment_metadata`.
- История открытого диалога не пропадает после ответа оператора.
- Подгрузка предыдущих сообщений продолжает работать при degraded metadata-path.

## Результат выполнения

- В `DialogConversationReadService` добавлен fallback: если чтение истории с `LEFT JOIN chat_attachment_metadata` падает, сервис повторяет запрос только к `chat_history` без metadata-join.
- Сохранено текущее legacy-поведение истории:
  - reply preview;
  - сортировка сообщений;
  - legacy attachment URL fallback;
  - загрузка previous-history батчей через тот же degraded path.
- Добавлен unit-level regression test на повторное чтение истории без metadata после `DataIntegrityViolationException`.
- На текущей runtime БД подтверждено service-level вызовом:
  - при `SQLITE_CORRUPT` сервис пишет warn и повторяет чтение без metadata;
  - `loadHistory("30754419-bc81-4d3f-927e-f234bf59cdf0", null)` вернул `8` сообщений вместо пустой истории;
  - `loadPreviousDialogHistory(..., 0)` вернул batch с `40` сообщениями.
- `spring-panel\\mvnw.cmd -q -DskipTests compile` проходит успешно.
- Полный `test`-цикл репозитория сейчас не является зелёным из-за уже существующих посторонних ошибок test-слоя вне этой задачи.
