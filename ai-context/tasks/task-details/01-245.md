# Задача [01-245] Не восстанавливать отсутствующие исторические вложения по решению владельца

## Цель

Зафиксировать, что восстановление 24 исторических медиа не требуется владельцу проекта, не скрывая факт их отсутствия и не удаляя полезную metadata без отдельного retention-решения.

## Контекст

- В `chat_attachment_metadata` остаются 24 записи со статусом `missing`: 20 с provider `s3` и 4 с provider `local_fs`.
- Для 20 S3-записей выполнена прямая сверка с 98 объектами `iguana/attachments` в MinIO; совпадений нет.
- Поиск по `attachments`, `.tmp` и `temp-recovery` также не нашёл ни одного из 24 файлов.
- Автоматически менять статус на `available` нельзя: это скроет реальную потерю и оставит неработающие ссылки в UI.
- Владелец проекта `02.09.2026` подтвердил: эти файлы больше не нужны.

## Что сделать

- Не выполнять восстановление и не искать внешнюю резервную копию.
- Не менять `missing` на `available` и не удалять metadata автоматически.
- Считать эти записи исключёнными из release gate; физическое удаление metadata возможно только отдельной retention-задачей.

## Критерии готовности

- Решение владельца о невосстановлении зафиксировано.
- Новые медиа и актуальные диалоги не блокируются этим историческим остатком.
