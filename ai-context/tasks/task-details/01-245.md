# Задача [01-245] Восстановить отсутствующие исторические вложения из внешней резервной копии

## Цель

Вернуть доступность исторических медиа, для которых PostgreSQL сохранил metadata, но бинарные объекты отсутствуют во всех доступных локальных и MinIO-хранилищах проекта.

## Контекст

- В `chat_attachment_metadata` остаются 24 записи со статусом `missing`: 20 с provider `s3` и 4 с provider `local_fs`.
- Для 20 S3-записей выполнена прямая сверка с 98 объектами `iguana/attachments` в MinIO; совпадений нет.
- Поиск по `attachments`, `.tmp` и `temp-recovery` также не нашёл ни одного из 24 файлов.
- Автоматически менять статус на `available` нельзя: это скроет реальную потерю и оставит неработающие ссылки в UI.

## Что сделать

- Получить внешний backup MinIO/legacy attachments или повторную выгрузку файлов из исходных каналов.
- Сформировать инвентарь восстановления по metadata ID, ticket ID, storage key, имени, MIME type и ожидаемому размеру/hash при наличии.
- Восстановить бинарные объекты в `iguana/attachments/<storage_key>` без изменения логических ключей.
- Проверить открытие каждого объекта через panel media endpoint и только после этого перевести metadata в `available`.
- Зафиксировать невосстановимые записи отдельным отчётом с причиной и владельцем решения по retention.

## Критерии готовности

- Для каждой из 24 записей есть восстановленный объект либо подтверждённый акт отсутствия источника.
- Восстановленные файлы открываются из истории диалога и имеют корректные MIME type/размер.
- Проверка MinIO и metadata не показывает ложных `available` и не оставляет восстановленные объекты в `missing`.
