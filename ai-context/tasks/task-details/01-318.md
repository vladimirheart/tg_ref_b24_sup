## Реализация

- Единая PanelAccessPolicy требует PAGE_SETTINGS и право соответствующего блока.
  DENY имеет приоритет; legacy права users/channels не переживают запрет родителя.
  Фильтр закрывает чтение и запись API, controller guards сохраняются.
- /users и /users/{username} больше не рендерят отдельные страницы управления:
  разрешённые запросы перенаправляются в Settings. /channels также только alias,
  с проверкой channels. Старые пункты навигации/fallback после входа удалены.
- Запрещённые блоки/вкладки/карточки скрываются. Общие settings/page-data и словари
  исключают запрещённые данные. Сохранение разрешённого блока не отправляет пустые
  значения запрещённых соседних блоков и не требует их валидации.
- Шаблоны/автозакрытие/сеть сохраняют свою вкладку независимо от права channels.
  Отчётам возвращаются только названия и строковые ID каналов; привязкам управляющих
  доступен существующий минимальный roster, без открытия account-management API.
  Организация/workforce получают ограниченный auth aggregate вместо данных ролей
  и контактных/account capabilities. Passport-specific equipment read checks сохранены.
- Сервер запрещает смену собственной роли, понижение/отключение/переименование/
  блокировку/удаление системного admin и изменение прав/названия/удаление защищённых
  системных ролей. UI capabilities соответствуют ограничениям; свой профиль/пароль
  остаются доступны при действующих правах блока и проверке числового ID.
- Bootstrap поддерживает каноническую роль admin только для уже подтверждённого
  уникального exact admin с прямым ROLE_ADMIN. Этот workload запускается только
  в роли MIGRATOR; на panel-web он намеренно не выполняется.
