# Задача [01-214]

## Короткое описание

Убрать обязательный Redis UI fanout из local PostgreSQL bootstrap-контура Windows launcher.

## Цель

Починить запуск `spring-panel\run-windows.bat` в локальном bootstrap-режиме PostgreSQL, когда launcher осознанно включает `APP_COORDINATION_MODE=direct`, но приложение всё равно падает на старте из-за `uiEventRedisMessageListenerContainer` и попытки подключиться к Redis `localhost:6379`.

## Контекст

- Локальный launcher уже подставляет compatibility defaults:
  - `APP_COORDINATION_MODE=direct`
  - `APP_COORDINATION_REQUIRED_FOR_POSTGRESQL=false`
  - `APP_STORAGE_OBJECT_REQUIRED_FOR_POSTGRESQL=false`
- `RuntimeRoleSafetyValidator` уже разрешает `APP_UI_EVENT_FANOUT_MODE=auto` только для compatibility `role=all`.
- При этом `UiEventRedisSubscriptionConfiguration` создаёт Redis listener без явной проверки runtime fanout mode.
- `UiEventFanoutPublisher` в `auto` не должен превращать local bootstrap в hard dependency на Redis.

## Что сделать

- Привести `AUTO` UI fanout к совместимому local поведению для `role=all`.
- Не поднимать `uiEventRedisMessageListenerContainer`, если `APP_UI_EVENT_FANOUT_MODE` не равен `redis`.
- Сохранить fail-fast поведение split-role production-контура, где `panel-web` / `ops-worker` требуют явный Redis fanout.
- Добавить/обновить unit/runtime tests на новый контракт.
- Проверить, что `run-windows.bat` больше не падает на `Unable to connect to Redis` в локальном bootstrap-контуре.

## Критерии готовности

- `run-windows.bat` доводит локальный PostgreSQL bootstrap до успешного старта `spring-panel` без Redis.
- `UiEventFanoutPublisher` в compatibility `AUTO` не требует Redis и выполняет process-local fallback.
- Redis subscriber/listener поднимается только при явном `APP_UI_EVENT_FANOUT_MODE=redis`.
- Targeted tests проходят.
- После AI implementation статус задачи только `🟣`; перевод в `🟢` делает пользователь после ручной проверки.

## Update 2026-08-26 19:01:00 +03:00 — local bootstrap больше не падает на Redis UI fanout

Корень проблемы:

- `run-windows.bat` уже подставлял compatibility defaults для local PostgreSQL bootstrap:
  - `APP_COORDINATION_MODE=direct`
  - `APP_COORDINATION_REQUIRED_FOR_POSTGRESQL=false`
- но `UiEventRedisSubscriptionConfiguration` всё равно безусловно поднимал `uiEventRedisMessageListenerContainer`;
- на startup это превращало optional UI fanout в hard dependency на Redis `localhost:6379`.

Что изменено:

- compatibility `APP_UI_EVENT_FANOUT_MODE=auto` теперь ведёт себя как process-local fanout и не публикует события в Redis;
- Redis subscriber configuration включается только при явном `APP_UI_EVENT_FANOUT_MODE=redis`;
- source tests обновлены под этот контракт.

Проверка:

- targeted tests:
  - `UiEventFanoutPublisherTest`
  - `RuntimeRoleSafetyValidatorTest`
  - `UiEventRedisSubscriptionConfigurationTest`
- реальный launcher:
  - `spring-panel\\run-windows.bat`
  - после фикса panel успешно поднялась;
  - `http://localhost:8080/` ответил `HTTP 200`.
