# Задача [01-233] Сделать интервалы и паузы RMS-мониторинга настраиваемыми из UI

## Короткое описание

Убрать жёстко заданные интервалы RMS-проверок и паузу очереди, предоставив безопасную ручную настройку на странице «Контроль RMS».

## Цель

Оператор может отдельно задать частоту проверки лицензий, доступности RMS и интервал между последовательными запросами; настройки сохраняются и применяются в worker без перезапуска.

## Контекст

- Сейчас `RmsLicenseMonitoringScheduler` использует `@Scheduled` с зашитыми 24 часами для лицензий и 5 минутами для сети.
- `RmsLicenseMonitoringService` использует `QUEUE_GAP_MS = 20_000L`.
- Общие runtime-настройки хранятся в `config/shared/settings.json` через `SharedConfigService`.

## Что сделать

- Добавить сервис persisted RMS schedule policy с ограничениями значений и defaults, совместимыми с текущим поведением.
- Перевести scheduler на периодический dispatcher, который сверяет сохранённые интервалы и запускает проверки через existing lease boundary.
- Подключить паузу очереди из policy.
- Добавить GET/PUT API и форму настройки на странице RMS.
- Добавить backend и web-contract тесты.

## Критерии готовности

- Лицензии, доступность и пауза редактируются из UI и сохраняются после перезагрузки.
- Значения валидируются и защищены от опасной частоты запросов.
- Новые значения применяются worker без рестарта и без параллельных проверок.
