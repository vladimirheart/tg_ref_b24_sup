# 01-200 - SMTP and incident notification delivery health

## Статус

`🔴` -> `🟣` после завершения AI implementation wave.

## Контекст

После `01-199` в monitoring contour Iguana остается следующий blind spot из roadmap `01-197`:

- состояние SMTP relay / mail relay как внешней зависимости support-контура;
- разница между "канал доставки теоретически доступен" и "incident notification реально дошел";
- backlog / failed / pending состояние `incident_route_delivery_outbox`;
- operator-facing timeline по SMTP probe и recent delivery failures.

В проекте уже есть `IncidentRouteDeliveryOutboxService`, `IncidentRouteDeliveryService` и diagnostics по конкретному incident, но нет отдельной operator-facing поверхности, которая показывает здоровье notification path целиком.

## Что нужно сделать

1. Добавить новый monitoring source для SMTP relay probes.
2. Ввести отдельную сущность/таблицу конфигурации SMTP monitor:
   - `monitor_name`
   - `relay_host`
   - `relay_port`
   - `protocol_mode`
   - `connect_timeout_ms`
   - `enabled`
   - runtime snapshot полей relay/banner/TLS.
3. Реализовать probe-слой:
   - TCP connect;
   - SMTP banner validation;
   - implicit TLS probe для `tls`;
   - STARTTLS upgrade probe для `starttls`.
4. Собирать aggregate severity и summary:
   - `ok`
   - `critical`
   - `disabled`
   - availability overview.
5. Писать timeline в `monitoring_check_history`.
6. Добавить scheduler с lease.
7. Добавить отдельную analytics page + JS runtime:
   - SMTP overview
   - table with CRUD
   - manual refresh
   - history modal
   - route delivery health summary
   - recent failed delivery list
8. Добавить aggregate service по `incident_route_delivery_outbox`, который показывает:
   - delivered / failed / pending counts
   - failed backlog
   - last successful delivery
   - last failed delivery
   - breakdown by route type
   - transient vs permanent failures
9. Обновить `AnalyticsController`, `analytics/index.html`, SQLite bootstrap и PostgreSQL migration.
10. Добавить тесты на:
   - healthy SMTP probe flow
   - STARTTLS/TLS failure aggregation
   - analytics route rendering
   - bootstrap schema presence.

## Ожидаемый результат

В Iguana появляется отдельный operator-facing monitoring contour, который показывает:

- жив ли SMTP relay и проходит ли базовый protocol handshake;
- сколько notification deliveries доставлено/застряло/упало;
- есть ли failed backlog в incident route outbox;
- какие route types деградируют;
- какие последние ошибки требуют ручного recovery или redelivery.
