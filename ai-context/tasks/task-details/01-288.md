# 01-288 — Автоматическая подготовка инфраструктуры ботов

Статус: 🟣 — реализация и локальные проверки завершены; ожидается проверка пользователя.
Baseline HEAD/origin/main: `35bed94d00b301286c79a99df4030cb302d4147d`.

Промт пользователя:

```text
автоматизируй подготовку инфраструктуры
```

Контекст: добавление Telegram/MAX ранее сохраняло только канал; отдельные SQL/Rabbit
principals и очереди требовали ручного provision. Требуется автоматизация при
сохранении нового канала и возможность завершить подготовку после частичной ошибки.

План: backend-owned V94/ограниченная SECURITY DEFINER функция и журнал; idempotent
RabbitMQ management client; вызов после сохранения и до lifecycle start; spinner,
понятный результат и повтор через «Старт»; настройки окружения и runbook. Существующие
manual principals не усыновляются, не ротируются и не включаются после revoke.
Никаких общих child credentials, административных broker tags или configure rights.

Применимы operating protocol, guarded change, multibusiness S0 и PostgreSQL-only
storage boundaries. Новые бизнес-привязки не выводятся из текстовых имён. Работа
в detached `.tmp/01-288-infrastructure-source`; запись в основной checkout только
после targeted GREEN, exact scope и diff checks. Рабочие сервисы/провайдеры и БД
не используются. Docker недоступен; PostgreSQL — собственный nonce-checked native
cluster на loopback, broker — stateful loopback HTTP double. Live broker/provider
приёмка и выпуск остаются отдельными действиями.

Результат: V94 создаёт приватный journal и backend-owned SECURITY DEFINER функцию
с фиксированным search_path. Функция атомарно создаёт только ограниченный child
login, V86 binding и journal. SQL не подставляется из HTTP payload; роль/права
фиксированы, password выводится из прежнего HMAC contract. До broker writes SQL
транзакция фиксируется; salted broker hash сохраняется для безопасного повтора,
SQL password в journal отсутствует. Завершение сериализуется по journal row с
shared locks canonical channel/principal, включая повторную проверку active/platform/
enabled. Отозванные/чужие identities не присваиваются, не ротируются и не оживляются.

RabbitMQ client использует backend-only management credentials, проверяет backend
exchanges, создаёт недостающие own user/queues/bindings/permissions и проверяет
совпадение существующих. configure=^$, write только inbound exchange, read только
own outbound queue, tags отсутствуют. Redirects запрещены, HTTP3s/этап30s; сырые
SQL/HTTP ошибки и credentials не возвращаются в UI или logger. Management env
отсекается существующим child environment allowlist. Manual principals остаются
на прежнем startup principal gate и не усыновляются автоматизацией.

После сохранения ChannelTransportService возвращает infrastructure.state/message;
частичная ошибка не удаляет канал. Форма показывает spinner, исключает повторный
submit, выводит предупреждение и возможность повторить «Старт», сохраняет отзыв
права редактирования при позднем завершении. BotProcessService готовит инфраструктуру
до остановки работающего процесса; неподготовленный новый процесс не запускается.
Стандартные ручной start/restart и runner auto-start используют этот же путь.
GET списка и статусов, stop и редактор без команды запуска не выполняют provision.
Настройки application/Compose/.env.example и runbooks обновлены. Смена бизнесов,
шаблонов, platform/secret rotation, автоматическое удаление identities и очередей
не входят в scope.

Проверки: 849 targeted JVM cases/17 suites, failures/errors/skipped=0; 11 Node
cases — GREEN. 69 actual PostgreSQL cases (14 новые +55 principal regression)
прошли на собственном native PostgreSQL16 с SCRAM для children; test-admin доверен
только на loopback и nonce/data_directory проверены. Проверены ошибки пароля,
least privilege, RLS/revoke, concurrency, восстановление после потерянного ответа,
изоляция schema и полная Flyway chain до V94. Migration count fixture principal
test обновлён с устаревшего87 до94, assertions политик и удаления binding сохранены.
Новый тест отказа SQL сверяет SQLSTATE42501 в корневом SQLException, а не текст
обёртки Spring. Native тестовые DB подготовлены заново после первого прогона.
RabbitMQ — stateful loopback HTTP double: конфликты hash/tags/permissions/queues/
bindings и потерянный ответ. Docker engine недоступен; real broker/AMQP и provider
end-to-end не проверялись. Полный package/Sass build и выпуск не выполнялись.

Maven compiler:compile и compiler:testCompile проверили Java; после последних
изменений все changed/new Java classes проверены javac с текущим Surefire classpath.
JS syntax, docker compose config --quiet с .env.example и git diff --check GREEN.
Обновления остальных test constructors только добавляют mock новой зависимости.

Исходный общий ChannelApiControllerWebMvcTest имеет10 старых failures из50
(refresh info, credential deletion, test-message и legacy secret expectation).
Оригинальные service/test файлы прочитаны из exact baseline, независимо скомпилированы
и запущены: те же10 failures,40 pass. Assertions не ослаблялись; текущие10
createChannel cases, включая2 новых, GREEN. Этот общий набор не объявляется зелёным.

Артефакты: `.tmp/01-288-infrastructure-source/spring-panel/target/infra288-final.log`,
`infra288-postgres-final.log`, `infra288-validation.json`; baseline proof —
`.tmp/01-288-baseline-check/result.json`. Targeted sandbox GREEN; проверенные35
project files перенесены в основной checkout с exact HEAD/origin/status/scope и
SHA256 guards. source_applied=true; staged=false; committed=false; pushed=false;
deployment=false. Временный PostgreSQL остановлен; рабочие БД, брокер и боты
не затрагивались. При выпуске нужны новые backend/panel и bot-runner с V94;
исходники bot JARs не меняются. macOS completion-alert на Windows не применим.
