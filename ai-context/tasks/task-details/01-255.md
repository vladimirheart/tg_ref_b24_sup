# Задача [01-255] Уплотнить идентификационную шапку диалога и вынести бизнес в центр

## Короткое описание

После 01-254 action-controls стали компактнее, но левая идентификационная часть
шапки всё ещё расходует лишнюю высоту: внутренний ID смешан с номером обращения,
локация вынесена отдельной строкой, а бизнес не виден в центральной части header.

## Цель

Сделать шапку диалога ниже и быстрее считываемой оператором, не меняя backend/API
контракты и не затрагивая действия, composer, историю или SLA-логику.

## Что сделать

- Не показывать внутренний ticket/dialog ID в шапке.
- Показывать только номер обращения в форме `Диалог № <номер>`.
- Перенести локацию в ту же строку сразу после номера диалога.
- Сделать подписи `Диалог` и `Локация` одинаково жирными.
- Поднять avatar + номер + локацию к верхней границе header.
- Убрать отдельную строку локации и сократить нижний padding header примерно вдвое.
- В центр шапки добавить выбранный бизнес текущего диалога.
- Бизнес должен обновляться и из fallback row, и после ответа details API.
- Если для бизнеса настроены business-cell colors, использовать их и в центральном badge.
- Сохранить responsive layout на узких экранах.
- Обновить app.css/dialogs runtime cache-busters.
- Generated CSS напрямую не редактировать.

## Критерии готовности

- В шапке отсутствуют `ID диалога`, `ID:` и другие внутренние идентификаторы.
- Видно `Диалог № <номер>`, затем `Локация <наименование>` в одной строке.
- `Диалог` и `Локация` имеют одинаковый font-weight.
- Avatar и идентификационная строка выровнены по верхнему краю.
- Нижнее пустое пространство header заметно меньше.
- Текущий бизнес отображается по центру header и обновляется при открытии диалога.
- Existing icon actions, font control, composer, media viewer и SLA behavior не регрессируют.
- Source-contract tests, node --check, git diff --check и isolated SCSS compile проходят.
