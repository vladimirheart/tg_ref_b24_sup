# Задача [01-184]

## Короткое описание

Довести AI Ops из наблюдательного экрана до рабочего operator control center, где сохранённые решения управляются явно, feedback реально влияет на memory, а auto-reply можно безопасно проверять до отправки клиенту.

## Цель

Сделать AI Ops рабочим инструментом для эксплуатации подсказок и автоответов:

- оператор видит, какие записи solution memory реально участвуют в runtime;
- сохранённый текст ответа можно редактировать и повторно активировать;
- запись можно безопасно отключить без физического удаления истории;
- auto-reply для memory разрешается только явным opt-in на конкретной записи;
- отклонённая подсказка возвращает memory на ревизию и немедленно блокирует auto-reply;
- одна memory не может сама подтвердить себя через автоматически созданный knowledge unit;
- Decision Testbench показывает прогноз runtime-решения без отправки клиенту.

## Аудит до v44

Повторная проверка текущего `main` показала, что AI runtime не является декорацией: retrieval, intent policy, decision engine и реальная отправка auto-reply существуют и связаны между собой. Проблема была в operator governance и нескольких safety-gap:

1. Approved/medium memory могла попасть в auto-reply без отдельного разрешения оператора на эту запись.
2. Автоматически созданный из memory knowledge unit мог считаться вторым независимым подтверждением той же memory.
3. Suggestion feedback сохранялся как telemetry, но не менял конкретную memory, потому что `memory_key` не передавался через UI/API.
4. `Вставить как есть` не создавал positive feedback.
5. Cooldown проверял `auto_reply`, тогда как runtime сохраняет действие `auto_replied`.
6. Редактирование query text оставляло старый hash-key и могло разрушить identity memory.
7. DELETE физически удалял memory, хотя UI одновременно предлагал историю/rollback.
8. `ai-retrieve-debug` существовал, но не был выведен оператору как безопасный testbench.

## Реализация v44

- PostgreSQL V32 / SQLite V50: `ai_agent_solution_memory.auto_reply_allowed`, default `0`.
- Все существующие memory после миграции остаются suggestion-only до явного opt-in.
- Message flow проверяет одновременно source trust, intent policy и per-memory `auto_reply_allowed`.
- Derived knowledge с `source_ref=memory:*` не участвует как отдельный retrieval candidate; независимые memory-links продолжают давать evidence count.
- Rejected feedback: `times_corrected + 1`, `draft`, `low`, `review_required=1`, auto-reply off, derived knowledge forgotten.
- Accepted feedback: `times_confirmed + 1` для конкретной memory; trust автоматически не повышается.
- Question/query в AI Ops становится read-only identity; редактируется solution text.
- Отключение memory становится soft-disable (`deprecated`) вместо hard delete.
- Rollback всегда возвращает текст с auto-reply выключенным, пока оператор снова явно не разрешит его.
- Decision Testbench использует реальные reclassify/retrieve-debug/policy thresholds/dialog controls/consistency/loop guard без side effects.

## Критерии готовности AI-части

- Existing memory не может автоматически отвечать после миграции без explicit opt-in.
- Один derived knowledge unit не открывает auto-reply сам по себе.
- Suggestion reject снимает memory с auto-reply и отправляет на review.
- Suggestion apply-as-is фиксирует positive feedback по `memory_key`.
- `auto_replied` учитывается cooldown guard.
- AI Ops позволяет редактировать solution, включать/выключать per-memory auto-reply, отключать memory и смотреть историю.
- Testbench показывает intent, mode, consistency, evidence и финальный прогноз action/reason без реальной отправки.

## Что остаётся для ручной проверки

1. После миграции открыть AI Ops и убедиться, что старые memory имеют auto-reply off.
2. Выбрать безопасную memory, разрешить auto-reply и проверить testbench на существующем тестовом ticket.
3. Убедиться, что suggestion-only memory в testbench даёт `suggest_only`, а не `auto_reply`.
4. Отклонить подсказку в диалоге и проверить: corrected увеличен, запись ушла на ревизию, auto-reply выключен.
5. Разрешить auto-reply на безопасной записи и выполнить отдельный контролируемый live smoke на тестовом клиенте.

До ручной проверки задача остаётся `🟣`.
