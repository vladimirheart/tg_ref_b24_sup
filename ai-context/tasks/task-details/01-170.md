# Задача [01-170]

## Краткое описание

Убрать пересборку dropdown оповещений при смене `read-state` и синхронизировать только статус записей.

## Цель

Довести UX sidebar-оповещений до стабильного состояния: при auto-read, ручной пометке или bulk-read список не должен визуально пересобираться, если состав и порядок уведомлений не изменились.

## Контекст

- В задаче `01-169` порядок оповещений уже был зафиксирован, но пользователь сообщил, что при чтении dropdown всё ещё выглядит как пересобранный.
- Текущий runtime в `spring-panel/src/main/resources/static/js/sidebar.js` после read-действий всё ещё может целиком перезагружать список через `loadNotificationsSafe()` и реакцию на `notifications_changed`.
- Для данного UX-сценария достаточно локально обновлять `read/unread`-состояние DOM-элементов и toolbar, а полный rerender делать только если реально изменился состав или порядок уведомлений.

## Что сделать

- Добавить в sidebar-runtime мягкую синхронизацию dropdown оповещений по `id` без полной пересборки DOM, если порядок элементов не изменился.
- После auto-read и `Прочитать все` обновлять локальное состояние карточек и toolbar без вызова полного reload списка.
- Изменить refresh-логику так, чтобы при уменьшении количества непрочитанных уведомлений открытый dropdown не ререндерился целиком.
- Сохранять полный rerender только для сценариев, где действительно появился новый элемент, пропал старый или поменялся порядок.

## Критерии готовности

- При автоматической пометке уведомления как прочитанного карточка остаётся на месте и не вызывает видимую пересборку dropdown.
- При `Прочитать все` список сохраняет текущий DOM-порядок, а меняется только стиль и toolbar состояния.
- При получении новых уведомлений dropdown по-прежнему может обновиться корректно, если состав списка изменился.
- Есть локальная проверка `sidebar.js`.

## Обязательные дополнительные условия

- По завершении задачи показать алерт через `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно не отменил это требование.
- В финальном ответе подготовить `Резюме для коммита` по формату из `ai-context/baseline/guides/tasks.md`.
- После любых file changes создать отдельный changelog-файл в `ai-context/changelog` и включить в него пользовательский промпт, который привёл к изменению.
