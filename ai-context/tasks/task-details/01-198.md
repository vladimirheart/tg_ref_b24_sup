# Задача [01-198]

## Короткое описание

Внедрить мониторинг freshness backup и restore evidence для production contour.

## Цель

Сделать backup/restore readiness частью реального monitoring contour Iguana: support и on-call должны видеть, есть ли свежий backup, не устарело ли последнее restore evidence и насколько рискованно текущее состояние recovery-контура.

## Контекст

- В production roadmap уже зафиксировано, что backup freshness и restore freshness входят в первую волну monitoring coverage.
- Сейчас это описано в документации и runbook, но в коде нет отдельного monitoring source с history, overview и alert-ready статусом.
- Для первого implementation шага достаточно file-based backup monitors + ручного подтверждения restore drill.

## Что сделать

- Добавить отдельный monitoring source для backup freshness.
- Поддержать file-path / directory / simple glob-pattern сценарий поиска последнего backup artefact.
- Добавить restore evidence timestamp и статус его свежести.
- Вывести overview, detail timeline и operator actions для refresh / confirm restore.

## Критерии готовности

- В Iguana есть отдельный monitoring surface для backup readiness.
- Видны как минимум:
  - last backup timestamp
  - backup age
  - freshness status
  - last restore verification timestamp
  - restore freshness status
- Есть timeline последних проверок и operator action для подтверждения restore drill.

## Обязательные дополнительные условия

- По завершении задачи показать alert через `./ai-context/baseline/scripts/show-completion-alert.sh`, если пользователь отдельно не отменил это требование.
- В финальном ответе подготовить `Резюме для коммита` по формату из `ai-context/baseline/guides/tasks.md`.
- После любых file changes создать отдельный changelog-файл в `ai-context/changelog` и включить в него пользовательский промпт, который привел к изменению.
