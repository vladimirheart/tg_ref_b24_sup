# Задача 01-301

## Короткое описание

Увеличить окно состава оргструктуры и исключить сжатие старым сохранённым размером.

## Цель и контекст

На скриншоте пользователя широкое окно состава имеет высоту около 220 px.
На baseline `00c8f7007befebce0aa3a4d05c24d3d5504880b2` (parent
`e0d77b1169f15e6a3a54b5d7eaddc6c6ce52c274`) воспроизведено:
при viewport 1280 × 663 и сохранённом размере 896 × 220 общий resize runtime
переопределяет высоту 740 px из SCSS. Предыдущая проверка 01-300 использовала
пустой localStorage и viewport высотой 900 px, поэтому не поймала сценарий.

## Изменения

- Открывать окно шириной до 1120 px и почти на всю высоту viewport (отступы 12 px).
- Разрешить отдельному окну задать минимальные размеры через data attributes:
  для состава 900 × 640, с ограничением доступной шириной/высотой экрана.
- Учитывать минимумы при восстановлении, pointer/keyboard resize и resize viewport;
  остальные окна сохраняют прежние общие минимумы 320 × 220.
- Сохранить общий EmployeePicker и текущие составы/права/формы.
- Список выбора занимает оставшееся место в окне. При открытом picker вводное
  пояснение скрывается, preview текущего состава становится компактным; на viewport
  до 540 px высотой preview временно скрыт. «Готово» возвращает полный preview.
  На низком экране уменьшены только отступы; размеры полей и строк сохранены.
- Обновить версии CSS и resize runtime, пересобрать CSS из SCSS.

## Критерии готовности

- Сохранённые 896 × 220 больше не открывают сжатое окно; очищать браузер не нужно.
- В сценарии скриншота список имеет видимую рабочую область, footer помещается в экран.
- Проверены светлая/тёмная темы, короткий viewport, мобильный экран и resize.
- Другие окна не получают новый минимум; состав и профиль по-прежнему сохраняются.
