# 01-284 — Документы и история паспорта объекта

Статус: 🟣 — реализация и локальные проверки завершены, ожидается проверка пользователя. Baseline HEAD / локальный origin/main: `e240cc0fc3c1dc99846e7250117641f8acdab2af`.

Промт пользователя:

```text
в паспорты объектов добавить возможность загружать и изменять отельно взятые файлы\документы и тому подобное. например документы приёмки оборудования после его настройки с разным пулом инфы. или исторические изменения. поле нужно полусвободным но с превью, например фото или дока. Сделать вероятнее всего нужно отдельной вкладкой.
```

Реализация: отдельная вкладка «Документы и история». Карточка содержит название, свободный тип, дату события, описание, дополнительные пары поле/значение и необязательный файл. Любое изменение сохраняет снимок предыдущей версии, автора и время; замена файла не удаляет старый. Архивирование обратимо. Просмотр доступен по праву паспортов; изменение имеет отдельное `passport.documents` / `EDIT_PASSPORT_DOCUMENTS` в ролях и персональных правах.

Границы: PostgreSQL хранит метаданные и версии (новая миграция V92), существующий MinIO/S3 — бинарные файлы. Изображения/PDF и текст DOCX/TXT/MD/CSV/LOG/JSON имеют превью, остальные форматы скачиваются. Файлы до 50 МБ. Полное удаление паспорта, содержащего документы, блокируется внешним ключом; обычное обновление и архивирование паспорта не затрагивают документы.

Правила: `ai-context/rules/00-agent-operating-protocol.md`, `ai-context/rules/01-guarded-change-operator.md`, `ai-context/rules/backend/05-iguana-production-storage-boundaries.md`, `ai-context/baseline/guides/tasks.md`.

План проверки: компиляция, тесты реального PostgreSQL в одноразовом локальном контуре, HTTP-права/CSRF/чужой паспорт, замена и чтение старого файла, конфликт версий/rollback, безопасное превью, браузерные сценарии на 320/1440 px. Рабочие БД, внешние системы и развёртывание в задачу не входят.

Результат: вкладка загружает записи по запросу; есть поиск, ограниченная выдача по 25 записей/версий, просмотр, редактирование, замена файла, архив и возврат из архива. Предыдущие снимки и файлы доступны для чтения. Конфликт версии возвращает 409 и не стирает введённые данные в форме. Безопасное превью использует серверное определение формата; HTML/SVG и прочие неподдерживаемые форматы скачиваются. PDF проверен визуально в браузере; изображения и текст DOCX/TXT отображаются внутри окна просмотра.

Валидация: итоговые Surefire XML 13 целевых наборов — 335 тестов, 0 failures/errors/skipped. Финальная отдельная перепроверка 4 security-наборов — 112 тестов, exit 0. Проверены реальные PostgreSQL-транзакции V92, два конкурирующих сохранения, 409, rollback и очистка только нового файла, неизменность старого файла, связь документа с паспортом, ограниченная выдача и архив. HTTP-проверки используют настоящий SecurityConfig, включая запреты записи, CSRF и единственное SAMEORIGIN для успешного типизированного file-preview; обычные ответы и ошибки сохраняют DENY.

Playwright: 320/1440 px, просмотр/редактирование, свободные поля, загрузка изображения, замена на PDF, текст DOCX без исполнения разметки, скачивание прежнего изображения с проверкой байтов, конфликт сохранения, архив/возврат — GREEN. Фикстуры используют настоящий HTML-фрагмент, CSS и JS. Скриншоты и свидетельства в `spring-panel/target/passport-documents-qa/`; сценарий `tools/passport-documents-qa.cjs`. Синтаксис JS и `git diff --check` — GREEN.

Docker на текущей машине недоступен, поэтому для JDBC-проверок использовался отдельный nonce-owned PostgreSQL 16.16 на loopback, созданный под игнорируемым `spring-panel/target/passport-documents-pg/`. Запуск выполнялся через существующий контракт `PostgresqlJdbcTestSupport` (`r290.edit.jdbc`, `r290.edit.nonce`). Кластер после проверок остановлен, установочный архив удалён. Тестовые бинарные файлы получены с официальной страницы EDB; системная установка и служба PostgreSQL не создавались.

Для применения: пересобрать панель, применить V92 штатным Flyway-процессом развёртывания, назначить обычным редакторам право `passport.documents`. `fields.edit: ["*"]` и системные административные роли включают его автоматически; `settings.*` не включает. Пользователи с одним PAGE_OBJECT_PASSPORTS могут читать документы. Документация хранения и матрица прав обновлены.

Фактическое состояние: source_applied=true, staged=false, committed=false, pushed=false, deployment=false. Отдельный source sandbox не создавался; тесты запускались в текущем checkout с изолированной временной БД/хранилищем. Миграция рабочего экземпляра, его файлы/настройки/роли, NetBox и другие внешние системы не изменялись.
