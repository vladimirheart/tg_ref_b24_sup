# Задача [01-294]

## Короткое описание

Унифицировать вопросники ботов: каждый вопрос может явно записывать ответ в
каноническое поле обращения или аналитики.

## Цель

Для канала назначается один вопросник. Вопросник сам определяет, какие ответы
становятся бизнесом и описанием проблемы; отсутствие таких ответов прозрачно
фиксируется без угадывания и без legacy fallback.

## Контекст

- `channels.question_template_id` — назначение вопросника каналу.
- Действующие business-scoped шаблоны и их snapshot должны продолжать
  обслуживать начатые сессии и исторические обращения.
- Бизнес — только канонический идентификатор, а не свободный текст.
- Отсутствие бизнеса и отсутствие проблемы — независимые признаки, а не
  lifecycle-статус обращения.

## Что сделать

- Ввести явные назначения результата вопроса `business` и `problem` в
  question flow с валидацией контракта.
- Добавить opt-in unified runtime для шаблона канала, не меняя поведение
  существующих scoped шаблонов.
- Создать отдельный unified-дубликат текущего вопросника Telegram-канала и
  назначить его каналу через штатное сохранение настроек.
- Сохранить отсутствие ответа как каноническое `WITHOUT_BUSINESS` /
  `WITHOUT_PROBLEM` представление для аналитики и карточки обращения.
- Сделать назначение вопросника в UI канала прозрачным: fallback не должен
  выглядеть как активная бизнес-анкета.

## Критерии готовности

- Новый вопросник канала записывает выбранный бизнес в `tickets.business_id`.
- Если business/problem не назначены или не получены, обращение остаётся
  валидным и отображает независимые признаки отсутствия данных.
- Действующие question template snapshots и старые обращения не изменяются.
- Оценки и автоматические действия остаются привязками конкретного канала.

## Обязательные дополнительные условия

- В финальном ответе подготовить `Резюме для коммита` по формату из
  `ai-context/baseline/guides/tasks.md`.
- После изменения файлов создать отдельный changelog-файл в
  `ai-context/changelog` с пользовательским промтом.
