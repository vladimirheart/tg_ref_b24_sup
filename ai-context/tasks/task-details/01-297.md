# Задача 01-297 — оформление и палитры Iguana

Статус: 🟣. Реализация и локальные проверки завершены; ожидается ручная приёмка.

## Цель и контекст

Перенести в настоящий интерфейс согласованное превью: спокойная навигация,
тонкие разделители, компактная типографика, графитовая, хвойная, песочная,
северная и сливовая палитры. Для каждой — light/dark/auto через существующий
ThemeRuntime и пользовательские UI preferences.

Исходные сообщения пользователя: «уже приятнее. а как с другими цветовыми
гаммами\\темами будет выглядеть?» и «уже интереснее. давай делать».
Ранее отдельно указана обязательность перемещения, скрытия, возврата и сброса
плашек дашборда. Закрепление также сохраняется.

Baseline HEAD/origin/main: `86b9b4e25f9268e881ab96457175422202a97e08`.
Основной checkout чистый; подготовка и проверка в detached worktree
`.tmp/ui-refresh-20261119`. Внешний сервер и рабочие БД не используются.

## Объём

- Общее оформление страниц и sidebar без изменения маршрутов/прав.
- Пять палитр, независимый режим яркости, старые Catppuccin/Amber сохранены.
- `neo` остаётся совместимым ключом графитовой палитры: миграция не нужна.
- Выбор в настройках оформления с образцами; сохранение тем в профиле.
- Кнопка настройки раскладки показывает прежние pin/hide/drag/reset controls.
- Общие версии CSS и bootstrap JS обновляются для всех самостоятельных страниц.

## Критерии готовности

Sass и Java compile; round-trip палитр в профиле, изоляция пользователей,
сохранение dashboardPanelLayout; browser-проверка тем, системного режима,
reload, переключения страниц, настройки дашборда и узкого экрана.
Рабочие runtime, deploy, commit/push и ручная приёмка не выполняются.

## Реализация и проверка

Добавлены общие SCSS-слои палитр, приложения, sidebar и настроек с производными
CSS. Navbar использует существующие Bootstrap Icons вместо emoji, активные
пункты и обычные строки имеют сдержанное выделение. Сообщения клиента и
оператора в карточке диалога получили прозрачные поверхности с сохранением
авторов, времени, меню, вложений и reply highlight. Метрики дашборда лишены
вложенных рамок; фильтры и существующие вкладки сохранены.

В настройках пять основных палитр с образцами и прежние две в disclosure.
Разрешения не менялись: browser проверяет запрещённое редактирование у
viewer и включение по отдельному appearance permission. Кнопка «Настроить»
управляет только видимостью прежних panel actions; их inline runtime,
сортировка, хранение и восстановление раскладки не переписаны.

- Repository Maven wrapper: Sass, main/test compile, package — GREEN.
  После последней CSS-правки выполнены generate-resources, resources:resources,
  jar:jar и spring-boot:repackage. JAR собран в sandbox target.
- **84 Java cases / 12 suites**, failures/errors/skips = 0, включая 14
  UiPreferenceService cases: новые/старые палитры, round-trip, другой пользователь,
  независимый dashboardPanelLayout и невалидное значение.
- **160 browser cases**: 8 настоящих MVC-экранов × 5 палитр × light/dark ×
  390/1440 px. Проверены полный token contract, цвет страницы, отсутствие
  выхода основного содержимого за viewport и контраст основного текста.
  Это не полная WCAG-проверка всех элементов.
- Дополнительно: форма выбора и reload, auto с настоящим media change,
  appearance permission, pin/hide/индивидуальный возврат/show-all/reset,
  native drag между видимыми панелями, сохранение раскладки при смене темы,
  мобильное меню, видимая ошибка поля и кнопка закрытия в dark. Uncaught errors = 0.
- Source audit: **79 templates / 50 самостоятельных страниц**; версия CSS
  обновлена на каждой. `shared-work-access` правильно учитывается как fragment.
  Единственные inline styles — прежние critical first-paint блоки.
- Начальные RED были в проверяющем контуре: устаревший dialogsAssetVersion и
  неполная fixture модели knowledge/editor после обновления прав/разделов/связей.
  Исправлены fixtures/ожидания, production logic и права не ослаблялись.
  Существующие 83 cases затем прошли; исправленная page-family suite повторена
  GREEN. Browser harness исправлен для visible native drop, асинхронного
  media event и отдельных viewer/editor fixtures; итоговый полный прогон GREEN.

Рабочие БД не использовались: новый nonce-owned PostgreSQL с отдельным
каталогом и случайным loopback port остановлен после тестов. Browser использует
локальные fixtures вместо API и блокирует внешнюю сеть/рабочие записи.
Схема БД, боты, runtime flags, live server и доставка сообщений не менялись.
Commit/staging/push/deploy не выполнялись; acceptance остаётся владельцу.
