# Задача [01-291]

## Короткое описание

Добавить короткие, различимые звуки для рабочих уведомлений панели и проверить
корректность запроса на разблокировку клиента.

## Цель

Оператор слышит тип события без тяжёлых медиафайлов и без повторных звуков при
одном событии. Запрос на разблокировку не может сам заблокировать клиента, а
одна заявка не получает два решения при конкурентной обработке.

## Контекст

- Глобальный SSE-канал панели уже транслирует `notifications_changed`,
  `dialogs_changed` и `sidebar_unblock_changed`.
- Причины `incoming_client_message` и `dialog_feedback_created` позволяют
  определить сообщения и оценки без эвристик по тексту.
- Заявка `/unblock` приходит от дочернего бота через подписанный internal API.
  Проверка привязки к каналу уже есть, но создание заявки не проверяло, что
  клиент действительно заблокирован.

## Что сделать

- Добавить глобальный Web Audio runtime для системных, incident, диалоговых,
  оценочных и unblock-событий.
- Не проигрывать исторические уведомления при открытии страницы и не дублировать
  общий сигнал для более конкретного SSE-события.
- Защитить panel-side и legacy-path создания unblock-заявки от блокировки
  незаблокированного клиента; блокировать строку blacklist на время создания.
- Сериализовать решение заявки оператором транзакцией с блокировкой записи.

## Критерии готовности

- Все пять типов события используют разные короткие сигналы без внешних аудио-
  ассетов; звук появляется только после первого действия пользователя в панели.
- `/unblock` у незаблокированного клиента не меняет blacklist и не создаёт
  заявку.
- Целевые unit-тесты и синтаксическая проверка JavaScript проходят.
