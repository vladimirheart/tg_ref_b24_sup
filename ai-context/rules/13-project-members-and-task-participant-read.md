# Проекты и чтение задач участниками — 01-327

Действует поверх R302–R305 для READ задач. Участие в проекте по-прежнему не
открывает его задачи. Владение не выводится из creator/lead или отображаемых имён.

## Чтение задачи

- Ответственный, соисполнители и наблюдатели получают только READ своей задачи
  через task_people.user_id. OWNER/EDITOR/VIEWER в shared_task_members остаются
  отдельными явными назначениями. Производное участие не выдаёт WRITE/OWNER.
- Сохраняются current account, exact ID/raw username, PAGE_TASKS + shared can_read,
  ограничения enabled/blocked и existing owned-root boundary. Старому объекту без
  владельца владелец назначается администратором явно; creator не становится OWNER.
- List/count/page, «Мои задачи», прямой READ, вложения, notification recipients и
  поздняя доставка используют это же правило. «Мои» учитывает assignee/co/watcher
  по numeric user_id, включая переименованный аккаунт.
- Состав меняется доверенным WRITE задачи. В той же транзакции новые назначения
  привязываются к единственному exact account; неизменённая историческая привязка
  сохраняется, в том числе NULL после удаления. Повторное использование логина
  другим аккаунтом не восстанавливает старое участие. Физическое удаление аккаунта
  ставит FK в NULL; identity/role остаются историческими данными.
- Удаление из состава отзывает производный READ. Явный grant остаётся независимым.
  READ удерживает share lock участника до commit; roster replacement ждёт окончания
  чтения/доставки. Глобальные права и допуски автоматически не выдаются.
- V109 один раз связывает существующие assignee/co/watcher с exact, однозначными
  users.id. Не делает trim/case folding, не связывает creator, не меняет ownership.
  Если assignee отсутствует в roster, V109 сохраняет его из канонического поля
  tasks.assignee, включая историческую подпись с NULL binding. Новые system
  follow-up writers записывают assignee в roster сразу: «Мои» не теряет такие задачи.

## Панель проекта

- «Сведения» и «Участники» находятся внутри прокручиваемой modal body. На карточке
  проекта есть явная кнопка участников; после создания открывается их вкладка.
- Добавление доступно OWNER/current system admin и видно перед длинным roster.
  Кандидаты берутся только из прежнего server-scoped people API; новых grants и
  global fallback нет. Результат mutation повторно читается без автоматического retry.
- Дополнительные поля, архивирование, передача владельца и аудит свёрнуты. Действия
  состава сохраняются сразу, редактирование сведений — кнопкой «Сохранить».
- Производный taskParticipant в roster не предлагает бесполезный DELETE явного
  membership: такой READ меняется составом задачи. Явный membership можно отозвать.
- Запрет доступа закрывает карточку также во время открытия Bootstrap modal.
