# R209: Operational notification load shedding

## Статус

Действует с 25.11.2026.

## Правило

Persisted bell-уведомления предназначены только для критичных операционных состояний:

- incident с severity `critical` или выше;
- event, содержащий escalation;
- SLA-эскалация просроченной первой реакции;
- AI-эскалация диалога.

Routine-события диалога — новое обращение и входящее сообщение клиента — не создают notification rows для всех операторов. Они остаются доступными через список диалогов, историю и UI realtime events.

## Производительность

Fallback polling sidebar обязан иметь один in-flight запрос и увеличивать интервал после ошибки. Нельзя использовать независимый `setInterval` для endpoint, который может работать дольше интервала.

## Граница PostgreSQL

`APP_POSTGRES_MAX_CONNECTIONS=550` — серверный потолок контура. Он не отменяет ограничений отдельных Hikari-пулов: увеличение pool size требует отдельной оценки суммарной concurrency и памяти хоста.
