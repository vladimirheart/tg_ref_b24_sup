# Правило: ограниченная серверная выборка списка диалогов

## Статус и границы

Задача `01-282`. Относится к legacy `/dialogs` и `/api/dialogs`, не меняет GENERAL/BUSINESS routing, membership или плановые SLA-обработчики.

## Контракт

- PostgreSQL выполняет поиск, фильтрацию, сортировку и пагинацию **до** передачи строк приложению. Обычный размер страницы — 20, максимум — 100. Отсутствие параметров, старое сохранённое `all` и некорректные размеры не включают неограниченную выборку.
- Первоначальный HTML тоже содержит только ограниченную страницу. Нельзя вернуть полную выборку и скрывать лишние строки классами CSS.
- Поиск — буквальная подстрока, включая `%`, `_`, обратную косую черту; значения связаны параметрами SQL. SQL sort/view — только из allowlist.
- Номер обращения вычисляется по полному допустимому набору **до** фильтра/лимита, не начинается заново на каждой странице.
- Общее количество и страницы вычисляются в одном SQL snapshot. Удаление последней страницы приводит к последней существующей, пустой результат — к странице 1 с нулевым количеством.
- Сводные показатели независимы от текущей страницы. Вспомогательный preview «Мои диалоги» ограничен 20 строками в каждой группе, отдельно возвращает полные количества. До 100 явно закреплённых активных обращений могут дополнять preview.
- Для фильтров и смены страницы агрегаты можно не перечитывать; SSE/poll обновляет ограниченную страницу и отдельные агрегаты. Нет передачи полного архива на каждое событие.
- Отложенные обращения передаются на сервер как точные opaque ID и участвуют в фильтре **до** count/limit. Нельзя фильтровать лишь видимую страницу и выдавать её количество за общее.
- Read-only `POST /api/dialogs/query` нужен для точной передачи списков ID без URL-length/comma-splitting проблем; он не изменяет данные, требует PAGE_DIALOGS и CSRF. Существующий GET сохраняет прежнюю auth-границу, но становится ограниченным по умолчанию.
- GENERAL и все raw-ID collisions, включая mixed GENERAL/non-GENERAL, исключаются до нумерации и пагинации. Эти guards не заменяют business membership и не предоставляют новых business grants.
- Браузер отменяет/игнорирует устаревшие ответы при смене фильтров; debounce поиска не должен оставлять окно для применения старого результата. Повторные invalidation coalesce-ятся; при возвращении к вкладке выполняется свежее чтение.
- Групповые действия относятся только к явно выбранным загруженным строкам. При смене страницы/фильтра выбор очищается. Открытый диалог и прямые ссылки не требуют присутствия записи на текущей странице.

## Проверки

Реальный изолированный PostgreSQL: тысячи обращений, первая/последняя/пустая страница, буквальный поиск, фильтры/SLA/сортировка, полные счётчики, stable number, GENERAL/collisions. HTTP: нормализация и границы запросов, PAGE_DIALOGS/CSRF для нового endpoint. Браузер: переходы, быстрый поиск/ответы вне порядка, SSE/poll, выбор строк и повторная загрузка.

Полная история выбранного диалога, cursor-пагинация истории и перенос других страниц проекта не входят в `01-282`.
