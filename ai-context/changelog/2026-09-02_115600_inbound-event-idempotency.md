## Фактические изменения

- Для входящего сообщения активного обращения event ID теперь детерминированно строится из канала, обращения и provider message ID, когда такой ID доступен.
- Повторная доставка одного сообщения Telegram/MAX больше не создаёт новый event ID и должна быть отфильтрована PostgreSQL inbox.
- MAX передаёт свой `message_id` в общий inbound command вместе с текстом и attachment reference.
