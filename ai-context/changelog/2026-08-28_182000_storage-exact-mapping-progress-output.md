# 2026-08-28 — Exact-mapping audit progress output fix

## Context

Production was already synchronized to commit `a049ba62d6035bc22fcc774bc97280481089bf78` with a clean working tree. Fresh read-only inventory on that commit reproduced the expected local-storage boundary (`130` total files, `117` dialog-or-orphan files, `13` avatar files, `43` duplicate relative paths). The exact-mapping script also passed `-ValidateOnly` under real Windows PowerShell 5.1.

During the first full exact-mapping run, the console appeared to hang with no output after `=== RUN EXACT MAPPING AUDIT ===`. Live diagnosis showed that the child `storage-cutover-gate.ps1` process was active and was executing the expected read-only `docker compose run --rm ... minio-init ... storage-cutover-object-stat.sh` object checks. The main production services stayed running and the critical application/infrastructure services remained healthy.

The storage cutover gate later finished. At the end of diagnosis there were no related storage-audit PowerShell processes and no fresh exact-mapping evidence files in `C:\Users\SinicinVV\git_h\iguana-legacy-storage-inventory\20260828-174458`:

- no `storage-local-exact-mapping-audit.json`;
- no `storage-local-quarantine-candidate-manifest.json`;
- no `storage-local-orphans.csv`.

Therefore the interrupted/diagnostic run produced no candidate manifest and authorized no quarantine.

Immediately before this repository change, GitHub `main` was rechecked and still pointed to `a049ba62d6035bc22fcc774bc97280481089bf78`.

## Root cause

`scripts/docker-production-storage-local-exact-mapping-audit.ps1` invoked both child storage gates through the generic `Invoke-Native` helper. That helper captures the entire native-process output into an array and only returns it after process exit. The storage cutover gate may perform many sequential canonical-object checks via one-shot `minio-init` containers, so the exact-mapping console could remain completely silent for a long period even though the read-only gate was still working.

## Changes

### `scripts/docker-production-storage-local-exact-mapping-audit.ps1`

- Added `Invoke-PowerShellScriptStreaming` for child PowerShell gates.
- Storage cutover and client-avatar gate output now flows directly to the operator console instead of being fully buffered.
- Added explicit `[INFO]` stage markers for:
  - `storage-cutover-gate`;
  - `client-avatar-cutover-audit`;
  - runtime storage contract discovery;
  - attachment metadata loading;
  - local SHA-256 hashing;
  - exact local/metadata mapping.

- Candidate selection, exact case-sensitive mapping, SHA-256 validation, known-unrecoverable handling, orphan exclusion and manifest authorization defaults are unchanged.
- No write path to legacy source files, PostgreSQL rows or MinIO was added.
