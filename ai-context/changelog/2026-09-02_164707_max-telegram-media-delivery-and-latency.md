# MAX/Telegram media delivery and latency

## Пользовательский запрос

`так исправь чтобы всё работало`

## Фактические изменения

- MAX runtime переведён на актуальный `platform-api2.max.ru`; в Docker-образ добавлен проверенный Russian Trusted Root CA для Java TLS.
- Входящие MAX-вложения скачиваются только с разрешённых HTTPS CDN-хостов, сохраняются в MinIO/S3 и передаются панели как стабильный storage key с исходным именем.
- Исходящие MAX-вложения используют безопасно проверенный upload URL; ошибка одного API-маршрута больше не прерывает резервный маршрут отправки.
- Загрузка вложений в S3 переведена с полного чтения в память на временный файл и потоковую передачу, чтобы крупные медиа не исчерпывали heap.
- S3-вложения в bot-core больше не помечаются как `missing` только из-за отсутствия локального файла.
- Интервалы integration outbox и UI event outbox уменьшены до 250 мс для сокращения внутренней задержки доставки.
- AI-сообщения в истории отображаются как `AI Ops (система)`, а не как оператор `admin`.
- Старое повышенное Windows-дерево панели остановлено; в production-контуре оставлен один bot-runner с отдельным токеном для каждого Telegram-канала.

## Проверки

- Пройдены compile и целевые тесты Spring Panel, MAX runtime и bot-core attachment metadata.
- Docker-образ успешно собран; CA присутствует в Java truststore panel-web и bot-runner.
- Оба Telegram runtime стали владельцами long polling без `409 Conflict`; MAX long polling запущен без PKIX/SSL ошибок.
