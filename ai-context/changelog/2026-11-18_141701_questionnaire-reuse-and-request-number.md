## Изменение

- В Telegram-потоке предложение повторно использовать значения предыдущего обращения больше не выключается для вопросника с привязкой бизнеса через поле. В предложение попадают только непустые значения бизнеса, типа локации, города и локации; описание проблемы никогда не переносится.
- Расчёт клиентского номера обращения теперь строит границы дня по `messages.created_at`. Он больше не сравнивает это значение с устаревшим текстовым `messages.created_date`, который в рабочей БД содержит часовой пояс и делал внутренний запрос номера невалидным.

## Проверка

- Добавлены unit-тесты для набора повторно используемых значений и для расчёта номера по времени создания.
- В production пересобран общий образ и перезапущены `panel-web` и `bot-runner`; оба контейнера прошли healthcheck. Миграции и переменные окружения не менялись.
- Защищённый runtime API на существующем обращении вернул номер `20261118-003`; endpoint предыдущего обращения вернул бизнес и данные локации.
