## Что фактически сделано

- В качестве технического S2A решения выбран opaque 32-hex
  `ticket_public_id`; legacy API не переключаются и legacy records не получают
  ID автоматически.
- `ticket_id` не объявляется глобальным ключом: resolver не поддерживает bare
  ID и допускает internal compatibility только по `(user_id, ticket_id)`.
- Бизнес-принадлежность, legacy aliases, UNRESOLVED assignment, strict scope и
  rollout остаются вне S2A и требуют последующих подтверждённых этапов.
- Первая попытка targeted Maven-проверки завершилась RED на компиляции теста:
  для `OptionalAssert` был указан несуществующий `containsExactly`. Assertion
  заменён на `hasValue`; повторная проверка прошла GREEN.
- Итоговая targeted команда
  `spring-panel\\mvnw.cmd -q "-Dtest=TicketPublicIdTest,TicketLocatorServicePostgresIntegrationTest,TicketLocatorFlywayMigrationTest" test`
  прошла GREEN: `3/3`; последний тест валидировал и применил весь Flyway chain
  V1→V52 в чистой PostgreSQL Testcontainers-схеме.
- После сужения проверки trigger до текущей schema обычный Maven-run исполнил
  stale bytecode и сообщил ложный unresolved compilation problem. Повтор через
  `mvnw.cmd clean ... test` выполнил чистую компиляцию и тот же набор `3/3`
  прошёл GREEN.
