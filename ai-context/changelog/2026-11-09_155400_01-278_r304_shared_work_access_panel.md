## Пользовательский результат

Системный администратор на страницах «Задачи»/«Проекты» открывает «Доступ к
задачам и проектам», выдаёт чтение и независимые права создания. Значения после
сохранения перечитываются с сервера. Снятие чтения снимает create flags; shared
грант не выдаёт участие в чужих объектах. ROLE_ADMIN получает навигацию также
без PAGE_TASKS; полный доступ R303 сохранён.

Внутри карточек задач/проектов есть текущий состав. OWNER/системный администратор
находит пользователя с текущим допуском, добавляет/меняет VIEWER/EDITOR,
отзывает участие или подтверждает передачу владельца. После записи состав и
capabilities перечитываются; прежний OWNER становится EDITOR и теряет управление
составом. Администратор может назначить владельца unowned объекта.

Новые GET /api/shared-work/context, /{kind}/{id}/access и /{kind}/{id}/people?q=
возвращают текущие права/состав/candidates с no-store. Поиск кандидатов доступен
только OWNER или текущему системному администратору; current enabled/blocked,
exact identity и module grants проверяются ядром. До100 подходящих строк каталога
за запрос, поиск уточняется по имени. Имена не определяют identity: numeric ID
передаётся строкой, в том числе BIGINT больше JavaScript safe integer.

Общий UI runtime использует textContent, CSRF и same-origin/no-store requests.
Generation guards исключают late response другой карточки/поиска. Повторный
click во время записи блокируется; mutation с неизвестным результатом не
повторяется автоматически. При отказе состав очищается, запись блокируется,
карточка закрывается и основной список обновляется. Create/write buttons
включаются по текущим server capabilities. Передача требует подтверждения.
