# 01-271 — Backup & recovery UI polish after phase B local acceptance

## Время

2026-09-18 20:50 +03:00

## Контекст

Phase B local read-only probe принят end-to-end в production: host runner выполнил `path -> read -> free_space`, panel-web увидел тот же status/signature, local destination остался `NOT_DR`, write/delete не выполнялся. Ручная UI-приёмка подтвердила функциональность, но пользователь отметил визуальный шум и попросил убрать текстовые `Подробнее`, перенести пояснения в `i` и скомпоновать workspace.

## Что меняется

- backup modal исключается из автоматического `Подробнее` для собственных helper-текстов через `data-no-disclosure`;
- длинные пояснения destination/DR/probe/manual execution переносятся в локальные info-popover по кнопке `i`;
- верхний informational alert заменяется компактной context line;
- local `NOT_DR` warning становится компактным state strip вместо full-width alert;
- probe status собирается в одну summary-строку: status + steps + human-readable free space + finished time;
- raw technical probe metadata остаётся доступна внутри `i`;
- manual runner card сокращается, техническое объяснение queue/runner переносится в `i`;
- success/info feedback автоматически сворачивается через короткий timeout, warning/error остаются до следующего действия;
- backend API, backup policy, DR gate, probe request/status и host runner semantics не меняются.

## Safety

Validate-only оператор патчит только sandbox clone, выполняет syntax/source-contract/Sass compile checks и не запускает probe, SMB auth, backup/restore, deploy/restart или credential mutation.
