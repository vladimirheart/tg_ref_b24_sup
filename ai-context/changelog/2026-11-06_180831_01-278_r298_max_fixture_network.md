## Изменение

В R297 MAX42 остановились до сценариев: Docker29 не создал host port mapping
PostgreSQL в internal-only network. Подготовлено исправление test-only fixture:

- PostgreSQL/Rabbit остаются только в собственной nonce-labelled internal
  service network, без exposed/mapped host ports. Ожидание готовности — по
  startup logs вместо недоступного host mapping.
- Socat relay alpine/socat:1.7.4.3-r0 соединяет свою ingress network и internal
  services. Только два фиксированных TCP target, случайные нестандартные host
  ports на127.0.0.1. User65534, read-only root, capabilities dropped,
  ip_forward=0, memory/CPU limits. Рабочие/чужие networks не подключаются.
- До JDBC/AMQP проверяется actual docker-java inspect: ownership/roles/driver/
  internal, точное membership, отсутствие service bindings, два точных relay
  loopback mappings. Отсутствующий mapping остаётся ошибкой, внешний endpoint
  fallback отсутствует. Cleanup работает только по exact owner+nonce с
  image/role/isolation guards. Исходная ошибка старта сохраняется при cleanup
  failure через suppressed exception.
- Runner передаёт api.version=1.44 тестовой JVM, раздельно выполняет MAX42 и
  principal15. При media startup error principal suite всё равно выполняется;
  первый failure/partial counts и failed/startup XML сохраняются. Старое имя
  r292-proof.json оставлено, Phase=R298. Успех требует57 IT без skips и
  ExistingContainersUnchanged=true.

Причина и схема сверены с первичными источниками:
[Moby internal port publication](https://github.com/moby/moby/discussions/53256),
[Docker localhost bindings](https://docs.docker.com/engine/network/port-publishing/),
[Testcontainers1.19.7 SocatContainer](https://github.com/testcontainers/testcontainers-java/blob/1.19.7/core/src/main/java/org/testcontainers/containers/SocatContainer.java).
Это подготовленное исправление с локальным proof; фактическая совместимость
новой topology на Docker29 требует полного запуска, который здесь недоступен.
