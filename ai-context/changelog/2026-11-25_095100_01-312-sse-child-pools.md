## Изменения

- Child DataSourceConfig читает и проверяет minimumIdle/maximumPoolSize/idleTimeout;
  supervisor явно передаёт отдельные настройки child через runtime contract.
- Compose, `.env.example` и локальный ignored `.env` задают child min=5/max=20,
  idleTimeout=120000 мс. Pool panel service JVM остаётся 6.
- V103 повышает CONNECTION LIMIT с 16 до 20 только у исходных active managed
  roles с совпадающим journal OID и без повышенных прав. Future provisioning
  function и ручной provisioning SQL также создают quota 20; старые миграции
  не изменены, пароли, ACL и идентичности сохраняются.
- В Nginx direct/HTTP/TLS configs выделены SSE locations: buffering/cache off,
  read timeout 180 с. Обычные HTTP endpoints сохраняют timeout 60 с.
- Основной SSE controller возвращает no-store и X-Accel-Buffering=no.
- UI и GENERAL heartbeat используют отдельный scheduler из двух потоков и
  независимые scheduled methods с прежним интервалом 25 с.
- Исправлен обнаруженный при restart конфликт default PUBLIC grants
  pg_stat_statements с child startup isolation check: diagnostic SQL отзывает
  PUBLIC доступ к views/functions. Владелец БД продолжает читать статистику;
  security guard не менялся.
- Добавлены правила/runbook и регрессионные проверки. SSE fixture дополнен
  реальными session-version/shared-access beans и соответствующей колонкой.
